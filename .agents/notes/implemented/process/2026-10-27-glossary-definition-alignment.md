# Agent Note: 术语定义与实现核对

Status: implemented

## Problem

[仓库词汇表与术语管辖权](2026-10-24-domain-glossary-and-ownership.md)把文件身份、组身份、结果代际、修订号和规则版本统称为递增计数。这会使读者误用数值大小判断代际先后，或把输入修订当作已消费的修订。[术语表](../../../../GLOSSARY.md)还把 file_generation 写成不带重写代次的文件身份，无法解释同一文件原地重写后为何产生新的证据身份。

基础名词只覆盖 magpie 请求和转报的 session，漏掉已经独立建行的 OTLP 输入。trace 又被定义为页面展示单位，没有区分单笔请求详情、会话阅读与 OTLP trace。同一调用由 magpie 和 OTLP 分别记录时，旧定义容易让人把记录数当作去重后的调用数。

词条同时保存位图、主键、状态枚举和操作步骤，违背字段事实归架构文档的既有分工。核对这两个文档时，架构文档还出现了派生代标识由组键拼出、derive_version 不再累加两处与代码不符的说明。

## Decision

保留单一根词汇表、按混淆场景准入、字段事实归架构文档以及不新增术语门禁的决定。本次修正已有词条的事实与适用范围：文件读取代际区别于底层文件身份，身份标识区别于修订和计数，当前输入区别于结果已消费的输入，基础名词覆盖受支持的来源与阅读方式。

词条保留定义、概念边界与代码名称对应关系，位图、主键、完整值域及执行步骤改为链接现行设计。架构文档同步修正已核对的事实，schema、运行行为与数据均不变化。

### 核对依据

| 具体情形 | 实现依据 | 文档修正 |
| --- | --- | --- |
| 同一文件截断或原地重写后从偏移零读取 | [readBatch](../../../../src/sources/files.ts) 将底层文件身份与 rewriteEpoch 共同构成 generation | 区分文件身份、读取代际与重写计数。 |
| 派生组删除后重建，或同一组重新开代 | [markGroupDirtyTx](../../../../src/derive/state.ts) 与 [beginGeneration](../../../../src/derive/slice/generation.ts) 各自生成 UUID | group_epoch 与 derive_generation 不承诺大小顺序；结果代的计算依据独立保存。 |
| 同步派生更新请求，包括保留旧摘要 | [同步派生](../../../../src/derive/sync.ts) 递增 derive_version | 计数限定到同步更新路径，不能推断算法或结果新旧。 |
| harness span 直接进入采集器 | [OTLP 摄入](../../../../src/sources/otlp/ingest.ts) 独立建请求，[属性映射](../../../../src/sources/otlp/mapping.ts) 提取 session | 请求与 session 定义覆盖 OTLP，并区分本项目 trace 与 OTLP trace。 |

本记录补充前述两篇 process note 的事实核对依据，不取代其文档管辖权、准入和命名决定；两篇记录继续活跃并链接到本文。

## Alternatives considered

**只改被审阅 note 的标题与措辞。** 修改最少，但权威词条仍会把身份当计数，架构文档中的反向说明也会保留。此次把已核对的事实同步到各自所属文档。

**让代码按文档改成递增代际或组合键。** 没有运行需求支持这个变化，还会涉及持久化身份、重放与迁移。保留实现，修正文档。

**为术语一致性增加自动门禁。** 格式检查不能证明两段自然语言含义一致。本次采用具体场景与源码对照，不改变既有门禁决定。

## Consequences

读者可以从词汇表区分身份、修订和算法版本，再按链接查询实现规格；同一字段机制不必在词条里维护第二份。代价是查完整枚举或存储形状需要跳转。

核对范围限于上述词条及直接关联的设计段落，不代表架构文档或源码注释已完成全量审计。此次交付为文档修正，源码核对不能替代运行验收，也不构成对真实数据重新验证的声明。
