# Agent Note: 容量基线怎么测、数字能信到什么程度

Status: implemented

## Problem

容量结论要能被人重跑并核对，也要能说明哪些数字只是观察、哪些可以当作事实。一台开发机上的单进程采集器同时受机器负载、采集器自身的同步事务与负载端的排队策略影响，三者混在一起时，"慢了"没有可判定的含义。

## Decision

测量方法是固定的，写在 [plan](../../../../docs/superpowers/plans/2026-10-22-atc-capacity-convergence.md) 的观测口径一节，产出与门槛结论在 [baseline record](../../../../docs/superpowers/capacity/2026-10-22-atc-capacity-baseline.md)。要点：

- **只打合成数据。** 每个场景新建 `atc-capacity-` 临时根与回环假上游，采集器在子进程里启动，负载端与它不共享事件循环；报告只写指标与固定原因码。临时根在场景结束时删除，报告留在仓外。
- **速率按绝对刻度发。** 计划刻度数是 `durationMs × rps`，落后不补也不顺延；在途请求有上限，到点发不出去就记 `ticks_dropped` 并让报告失败。"标记速率没发出去"与被测量对象"被标记为失败"是同一件事的两个面。
- **停止输入后要等静默。** 三个计数（未发布组、待对账 hook、来源缺口）连续静默 5 秒才算收敛，终值快照里的脏组另行记缺口。
- **分位数按最近秩。** 空样本返回 null，不把 0 当缺失；`backlog_max_age_ms` 的 null 表示整轮没见过脏组，按 0 读。
- **固定种子与固定会话数。** 20 个会话、`seed=1`、正文混合为 350 KiB 与 2 MiB 交替，正文长度按序列化后的实际字节记录。
- **门槛与预算同源。** 预算从同一次 `all` 汇总冻结并记下报告 sha256；门槛只读预算与报告，不读 `notes`。

机器：macOS 27.0.1、Apple M5 Pro、Bun 1.4.0。被测提交 `4da9307`。

实测数字（`all --full`，八段共 1,420,061 ms，报告 sha256 `fc2eb638…`）：`baseline-1rps` 600/600 刻度全部发出、hook p95 28.9 ms、事件循环 p99 183.45 ms；`baseline-5rps` 3,000 个刻度丢弃 969 个（实际投递 3.39 rps）、hook p95 3791.55 ms、写事务单笔 5294 ms、derive 作业合计约 286 s；`long-10000` 写事务单笔 1959.35 ms、增量与全量结果指纹一致；`burst` 观测到 10 并发与 `busy` 背压；`retention` 预置 raw 行清零。

## Alternatives considered

**只在一台"干净"机器上跑，并把被别的负载打扰的那一轮丢掉重跑。** 重跑一次要 24 分钟，而它换来的确定性有限：同一 1 rps 场景两轮的 page 读 p95 是 33 ms 与 153 ms，方差远大于门槛的余量。与其追求单轮干净，不如把方差写进记录，并让预算不依赖单轮包络。

**把测量口径写进常备文档。** 口径与本次数字会一起腐烂；数字属于一次实验，记在基线记录里，方法留在本 note。

**让报告带上"这次算不算数"的自评。** 自评会变成第二个结论出口；报告只写观测值，判定留给门槛与人工复核。

## Consequences

- 机器负载共用的那几秒会落在分位数上，读数要按"同轮里其它指标是否一致"来判可信度，不能单看一个 p95。
- 单轮包络不足以支撑紧的门槛，因此预算里有时延与写事务目标值的指标直接用目标值，只有单调量（rss、存储字节、拒绝计数）用包络。
- 长组不发 HTTP，`client` 计数为 0，时延指标为 null，不进长组的预算。
- 这一轮报告的 `route.unchanged` 恒为 0，当时的路由入口每轮都解压；三态计数在路由入口改成先哈希后解压（`4e36138`）之后才可观测，前后对照在 [baseline record](../../../../docs/superpowers/capacity/2026-10-22-atc-capacity-baseline.md) 的「路由解码对照」一节。这份记录里的路由数字仍是改造前那一轮的读数。

## Testing

不需要测试：本 note 记录的是测量方法与置信口径，方法与代码的对应关系由 `tests/capacity.test.ts` 与 `tests/capacity-gate.test.ts` 守着。重新测量即重新跑一遍 [baseline record](../../../../docs/superpowers/capacity/2026-10-22-atc-capacity-baseline.md) 里的三条命令。
