# Agent Note: 巡查自己留历史并算周环比

Status: implemented

## Problem

`bun run patrol weekly` 每次都只打印当期读数，日增、周增与 `>200` 会话数的变化要靠人把输出贴进周报再手算。脚本此前刻意不写文件，因为写进数据目录会与采集器争同一块磁盘、写进库会破坏只读边界。缺少历史还导致 `growth` 只能给绝对值，阈值里的日增/周增两档无从判定。

## Decision

`weekly` 把一期快照写进维护者的状态目录：默认 `<data>/patrol/history.json`（与 `scripts/monitor.ts` 的 `monitor/` 同级），用 `ATC_PATROL_STATE_DIR` 或 `--state-dir` 覆盖，不跟随 `--data-dir`。写入前读旧历史，按 ISO 周判期：同周重跑覆盖本期，只与严格更早的最近一期比较，输出 `growth_delta`（增量、占上期百分比、日均、是否越过日增/周增阈值）与 `conversation_delta`（`>200` 会话数与最大请求的变化）。只保留最近 12 期，写入时按周号裁剪；先写临时文件再改名，避免半写。

历史缺失、JSON 解析失败或形状不符时不算失败：退化为「无上期可比」，打印 `[info] history: 历史不可读 …`，退出码仍是 0/1/2；下次写入用本期重建。`smoke` 不写历史。`weekly --if-due` 把到期判断也收进脚本：本期 ISO 周已有快照时打印 `未到期（<本期> 本期已采，距上期 N 天），跳过` 并退出 0，不采集、不写快照；历史缺失或损坏视为到期。程序正文与阈值仍在 [docs/patrol.md](../../../../docs/patrol.md) 与 [scripts/patrol.ts](../../../../scripts/patrol.ts)。

## Alternatives considered

- **写进数据目录（`<data>/history.json`）**：与 `trace.db`、`-wal` 共用同一块盘，巡查就会往生产数据目录落文件，违背「巡查不写数据目录」的边界。
- **写进库**：破坏只读连接的前提，也让巡查承担 schema 变更。
- **写进仓库工作区**：快照是维护者本地运行产物，进仓库会污染 diff，也会被误当成产品数据。
- **每次运行都留一条**：一天内多次跑会堆出噪声，周环比的分母失去意义；按 ISO 周覆盖本期更稳定。
- **让调用方读 `takenAt` 自己判断到期**：定时器或 agent 要各自解析状态目录与 JSON，路径、时区与期号口径会在多处复制；`--if-due` 把这条规则放进脚本，退出码即可表达「跳过」。
- **`--if-due` 按「距上期不足 7 天」判断**：首版这么实现，但同周不带闸门重跑会覆盖本期并把 `takenAt` 刷到当天，下一期头一天算出来不足 7 天，整期被跳过。期号本来就是快照的去重键，改判「本期是否已有快照」才与「一周一期」对齐。
- **无限保留历史**：状态目录会持续增长；12 期足够看到季度趋势，超出后裁剪。
- **历史损坏时退出 2**：一次坏文件就让每周巡查不可用，且巡查的报告价值不依赖上一期。

## Consequences

- 状态目录成为巡查唯一写点，只写 JSON 快照；数据库仍然只读，删掉状态目录只丢周环比。
- 期号按本地时区的 ISO 周计算，跨年周（如 `2027-W01`）按 ISO 规则落在周四所属年份；同一周内重跑会覆盖 `takenAt`，日均按实际间隔算。
- 第一次运行与历史损坏时输出「无上期可比」，这是预期状态而不是失败。
- `--if-due` 未到期时退出 0 且不采集，调度方只需看这一条输出；主动想复测时不要带这个开关。
- 判据用期号而不是时间窗：同一周内任意时刻重跑都算「本期已采」，下一周第一次调用才放行。
- 副本实例要分开历史时需显式 `--state-dir`；默认状态目录与副本数据目录无关。
