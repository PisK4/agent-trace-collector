# Agent Note: 可读性常备规则——同步另起句与压缩词首现

Status: implemented

## Problem

2026-10-26 对活跃 note 树做了只读可读性评估（约 90 篇、5400 余句）：中位句长 39 字，11% 的句子超过 100 字，74 句超过 200 字，最长 473 字，密度最高的是 Decision 与 Testing 章节。词汇层有两类解码障碍：「结算」「读数」是活在代码与架构文档里的正式词（request-purpose 的 CAS 结算、architecture-design 的轮次结算、web 注释里的读数页），却不在[词汇表](../../../../GLOSSARY.md)里，按词汇表解码 note 的读者解不开它们；「口径」（活跃树 108 次）、「在场」「空壳」「身份行」这类写作压缩词则任何地方都没有定义。

长句有一个结构性成因，不处理它，任何文本修整都会被侵蚀回去：README 要求 implemented note 与实际交付保持同步，而同步的实际操作是往既有句子的中段追加插入语。工作区对[用量折叠行](../simplification/2026-10-24-usage-ledger-fold.md)的未提交修改即是实例——为同步 treemap 交付，向一句原本约 300 字的句子中段又插进约 60 字的破折号从句。句子单调变长是维护方式的必然结果，不是某一次写坏。

## Decision

治本进[文档标准](../../../../docs/AGENTS.md)写作规则节，新增两条：其一**同步另起句**——文档吸收新事实时新增内容另起一句或一个列表项，不往既有句子中段插从句，旧句确需变动就整句重写，一句只装一个事实，三项以上并列细节进列表；其二**压缩词首现带所指**——不在词汇表的自造压缩词与非代码标识符的英文行话，首次出现写明具体所指。

术语层不新开文件，用既有词汇表：结算、读数按准入判据补进 [GLOSSARY.md](../../../../GLOSSARY.md) 新节「判定与读出」。准入的触发事件是本次评估记录到的解码失败——结算与派生、读数与读取/读模型的词形冲突，和词汇表已收录的 source 一词三义同类。页面读出词汇由此按同一准入进词汇表，管辖判据不变。「口径」不登记：它是普通中文词被宽用，不是概念边界混淆源，归首现带所指规则约束。

## Alternatives considered

**把文档用语全量登记进 GLOSSARY.md（增设「文档用语」节）。** 违反词汇表准入（场景压测中逼出边界混淆的词才收，不追求全量），且登记即合法化：有一张随时可登记的表，新造压缩词会更快增长而不是减少。只收逼出混淆的两条。

**新开规则层文件（如 docs/writing-rules.md，或把规则写进 note README）。** 文风与写作规则的家已经是文档标准，这是[根 AGENTS.md 收敛](2026-10-25-agents-md-single-home.md)确立的分层；规则另立文件就是给同一事实开第二个家。落选。

**句子长度数字门槛（如单句不超过 100 字）。** 机械门槛催生凑长度和无意义切分；规则按事实单元（一句一个事实）执行，不按字数。落选。

**一次性重写活跃树全部长句。** 不先改同步习惯，改完的句子会被下一次同步侵蚀回现状；长句拆分按篇分批另做，优先根 AGENTS.md 引用的常备篇与 architecture 类。推迟出本变更，不在此次范围。

**词汇表或写作规则接门禁。** 词汇表不接门禁是[既有决策](2026-10-24-domain-glossary-and-ownership.md)，写作规则同理靠评审捕捉；本次不改。

## Consequences

既有长句与既有英文行话不追溯，两条规则约束今后的写作与同步维护。工作区那条往用量折叠行句中插从句的未提交同步，合入时应按新规则改为另起句。词汇表新增「判定与读出」节，是管辖范围对页面读出词汇的一次小扩张，准入判据不变。后续按批拆长句时保留代码标识符、模块路径与版本常量锚点，只改自然语言部分。

## Testing

`bun run verify:notes` 通过：新 note 格式、归档封印、本次改动带 note。规则与词条无运行时行为，无代码回归面。
