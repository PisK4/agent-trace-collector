# Agent Note: README 对外介绍、验收记录独立成篇与 trace 格式规范

Status: implemented

## Problem

README 面向的是第一次打开仓库的人，但它写的是变更史：11 个小节里 156 行是实施记录与合成验收表，标题带 A5 / B5 / B6 / C1 / C2 / C3 这类内部批次代号。首屏第一句是「本机 magpie 请求记录器」，外部读者读完只知道它依赖一个自己没装的软件，不知道这东西对他有什么用。唯一不依赖 magpie 的入口 `bun prototypes/synthetic-server.ts` 完全没被提到，而这恰恰是任何人能立刻看到界面的路径。

第二个问题是没有一处描述「ATC 把一次请求结构化成了什么」。schema 的形状散在[架构设计](../../../../docs/architecture-design.md)的 DDL、[CONTEXT.md](../../../../CONTEXT.md) 的术语和代码里的读模型类型之间，外部读者无法据此理解数据。产品对外说自己是 trace 记录器，但没有任何一份文档回答 trace 长什么样。

第三个问题是验收记录没有自己的家。它挤在 README 里，与[文档标准](../../../../docs/AGENTS.md)「README 承载当前状态与运行命令」的分层互相拉扯，导致那条分层表要么被违反，要么被反复改写。

## Decision

README 重写为对外介绍，只留七节：它是什么、能看到什么、试一下、接真实流量、数据从哪来、trace 模型、边界与非目标、命令与文档入口。首段说清记录单位是请求、阅读单位是会话、三个用途是什么；试跑顺序改成先给合成 demo 再给真实接入，因为外部读者手上通常没有 magpie。

验收记录整体搬到 [docs/acceptance.md](../../../../docs/acceptance.md)，逐字保留原有结论，只做两件事：小节标题去掉批次代号改为内容名，跨文档相对链接跟着新位置调整。合成验收与真实流量验收在同一文件里分开写，每条带日期与前提。

新增 [docs/trace-format.md](../../../../docs/trace-format.md)，标题写明是内部读模型 v0。它描述现状：主实体与身份、三路证据各自给什么、正文按块去重与两个哈希的分工、派生结论清单、`derived_state` 的四态置信度、阅读版本与版本字段。文件开头三条限定写明它不是交换格式、只有一个数据源、schema 不原地升级，避免被读成对外承诺。

文档分层随之调整：[docs/AGENTS.md](../../../../docs/AGENTS.md) 的分层表给 README 换成对外介绍的职责，新增 acceptance.md 与 trace-format.md 两行，并把「README 里的验收记录属于待迁移的已知例外」改成「验收记录按轮次保存当时结果，是有意例外」。根 [AGENTS.md](../../../../AGENTS.md) 的「一个事实一个家」那条补上对外介绍与验收结果两个归属。索引登记在 [docs/README.md](../../../../docs/README.md)。

新增 MIT [LICENSE](../../../../LICENSE)：仓库此前没有任何许可证文件，别人在法律上没有复用权限，对外介绍的开放叙事会落空。

第二轮补上生态定位。外部读者打开仓库最常问的是「这不就是 Langfuse 吗」，而首屏只说依赖 magpie，没回答这个疑问。README 因此新增两处：开头点明真实数据依赖 magpie，新增「与观测平台的分工」一节。分工只写两件具体的事——逐笔新增消息的序列比对，以及网关在发送点能看到组装后的上下文——不写竞品能力矩阵：那种表会腐烂，且多为厂商自述。同节写明评测、提示词管理、协作权限、聚合告警这几块交给平台，ATC 不做。「不做服务端全文检索」补进边界清单，因为页面上的搜索只按标题与客户端标签过滤已加载列表，此前没有一处写清。magpie 的 OTLP 导出为何不能当第四路证据，落在 README 的数据来源节与 [trace-format.md](../../../../docs/trace-format.md) 的证据一节：它的属性只覆盖 `gen_ai.*`、`magpie.*`、`langfuse.*` 三类，没有 `response_id`、`conv`、`subagent`、`archive`，正文以两段文本发出，连接点缺失就合并不起来。

## Alternatives considered

**只重写 README，不新增 trace-format.md。** 落选。README 可以说清「结构化成了什么」的产品价值，但字段形状、两个哈希的分工、`derived_state` 的四态这些必须落在规范位置；塞进 README 会让它重新变成规格文档，正是这次要修的问题。

**trace-format.md 写成对外稳定协议 v1。** 落选。当前没有导出、没有版本化 schema、没有跨工具互操作，写成 v1 就是把不存在的东西承诺出去。文档标题与开头三条限定都指向内部读模型 v0。

**验收记录直接删除，历史留 git。** 落选。合成验收的具体结论（工具详情五态、结构分页、读取成本、容量实测读数）是排障时的第一手材料，只有 commit 历史等于失去可检索入口。

**验收记录留在 README 尾部，只去掉批次代号。** 落选。README 的长度会继续把它压成变更记录，外部读者的第一屏之后仍是内部内容；分层表的矛盾也原样保留。

**给 README 加截图。** 未做。本机 CDP 截图接口此前多次超时（验收记录里两轮都记了这件事），合成 demo 的界面在没有截图的情况下也能跑起来看；等截图路径可用再补。

**许可证用 Apache-2.0。** 落选。工具类项目要的是最低摩擦的复用，MIT 更短且足够；专利授权条款对这类本机工具没有实际增益。

**在 README 里放竞品能力对照表。** 落选。调研里那张 18 行矩阵覆盖 5 个产品，其中平台侧的评测、提示词、协作能力全部来自厂商自述，部分许可与版本信息标注「待核」。写进产品首页等于替别人的产品背书，且能力会随对方发版腐烂；本仓「报告忠实」要求不把未核实的外部声明当事实陈列。分工用两段散文说清边界，比矩阵更难腐烂。

**把整份生态调研搬进 docs/。** 落选。调研的结论已经在 README 与 trace-format.md 里落成三条可执行判断；余下部分是五类形态分类与逐项对照，属于一次性的决策输入，不是长期维护的文档。留在调研产物里更合适。

**给 README 加「Langfuse 接入 9 个 coding agent」这类对比事实。** 落选。这类数字随对方发版变化，且与本项目的能力边界无关；README 只需要回答「为什么不重复」，不需要复述对方的产品现状。

**把「必须先有 magpie」只留在安装小节。** 落选。它是受众边界而不是安装细节：没有 magpie 的人一条数据都收不到，这决定了这个项目值不值得别人装。首屏必须能读到。

## Consequences

README 从 219 行降到约 110 行，第一屏回答「这是什么、对我有什么用、怎么立刻看到」。代价是验收结论多了一跳链接，但排障时本来就会打开 docs 目录。

trace-format.md 描述的字段与 schema v6 绑定，schema 升级时要同步更新。这份同步负担是显式的：文件开头就写明 schema 不原地升级，读的人知道版本会变。

LICENSE 一旦发布就不可撤回：已发布的 MIT 授权永久有效。选它之前应当确认没有计划在将来改为限制性许可。

`docs/AGENTS.md` 现在有 acceptance.md 这个「写当时的结论」的例外，与「文档写现状」并列。例外被限定在一个文件里，新增记录按轮次追加、不改写旧结论，避免例外扩散成惯例。

README 现在有两处对外部事实的引用，都带出处：Langfuse 集成文档里的 hook 限制，与 magpie 源码里的 OTLP 属性清单。前者是对手方文档，随对方改版可能失效；后者锚在 `开源源码@magpie-2374ffe`，magpie 升级后要复核。两处都是「为什么不重复」这一段的证据，失效时改这一段即可，不影响产品叙述的其他部分。

README 从 110 行回到 136 行。新增内容全部回答同一个问题——「凭什么装这个」，没有回填任何调研的对照细节。
