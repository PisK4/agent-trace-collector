# Agent Note: 阅读准备的版本守卫

Status: implemented

## Problem

窗口准备会异步读取请求、显示依赖与增量。请求版本在等待依赖期间改变时，旧依赖不能证明新版本的显示信息；失败组开始重试时，旧的提交资格也不能继续生效。自动重读可能在切换会话后结束，迟到通知会落到新会话。保留投影里的来源坐标也可能属于旧版本。

## Decision

[窗口准备模块](../../../../web/trace-preparation.js)集中持有提交资格、同组任务与代次。重试先撤销旧资格；准备期间请求 token 变化时按新版本重新收敛依赖；换代、离窗或作废的任务不提交旧结论。自动重读的通知以 store 当前记录身份为准。显示层的旧投影只保留给阅读位置和外观，不能从旧步骤推断当前来源或配对。当前请求仍显示旧投影时，读数、正文和工具页等待当前版本备齐，失败时提供重读入口；路由页仍可使用。工具调用方在窗口内且仍显示旧投影时，工具页同样等待调用方备齐，重读入口指向需恢复的请求；判断调用消失前也等待来源和调用方换新。这样旧的结构选择不会指向新消息，旧步骤也不会被新回复顶替。

窗口准备原有的批次、依赖范围、增量预算和降级规则见[中栏窗口读取的准备流水线](../architecture/2026-10-27-trace-window-preparation.md)。作废与自动重读见[作废读取的自动重读与快照状态](../feature/2026-10-25-reader-invalidation-auto-reread.md)，保留投影的取舍见[版本恢复期间保留旧投影](../feature/2026-10-27-trace-version-retention.md)。这些决策继续生效，本篇补上异步收尾与旧来源的资格检查。

## Alternatives considered

**继续在页面分别维护准备集合和在途任务。** 同组去重、换代释放与提交资格需要一起判断；分散在页面难以验证等待依赖时的 token 变化。准备状态集中在一个模块，正文仍由 store 持有。

**让保留投影继续驱动右栏读取。** 投影可能来自旧 token，用它的工具归属和正文位置读取新版本会把不同版本的证据拼在一起。旧行只用于显示。

**作废后由窗口准备立即再发一次读取。** store 已负责自动重读，另开请求会重复竞争。缺少当前详情时交还 store 恢复，等待新版本通知。

## Consequences

请求组按自身当前阅读版本重新收敛依赖后才提交，依赖只读取窗口内可取得的元信息。重试期间有保留投影时继续显示旧版本提示；没有可用来源时右栏按当前状态显示。代价是版本反复变化会重复准备，失败依赖仍按原有规则降级，不能据此宣称所有配对元信息都已取得。

## Testing

`tests/trace-preparation.test.ts` 用可控 Promise 覆盖批次、重复任务、换代、作废、失败重试、token 更换与依赖降级。`tests/reader-store.test.ts` 覆盖旧会话自动重读完成后不再发通知。浏览器用合成 409 场景复现旧结构选择指向新正文和调用方换版提前清选择，补修后检查页签等待、调用保留与消失、重读失败和路由页，详见[验收记录](../../../../docs/acceptance.md)；没有执行真实流量验收。
