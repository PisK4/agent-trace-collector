# Agent Note: 缺失正文与空消息序列分开判定

Status: implemented

## Problem

正文没有到达的请求与确实没有消息的请求，在库里长得一样：`body_state` 都可能是 `partial`，`request_block` 都可能为空。按"块引用为空即不可读"判定，两者被压成同一种结果。

两个方向的错都在真实数据上发生。真实空消息数组被判成不可比，整组链从第一笔就断——这类请求数量少但位置关键，它们往往是组里的第一笔。反过来，没有骨架的行被当成空序列，而空序列是任何序列的合法前缀，于是它成了任意后续请求的父节点，凭空生成一条没有证据的边；按主链规则，它还会抢走主链根。

## Decision

可比较性由持久化的消息数量判定，不由块引用是否为空判定。`fingerprintsOf` 返回 `null`（不可比较）或指纹数组（可为空数组）：`body_state` 必须是 `available`/`partial`，骨架必须存在，`msg_count` 必须是非负安全整数，且块引用的数量、ordinal 连续性与非空指纹都符合。真实空消息数组因此成为有效证据，占主链根；没有骨架的行保持不可比较，记 `unknown`。

零长度序列不再是合法父节点。`matchPredecessor` 的完整前缀条件要求公共长度大于零：空序列是任何序列的前缀，认它当父节点等于用"这一笔没有消息"证明"本笔续自它"。

`msg_count` 为 NULL 的历史行保守判成不可比较，保留旧摘要；本批不隐式补数。正常写入时 `msg_count` 与骨架的 `has_messages` 一致，损坏骨架的全面校验不在本决策范围内。

顺序也收成一套判据。逻辑顺序按 `started_ms` 优先，同毫秒按 `[sort_source, sort_key]` 的规范化 JSON 定序，`req_id` 只在遍历兜底时参与，不参与关系判定。同毫秒桶里只要出现非账本来源、缺失或非法位置、或跨账本代际，整桶标为顺序未证实；同代际重复偏移只标重复的那几条。这些请求仍可遍历，但关系记 `unknown`、不进祖先集合，同毫秒的工具关系也不能 `resolved`。

同毫秒的账本偏移之所以能当证据：账本是按写入顺序追加的文件，同代际内偏移的先后就是发生的先后。跨代际、route 文件与随机 hook UUID 只提供身份，不提供先后。

## Alternatives considered

**把空块引用一律当不可比较。** 修复前的行为。它保护了缺失正文，却把真实空消息数组一起判死。

**按 `skeleton.has_messages` 判定。** 骨架里的布尔只说明保存时 `messages` 是不是数组，不说明块引用是否完整。库被外部改动、块被误删时它会继续声称"有消息"，读出来的序列比真实上下文短，前缀比较会给出错误的增量。

**让空祖先继续当父节点，但把关系标成 `first`。** 修复前的另一种表现。它把"没有可比对象"伪装成"本组第一笔"，同时给后续请求一条假的父边。

**沿用裸 `sort_key` 字典序。** 修复前的排序。它把时间与来源键混在一个字符串里比较，跨代际的账本键会压过真实时间顺序；补上 `time|…` 兜底后，同毫秒又退化成用 `req_id` 定先后，也就是用摄入顺序冒充逻辑顺序。

**同毫秒一律按来源身份字典序定序并直接当证据。** 它能让交换摄入 ID 得到相同结果，但 route 与 hook 的身份是随机或不透明的，字典序先后没有发生学依据；等于把"排序稳定"当成"因果已证明"。

## Consequences

- 时间优先是对现行链规则的改变，跨代际的既有关系可能变化。部署代码不会自动重算历史会话，历史对齐必须逐会话走维护入口，见[实施计划的离线上线步骤](../../../../docs/superpowers/plans/2026-10-22-atc-derive-correctness.md#上线与历史结果对齐)。
- 合法空请求仍可以是主链根，但不再是任何后续请求的已确认父节点；后继请求落成 `branch`，而不是被接进一条没有证据的边。
- 同毫秒且缺来源位置证据的请求整桶保守标为顺序未证实，可确认关系的比例可能下降。这是拿可见性换确定性：不同时间的 route/hook 合成行仍按时间定序，不能概括为这些来源永远不可排序。
- 这一保守标记会沿组内顺序向后传播（顺序未证实的请求也算"前面有不可比对象"），整组可能整体落成 `unknown`。
- 没有骨架但正文状态为 `available` 的行是防御性判据，生产里对应 `partial` 的降级形态；两者都按不可比较处理。

## Testing

`tests/derive.test.ts` 的「无骨架不充当祖先或主链根」「合法空 messages 可读但不证明后续请求的父节点」「有骨架但无 messages 不参与消息前驱比较」「缺消息引用不能缩成合法空序列」锁定可比较性判据；「同毫秒交换摄入 ID 仍得到相同链角色和工具关系」「时间优先于跨代际物理键字典序」「同代际重复偏移不能由 ID 创造确定关系」「缺键同时间桶保守且来源后补可重算」与三条参数化的「无同源位置证据」锁定顺序判据。`tests/hook.test.ts` 的「命中账本的 body_omitted / metadata_only 无骨架请求保持不可比较」从真实降级入口进入。
