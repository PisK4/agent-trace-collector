# Agent Note: 首页超时中的重复宽表读取

Status: implemented

## Problem

[生产只读排查](../../../../docs/acceptance.md#生产首页超时排查只读2026-11-06)复现首页 15–20 秒无首字节。主线程采样持续在 SQLite 读取，pending 耗时很长而写事务很短。hook 缺席候选沿时间索引回表检查历史请求，stats 的正文状态分组也扫描带骨架的请求表。只看提交耗时会漏掉同步的候选准备读取。

## Decision

复用 v14 既有索引，不增加迁移或解释版本。hook 缺席候选显式重述部分索引条件，避免 SQLite 未推导出条件时选择历史时间范围回表；缺席判定、NULL 比较、迟到合并与每轮动作上限保持原义。

stats 的状态分布从窄索引取得，不读取骨架；总数和状态数保持同一个读快照。该选择保留现有字段、新鲜度与写世代缓存，无需增加一份持久化计数。读取形状归[架构设计](../../../../docs/architecture-design.md#查询接口)。

监控日报按成功且带实例标识的样本比较实例变化。失败样本继续参与失败与告警判定；没有可比较标识时报告未知，不宣称进程稳定。告警阈值与恢复窗口不变。

[hook 缺席语义](2026-10-25-hook-absent-body-aging.md)和[监控批次决策](2026-11-04-monitoring-health-batch-fixes.md)仍然有效，本记录补足读取成本与报告缺口，不替代或归档原记录。生产起停与备份沿用[运维手册](../../../../docs/operations.md#起停与状态)，实施步骤与停止条件归[计划](../../../../docs/superpowers/plans/2026-11-06-homepage-timeout-repair.md)。

## Alternatives considered

**立即新增专用索引并升级 schema。** 现有索引可满足本批合成负载目标，暂不承担存量建索引、迁移与回退成本。若生产候选回表、反查或排序仍越界，再按测量结果重新评估。

**缩短等待队列或调整重试策略。** 排查窗口只有 7 个带 response ID 的等待项会查询候选，证据不足以支持改变迟到合并、歧义重试或孤儿 TTL。

**改为延迟缓存或新增 Worker。** 放宽 stats 新鲜度会改变可观察行为；新增执行位置也扩大了查询一致性与生命周期责任。先消除重复宽表读取，再判断剩余长尾。

**性能越界立即回退旧版。** 旧版已存在高比例超时。正确性错误、启动失败或明显恶化必须回退；只有残余长尾而整体改善时保留证据继续定位，不把退回已知故障版当作恢复。

## Verification

实际函数的 SQL 计划测试防止索引退化，行为回归保留迟到、NULL、歧义、限额和统计分布。显式[宽行实验](../../../../scripts/perf-pending-stats.ts)调用完整同步任务，分别测空命中、满批和 stats 强制重算；门槛由脚本的 `limits` 定义，不加入默认测试套件。

合成实验、生产只读探针、自然流量、monitor 恢复与页面操作分开报告，实际结果归[验收记录](../../../../docs/acceptance.md)。热缓存合成数据不能代替生产冷盘与长期流量，重试也不能覆盖首次失败。

## Consequences

部分索引仍可能随 pending 历史增长而变慢，本批不承诺任意规模常数时间。同步任务中的其他摄入、费用与派生操作仍可能产生长尾；查询修复通过不等于整机可用性已恢复。

本批不执行 schema 迁移、历史正文订正或重建。无 schema 变化时可以反向提交回退代码并保留新采集数据；恢复 bundle 另走明确的数据恢复范围，不作为自动代码回退。
