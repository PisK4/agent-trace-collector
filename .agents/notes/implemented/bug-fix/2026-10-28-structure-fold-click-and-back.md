# Agent Note: 结构折叠的默认面与返回

Status: implemented

## Problem

中栏改成按承载请求的 delta 分组后，点击任意消息行都会打开读数页。合并后的第一版把选中消息直接交给结构折叠：折叠展开时列表已被这条消息的详情替换，读者看不到自己点开的「这一行在请求结构里的位置」。更糟的是「返回消息列表」没有可见效果——折叠的选中同时来自步骤选择与结构选择，按钮只清后者，步骤选择立刻把详情又钉了回去。

合并前的另一分支按「返回时一并退出步骤选择」修过同一症状（见[消息配对按结果路径确认，返回列表退出步骤选择](2026-10-28-message-pair-path-and-structure-back.md)），按钮能用了，代价是连中栏的选中与高亮一起丢掉。

## Decision

折叠的详情选择只来自结构列表内的点击（`structureSelected`）；中栏选中的消息只决定三件事：折叠展开、列表里这一行的高亮（`highlight`）、以及列表滚到这一行。中栏点击不再写 `structureSelected`，因此详情不会因为一次轨迹点击而替换列表；在列表里点开的消息才显示详情，「返回消息列表」只清结构自己的选择，步骤选择继续给这一行高亮，不需要 `clear-step`。

滚动落点：中栏点中的消息在下一次右栏渲染时滚到列表中部，压过「落底」与锚点恢复；行还没进列表（读取中或不在已读分片）时保留待定位，换请求作废，不把读者留在列表末尾。

结构未读的折叠由点击方补读：自动展开的 `<details>` 不经过 `toggle` 事件，`ensureRead` 在读取就绪后按「折叠开着且结构未读」补一次尾片。未读判定抽成 `structureUnread`：从未读过（`structure.total` 为 null）按元信息总数判断，按钮读作「从末尾读取（共 N 条）」，不写误导的「已读 0–0」；读过后仍按已读下界 `back` 判断。

## Alternatives considered

**返回时退出步骤选择（合并前的修法）。** 按钮能用，但中栏的选择与高亮一起被清掉，读者返回列表后失去「刚才点的是哪一条」的定位。否决。

**点击直接展开详情，只修返回。** 点击的承诺是「打开这一行所在的请求结构」，详情替换列表让结构本身看不到，读者要先返回才能看到自己点开的东西。否决。

**列表与详情同屏，详情放在列表下方。** 40 条列表之下再接详情，首屏仍是列表，但要滚过整段列表才看到详情，折叠区高度也翻倍；收益不足以抵消。未采用。

**中栏点击写 `structureSelected` 并把「返回」改成同时清步骤。** 等于保留两个选中来源再让它们互相清理，返回后高亮与选择一起消失；选中来源只留一个更简单。否决。

## Consequences

中栏点击后看到的是结构列表与高亮行，消息详情多一次点击；结构未读时会多一次尾片读取，换来列表里能看到消息的位置而不是只有定点读到的一条。返回列表保留中栏选择与高亮。行不在已读分片时没有高亮，待定位保留到该行进入列表；同请求的再次点击会覆盖待定位。

## Testing

合成：`tests/web.test.ts` 覆盖「高亮不展开详情」「结构内点开详情可返回」「从未读过时按总数判断未读与按钮文案」「`structureUnread` 五种状态」；`bun run typecheck` 通过。真实数据（生产库在线快照、临时 collector 端口 8771，生产采集器未停）只读核对：点组 4 消息行 → 读数页结构折叠展开、列表高亮 `messages[2]`、无详情与返回按钮；在列表里点开 → 详情替换列表并给「返回消息列表」；返回后列表回来、`messages[2]` 仍高亮；再点一次仍能打开详情。请求 98（210 条消息）首读尾片 `[170,210)`，点中的 205 被滚到可见位置，「加载更早」后首条可见消息仍是 200、偏移 −16 不动。正文不进 fixture 与本记录，详见[验收记录](../../../../docs/acceptance.md)。
