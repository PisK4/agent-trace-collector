# Agent Note: 轮次命令按正文证据定位

Status: implemented

## Problem

轮次结算已经找到起点与收尾，但定位命令时只读 `messages` 和可信增量。Responses 的 `input` 因此找不到命令；由末尾形状支撑的起点也没有可信增量序号，即使正文可读，命令面板仍会空掉。Responses 裸字符串被存成内部消息块，直接把内部序号展示成原始数组路径同样不准确。

## Decision

轮次起点与路径污染仍由派生结果判定。已结算且位于返回窗口内的起点，再按其证据定位正文：可信增量在正文实际拆出的消息块中筛选用户主动文本；末尾形状沿用派生扫描，只定位匹配的末尾文本。正文引用不完整或尾部块无法解码时保留轮次并报告位置缺口。

正文来源路径来自存储骨架确认的键与形态。可信增量消费完整正文读取返回的原始消息块，与路径使用同一份拆块事实：旧 Responses 骨架可能拆的是 `messages`，即使请求同时含 `input`，内部序号也仍指向 `messages`。裸字符串没有数组下标；骨架无法确认时不猜路径。正文读取和轮次接口的现行形状见[架构设计](../../../../docs/architecture-design.md#轮次带与轮次两端阅读)。

本决策部分补充[轮次两端阅读](../feature/2026-10-25-turn-pair-reading.md)与[末尾命令形状](../architecture/2026-10-28-tail-command-shape.md)：沿用起点与结算判据，增加命令全文的定位。派生与读取共用的末尾扫描遇坏块停止，以免把更早历史当成本次末尾命令。同步组算法从 5 升到 6，切片算法从 9 升到 10；工具参数提取未变，汇总继续承认 5 / 9 的工具事实。

## Alternatives considered

**把末尾消息序号写成可信增量。** 末尾形状不证明相对前驱新增，复用增量字段会改变链证据的含义，也会让其他消费方误用。保留独立的阅读定位。

**只按协议名猜来源路径。** Responses 支持数组与裸字符串，旧骨架也可能拆 `messages`；使用骨架记录的键与形态。骨架不可信时不给路径。结果配对要求原始路径精确一致：旧混合键形态的 `input` 结果不会按序号强配给 `messages` 块，路径不同则中性显示。

**读取所有候选正文重新判定起点。** 起点和污染判据已有派生证据；每次结算都重解读全部候选会增加读取成本并形成第二套判据。只读取窗口内已结算起点。

## Consequences

可读的 Responses 命令和末尾形状命令有可定位的正文，损坏与回收不会生成虚假的命令位置。末尾形状不保证更早用户消息也属于本轮，故只呈现末尾一条；相对前驱不可判的跨请求工具循环仍不能凭时间建立确定链。

读取 `delta` 需恢复起点正文；末尾定位最多解码六个消息块，引用完整性检查仍需检查引用索引。本轮不改 schema。已派生为 `tail_command` 的历史行可按新规则定位正文，仍为 `tail` 或曾因坏块误判的历史行不会自动重算，按既有规则在修复或确认正文后显式按会话重建；不可恢复的正文仍受原有保留策略限制。

## Testing

`tests/turn-settlement.test.ts` 使用合成 Responses 数组、裸字符串、工具循环与未知前驱，覆盖命令位置、损坏引用、末尾坏块与显式重建。旧 Responses 骨架分别覆盖仅含 `messages` 和同时含 `messages`、`input` 的情况，确认命令序号来自实际拆出的块。`tests/body.test.ts`、`tests/turn-band.test.ts`、`tests/trace-view.test.ts` 和 `tests/web.test.ts` 覆盖原始形态与缺口显示。`tests/derive-slice.test.ts` 检查同步与切片在坏尾块下的结果一致，也检查前一切片算法的工具事实覆盖率；同步算法的覆盖率由 `tests/session-summary.test.ts` 检查。
