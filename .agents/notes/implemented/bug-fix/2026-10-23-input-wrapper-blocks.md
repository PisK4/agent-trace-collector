# Agent Note: 输入包装按内容块清洗，不再只剥消息开头

Status: implemented

## Problem

harness 的包装在真实消息里是按**内容块**出现的，一条用户消息常由多个文本块拼成。旧的解释器把全部文本块用换行拼起来，只在整段开头剥包装，于是排在用户正文之后或中间的包装块被当成用户输入。

用只读 v4 副本（21,151 条用户消息、103,942 个用户文本块）复核：

- `system-reminder` 19,758 块，其中 8,905 块不是消息的第一个块；2,820 条消息的可见输入里带着整段提醒。
- `local-command-caveat` 804 / `local-command-stdout` 765 块同样排在后面。
- 认不出的标签整段留在可见文本里：`file`（附件，64 块，块长 p50 12 KB）、`job`（omp 作业规格，53 块，规格之后才是用户的话）、`chat`（5 块）、`user`（3 块）。
- `<pasted_content id=…>` 有 248 个开块；闭标签带属性（`</pasted_content …>`），落在同一条消息的后续块里（343 个块带闭标签），闭标签之后还常跟着用户自己的话。

后果不只在页面气泡：`deriveTitle`、`previewOf`、`tailUserPreview`、`firstUserPreview` 都取第一个 `state='text'` 的可见文本首行，提醒或附件正文会成为标题与折叠行摘要。

## Decision

先把每个文本块单独清洗，再拼接，最后仍走一遍整段规则：

- 只由一对已知标签组成的块整块丢弃（`system-reminder`、`transcript`、`local-command-*`、`system-notice`、`recap`、`job`、`file`、`chat`）。
- 套着用户正文的壳剥壳留内容（`session`、`user`）。
- `<pasted_content id=…>` 是粘贴标记：删标记行与闭标签，粘贴正文保留——它是用户输进去的内容。
- 块的**开头**才剥包装；块中间的标签仍按用户内容原样保留。跨块的 `<transcript>` 在块内看是未闭合的，因此块级清洗不动它，仍由整段规则按拼接后的全文配对。

丢掉整块包装之后，如果一条消息只剩空文本，沿用原有判定：有删除记录就是 `injected`，没有就是 `empty`。

## Alternatives considered

**只扩充整段开头的标签集。** 问题不在标签集，而在位置：8,905 个提醒块根本不在消息开头，扩充标签集一个也救不回来。

**把所有同名字符串都从正文里删掉。** 用户会贴带标签的文本（真实数据里有 163 条消息的可见正文本身含 `<transcript>`），全删等于改用户的话。边界只能是块的开头。

**把附件（`file`）当用户正文展开。** 附件是用户提供的上下文，不是他们说的话；展开会让 12 KB 的代码成为气泡正文、标题与折叠行摘要的第一行。原文仍留在 `original` 里可复制，页面也照常转义。

**按 camelCase / snake_case 或大小写猜标签名。** 猜测会把不同客户端的同名字段混成一个；标签集在一处显式列出，认不出就原样保留。

## Consequences

- 真实副本上 1,992 条消息的可见文本变化；324 条从 `plain` 变成 `wrapped`（消息级标签记录现在包含块级删除）。1,154 条可见文本里不再出现包装标签。
- `file`、`chat` 独占的消息从 `text` 变成 `injected`；这类消息本来就没有用户说的话，标题与摘要改由后续消息提供。
- 语义指纹不动：包装仍然参与指纹，同一段历史在后续请求里字节稳定，链判定不受影响。
- 已经派生的行保留旧标题与旧摘要，等所在组重算时才换；本轮不为此改算法版本，也不回填历史。
- 认不出的标签（例如未来客户端新增的提示）继续整段保留并标注入或文本，不猜语义；新增标签要在[架构文档的输入解释一节](../../../../docs/architecture-design.md#输入解释与能力阅读)与这里同时登记。

## Testing

`tests/input-interpretation.test.ts`：块级用例覆盖「排在用户正文之后的包装块」「粘贴标记与闭标签」「作业规格丢弃、之后的话保留」「附件与对话简报」「跨块 transcript 仍被剥掉」「块内未闭合的已知标签原样保留」「user 壳保留内文」；`tests/derive.test.ts` 锁定标题与增量仍走同一解释。
