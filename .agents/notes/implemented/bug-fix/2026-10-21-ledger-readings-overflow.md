# Agent Note: 账本读数列的裁剪与异常标志外移

Status: implemented

## Problem

账本折叠行的读数列固定 168px、右对齐并 `overflow:hidden`。当一笔请求同时有首字、总时长与两项 token 时，四项内容实测 184.8px，超出部分从左侧被裁掉，最先丢失的是行首的 `首字` 标签；再叠加 `⎇ 分支`、`待关联` 等变长标志时，最坏情况内容宽 294.9px，两个标志与 `首字` 全部不可见。页面本身没有横向滚动：右对齐的负向溢出不会进入 `scrollWidth`，所以既有验收（只比较页面 `scrollWidth === innerWidth`）看不到这类裁剪。

## Decision

读数列只放数字，并按两行排布：上行首字与总时长，下行输入与输出 token，两行各 18px、右对齐，与内容列的两行对齐。168px 固定宽度保留，实测现有最大值下最宽一行 133.5px，余量 34.5px。

异常标志（失败、待关联、正文未到/回收/不完整/协议不支持）、分支标记与 HTTP 状态码移出读数列，放在内容行右端，`flex:none` 并右对齐；正文预览作为可收缩项用省略号让位。标志的右边缘因此始终落在内容列内，且与行右边界的关系固定。

1240px 以下整列移除读数列，而不是只隐藏可选读数；内容列接管原读数列的空间，异常标志仍然可见。620px 以下只收窄类型标签到 52px。

## Alternatives considered

**把列宽从 168px 加到 192px。** 只能覆盖典型行；现有数据最大 `首字 131.56 s + 133.44 s + ↓ 240.3k + ↑ 12.1k` 单行需要约 244px，仍会裁掉行首标签。

**去掉 `首字` 标签，保留单行。** 省 27px，但四项读数在现有最大值下仍需约 217px；同时丢失两个时间的语义区分。

**让读数列按内容自适应。** 每行数字的左边界随内容漂移，纵向扫读读数时列不再对齐，退回到固定列宽之前的问题。

**把标志放进类型标签列或单独的标志列。** 标志宽度可变，两个标志最宽约 127px；单独一列会在每一行固定占掉这些宽度，类型标签列只有 56px 放不下。

**1240px 以下继续隐藏标志。** 异常与分支是折叠行唯一主动出声的信息，隐藏它们会把「正文未到」这类状态藏起来；旧布局在 620px 以下已经付出过这个代价。

## Testing

浏览器几何验收（合成数据，覆盖现有最大值与最坏标志组合）：

- 1500px：每个 `.req-metric-line` 的所有子元素 `left >= 0`（实测最小 34.5px），读数行无内部溢出；最宽一行 133.5px；读数行与内容行的 top 偏差为 0。
- 1500 / 1200 / 900px：页面 `scrollWidth === innerWidth`；折叠行 56px；标志右边缘不超出内容列。
- 619 / 400px：`min-height:56px`，实测 57px（含底边框）；页面无横向滚动，标志仍在内容列内。
- 1240px 以下读数列 `display:none`，内容列接管空间；标志仍可见。
- 本机 CDP 截图仍超时，验收使用元素几何与计算样式。

## Consequences

- 读数不再被裁剪，异常标志在宽屏与窄屏都保留；行高、标签位置与主文本起点不变。
- 正文预览与标志共享一行，标志出现时省略号提前；这是把状态优先级放在文本之后的代价。
- 1240px 以下没有读数，但此前这些读数在该断点也已经被 `.opt{display:none}` 全部隐藏，信息量没有净损失。
- 固定列宽只对读数负责；以后新增读数时必须同时更新宽度预算与「子元素不越左边界」的几何验收。
- 168px 的两行预算在当前最大数据下有 34.5px 余量；两行时长都达到约 10 万秒（约 28 小时）时仍会从左侧裁剪，届时需要压缩时长格式或扩大列宽。
