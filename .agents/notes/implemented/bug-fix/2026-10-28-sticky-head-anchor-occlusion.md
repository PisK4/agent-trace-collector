# Agent Note: 吸顶会话头下的滚动锚点

Status: implemented

## Problem

打开会话后，中栏不从头显示：1 号组整组落在吸顶的会话头下面，列表看起来从 2 号开始。

浏览器实测（会话 `a58b0a51`）：会话头在汇总快照到达后从 135px 长到 205px。提交先按视口绝对坐标记下首条可见步骤，此时 1 号组顶 187px，等于旧头底；同一提交里替换会话头，内容整体下移 70px，`restoreAnchor` 为保持锚点的视口偏移把 `scrollTop` 从 0 加到 70。新头底 257px，补偿后的锚点正好落进遮挡区。

[web/trace-dom.js](../../../../web/trace-dom.js) 的 `captureAnchor` 与 `restoreAnchor` 都把 `main` 的盒顶当可见区上沿。会话头与轮次带是 sticky，`0..headH` 这一段被它们盖住，锚点机制没有表达这个事实。

## Decision

锚点的可见上沿改用吸顶元素下沿：

- `stickyBottom(main, scroller)` 取 `.session-head` 与 `.turn-band` 中 `position: sticky` 的元素的 `max(bottom)`；没有生效的吸顶元素时退回滚动容器盒顶。
- `captureAnchor` 用它做可见上沿，被盖住的行不参与锚点选择。
- `restoreAnchor` 的向下补偿经 `clampRestoreDelta` 夹取，最多把锚点放到遮挡区下沿；向上补偿保持原样。

头部高度不变时两条路径与旧公式等价。头部变高时，本会落进遮挡区的锚点停在吸顶下沿。

## Alternatives considered

**只修首组。** 打开会话后把首组贴到吸顶下沿，别处不动。否决：头部增高发生在任意提交里，汇总快照、窗口错误行与刷新时间行都会改变头部高度，只修首组会把同类遮挡留在其他入口。

**提交前记下吸顶下沿，按「相对吸顶下沿的偏移」守恒。** 语义同样正确，但 Anchor 要多带一个字段，并且会改变头部变高时中段阅读的落点。夹取只改变补偿会把锚点推进遮挡区的那一类情况。

**首次渲染时预留汇总折叠区的高度。** 能避开这一次的头部增高，但头部高度还会随窗口错误、刷新时间与折叠开合变化，预留高度只是把问题挪到下一次。

## Consequences

- 打开会话后 1 号组完整可见；头部高度不变时，中段阅读的补偿与旧行为一致。
- 头部变高且锚点本会落入遮挡区时，读者看到内容停在吸顶下沿。这是有意的行为变化。
- 吸顶元素的高度仍由内容决定，没有引入固定头部高度或占位。
- 窄屏的会话头是 `static`，`stickyBottom` 退回滚动上沿，行为不变。

## Testing

- [tests/trace-anchor.test.ts](../../../../tests/trace-anchor.test.ts) 断言 `clampRestoreDelta`：头部变高时 70px 的补偿被夹到 0；部分遮挡只补到吸顶下沿；中段阅读的补偿原样保留。
- 浏览器实测：打开会话 `a58b0a51` 后 `scrollTop` 保持 0，1 号组顶 257px，与会话头底边重合；「回到开头」同样落在 257px；「回到最新」仍选中最新一笔并居中。
