# Agent Note: 「加载后续记录」加载完成后仍保持禁用

Status: implemented

## Problem

真机验收发现：点一次「↓ 加载后续记录」把窗口从 30 笔扩到 60 笔后，按钮停在禁用态，再点没有任何请求，只有换窗或刷新才能继续翻页。

原因是两个状态源打架。[app.js](../../../../web/app.js) 的 `loadLater()` 就地给按钮置 `disabled`，而中栏按稳定键提交：加载完成后渲染输入里的加载入口 HTML 与点击前完全一样，`planCommit` 判定同键同 HTML 不换节点，就地改上去的 `disabled` 就留在 DOM 上。加载中的「正在读取后续记录…」也从未显示，因为 `renderMain()` 只在 `await` 之后调用一次。

## Decision

`loadLater()` 不再碰 DOM 属性：先调用 `store.loadLater()`（`windowLoading` 在第一个 `await` 前同步置真），立刻 `renderMain()`，让加载入口按渲染输入换成「正在读取后续记录…」；`await` 完成后重绘回按钮。重复点击由 store 的 `windowLoading` 门挡住，不靠禁用属性防重入。

## Alternatives considered

**在 `await` 之后手动把 `disabled` 置回 false。** 把 DOM 当状态存储，下一次改渲染输入（比如以后调整入口文案）又会漂；键控提交的约定是可见结果只由 HTML 字符串决定。不采用。

**让加载入口的 HTML 带上时间戳或随机数强制换节点。** 为了绕过比较规则，把无关信息塞进可见结果，提交计划的输入变得不可预测。不采用。

## Consequences

- 得到：加载完成后按钮恢复可点，可以连续翻页；加载中有文字反馈，不再只有一次点击机会。
- 代价：加载中的禁用态变成文案替换，按钮在加载期间消失；如果以后需要「不可点但仍在原位」的样式，要在模型里加显式状态，而不是就地改属性。

## Testing

真机复测（`0a950369`，生产库）：点「加载后续记录」30 → 60 笔，入口回到「↓ 加载后续记录」且未禁用；再点一次 60 → 120 笔。`web/app.js` 是 wiring，不在单测覆盖内。
