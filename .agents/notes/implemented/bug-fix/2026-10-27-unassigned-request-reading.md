# Agent Note: 孤立请求的正文与来源报告

Status: implemented

## Problem

缺少可确认会话归属的 hook 请求仍可能保存了请求正文。阅读器只消费可信新增消息，无法派生增量的请求因此只显示 Event，已有正文也无法在中栏阅读。账本错误和回调失败各自有来源事实，缺少清晰的来源提示时，读者也难以区分失败原因与没有收到回复。

缺少共同稳定标识的 hook 与账本记录可能在时间和模型上相近，这些相似条件不能排除并发、重试或证据缺失。

## Decision

按[轨迹阅读布局](../../../../docs/architecture-design.md#轨迹阅读布局)读取和展示归属未知的请求正文，同时保留归属未确认的提示。请求携带的历史和未确认的工具结果只按自身来源呈现，不用它们推断新增、工具配对或会话关系。回调报告和账本错误各自标明来源，不从回调结果补出 HTTP 状态。

本决定部分取代[生产阅读缓存 reader-store](../feature/2026-10-24-reader-store-cache.md)中未确认增量一律不读取消息的限制，并保留[单行步骤投影 trace-view](../feature/2026-10-24-trace-step-projection.md)的可信新增判据。[中栏窗口读取的准备流水线](../architecture/2026-10-27-trace-window-preparation.md)继续控制提交与并发预算；[版本恢复期间保留旧投影](../feature/2026-10-27-trace-version-retention.md)继续隔离旧版本的显示与读取。

## Alternatives considered

**继续隐藏孤立请求的正文。** 已保存的请求消息无法在轨迹中阅读，Event 行也无法解释实际输入。

**按时间和模型合并 hook 与账本。** 时间相近仍可能来自不同请求；缺少共同稳定标识时，自动关联会制造没有证据的失败原因和正文归属。

**将请求携带的历史消息当作新增。** 请求正文可能包含完整历史；没有可信增量时无法确认哪条是本次新增，历史 Assistant 也不能冒充本次回复。

## Consequences

读者能够查看孤立请求已保存的消息，并分别看到已知的回调、账本和 HTTP 状态。首片之外需要显式续读；有缺口或失败时保留重试入口。缺少稳定关联依据的记录仍分别显示，可能在页面中看起来相似。

本次只改变读取和展示，不修改持久化事实或请求关系。各类已确认会话的增量判定仍沿用原有规则。
