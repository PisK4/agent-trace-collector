# Agent Note: 跨来源模型名不参与调用身份比较

Status: implemented

## Problem

本地会话适配器上线后的首个生产轮转里，Zcode 的网关行与本地行没有合并：同一笔调用在 `request` 表里各占一行，四段 token、会话、开始时间（差 40 毫秒内）全部相同，只有 `model_requested` 不同——网关是 `group/auto-deepseek-v4-1-flash`，本地是 `auto/deepseek-v4.1-flash`。只读核对时有 189 对能唯一配上，且随回填继续增长。

根因在 `findRequestOwnerTx` 的两条跨来源线索都把模型名当硬条件：四段用量指纹在查询侧带 `model_requested=? OR model_served=?`，弱时间窗同样要求模型相等。网关会加供应商前缀、把点号写成横线，本地保留原始写法，等值比较几乎必然落空。这与[多来源同一调用的身份归一](../../proposed/feature/2026-11-04-multi-source-call-identity.md)里写定的规则相反：指纹本来就不该比较模型，时间窗只在模型可证时比较、模型名不同不构成拒绝理由。

## Decision

**指纹只比四段用量。** `usage_fingerprint.v1` 保留同 `conv_key`、同 agent、±2 秒、`in_tok/out_tok/cache_read/cache_write` 逐段相等、候选唯一、排除同来源证据；删掉模型过滤。四段用量同时相等已经足够具体，模型名不同只影响展示，不影响“是不是同一笔调用”。

**弱时间窗按归一后的模型名比较。** 新增 `normalizedModel`：转小写，去掉开头连续的 `group/`、`auto/` 前缀，再删掉所有非字母数字字符。只用于比较，不改写入库的原值。时间窗候选先按归一后模型相等过滤：恰好一个就认领；没有相等的候选时，唯一候选仍然认领（模型名不同不是拒绝理由）；多候选且无法区分时保持 ambiguous。查询侧模型为 null 时同样走这条兜底，一方缺失不再直接放弃。

**已落库的重复行由显式命令修复。** 新增 `bun run maintain dedupe-sessions --db <path>`：默认只预览，`--apply --approval-id <id>` 才写库。它只处理“只有一条会话证据”的行，按同一套 `findRequestOwnerTx` 再找一次 owner；只认精确身份（response id、turn ref、四段用量指纹），弱时间窗能配上的行只计数（`weak_only`），不在事后改行。命中后走新的共享 `mergeRequestTx`：迁移证据、正文引用、工具链接、别名与整组身份字段，删除源行，重算目标与两边的派生组。

**行合并逻辑从 hook 挪到共享层。** `src/merge.ts` 承接原 `mergeHookInto` 的行级迁移；hook 只剩 pending 队列与 hook 证据状态。`mergeRequestTx` 的 `fillIdentity` 选项区分两种合并：hook 只补账本缺失的 response/conv 身份，会话修复补全会话、actor、模型、用量、标题与来源事实。合并本身仍按“目标已有的事实不覆盖、空字段才补”的规则。

## Alternatives considered

**继续把模型名当硬条件，只做前缀归一。** 只能覆盖已知的 `group/`、`auto/` 两级前缀；供应商换写法（大小写、点号、`sn-` 前缀）就再次漏配。指纹的四段用量已经唯一，继续要求模型相等没有增加识别力，只会把真实重复留给人工。

**指纹匹配失败后直接放弃，不落到时间窗。** 相邻调用在 60 秒窗里经常有多个候选，放弃会让本地与网关各留一行；候选唯一性与归一后模型排序已经把误合并压到很低，弱兜底仍有价值。

**修复命令只删重复的会话行，再重置 Zcode 游标重放。** 删除会丢掉已经合并进这些行的其它来源证据（本批有 5 笔 OMP 行已带 hook 证据），且要重新解析 342 个会话；合并在原事务里完成，数据不丢、可重复执行。

**把修复做成自动任务，每轮扫描重复行。** 生产写路径每轮多做一次全表身份查询，成本与收益不匹配；重复是一次性的历史欠账，显式命令更符合仓库的迁移习惯。

## Consequences

- 生产库修复后，189 对 Zcode 重复行并入网关行；本地会话证据、正文与 actor 迁到目标，网关已有正文不被覆盖。修复命令重复执行为 0 合并。
- 弱时间窗比之前更容易命中：一方缺模型或多候选里只有一个归一后相等时会合并。代价是“同会话 60 秒内、模型缺失、候选唯一”的误合并风险；候选不唯一时仍保持两行。
- 模型归一规则只覆盖 `group/`、`auto/` 与标点差异。出现新的供应商前缀或模型族重命名时，需要扩展 `normalizedModel`；扩展前的不匹配行可由 `dedupe-sessions` 预览发现。
- hook 合并的行为不变：共享函数默认不迁移会话、actor 与模型字段，只补 response/conv 身份与 `have` 位；hook 相关测试全量通过。

## Testing

- `tests/owner-fingerprint.test.ts`：模型写法不同仍按四段用量认领；时间窗按归一后模型认领；模型名不同但候选唯一仍认领；多候选中只认归一后相等的；多候选无模型线索不合并。
- `tests/session-dedupe.test.ts`：历史重复行并回网关行并迁移证据与别名；只有弱时间窗能配上的行不修；已并入其它来源证据的会话行不参与修复。
- `tests/droid-dedupe.test.ts`：时间窗的模型名不同但候选唯一时合并；同窗多候选仍不合并。
- `bun test` 全量 1232 通过；`bun run typecheck` 通过。
- 生产验收待补：修复命令的预览与执行计数、合并后页面单行展示、后续轮转不再新增重复。
