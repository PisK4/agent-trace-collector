# Agent Note: Hermes 本地行按完成时间认领网关调用

Status: implemented

## Problem

Hermes 适配器把 `messages.timestamp` 当成调用开始时间写进 `started_ms`。只读对账推翻了这一点：该字段是消息落库时刻，等于调用完成时间。网关行有 `started_ms` 与 `ms`，本机会话里同一笔的 `timestamp` 与 `started_ms + ms` 只差 5–80 毫秒，与网关开始时间却可能差出整个调用时长。

错误基准把 owner 匹配的 ±60 秒开始窗变成掷骰子。修复前生产库有 4,560 条 Hermes 本地证据：旧规则（开始窗 + 模型相等）认领 3,216 条正确、12 条错误、92 条多候选、1,151 条无候选。更糟的是已经合并的 58 条里 30 条挂到了错误的网关调用上，本地完成时间与错主的网关结束时间中位差 24.7 秒——长调用被并进下一笔，短调用又被前一笔抢走。证据挂错不破坏正文（所有错主行的 `body_state` 都是 `available`），但页面上的来源与用量会指到另一笔请求。

## Decision

### 1. 适配器同时给出开始与结束

`SessionCall` 增加可选的 `endedMs`。Hermes 适配器把 `timestamp` 填进 `endedMs`，开始时间取同一会话展示集里的上一条消息时间戳——工具结果或 user 消息写完，下一笔调用随即发出——缺值才退回会话 `started_at`。摄入层据此写入 `started_ms` 与 `ms`（时长），本地行重放和事后复核都能还原窗口。

### 2. owner 匹配新增完成时间线索

`findRequestOwnerTx` 在用量指纹之后、弱时间窗之前增加 `byConvEnd`：同 `conv_key`、同 agent、`started_ms + ms` 与本地 `endMs` 相差不超过 2 秒，且候选唯一才认领，规则名 `conv_end.v1`。这里不要求模型归一相等——网关模型名与本地 `sessions.model` 经常不同，完成时刻已经足以唯一定位；多候选照旧标 `match_ambiguous`，不猜。

生产数据的判别结果（4,560 条本地证据，正确性用本地结束时间与网关结束时间 ≤2 秒独立判定）：

| 规则 | 唯一正确 | 唯一错误 | 多候选 | 无候选 |
|---|---|---|---|---|
| 旧开始窗 + 模型 | 3,216 | 12 | 92 | 1,151 |
| 完成窗 + 模型 | 3,230 | 0 | 99 | 1,142 |
| 完成窗，不限模型 | 3,320 | 0 | 105 | 1,046 |

完成窗把可比样本的错并降到 0，因此取「完成窗不限模型」。来源既已给出完成时间，完成窗不命中就独立成行，不再退回弱开始窗；弱窗只留给没提供完成时间的来源。生产重修后的对账给了这条规则直接证据：3,319 条按 `conv_end.v1` 合并的错主为 0；首次重摄入仍有 4 条走 `conv_time_model.v1`，按本地完成时间核对全部错主（结束差 16–198 秒），这条兜底因此去掉。网关缺 `ms` 的行不参与完成窗，也不会再被弱窗并走。

### 3. 提供按来源重置的修复路径

已经错并的证据不能靠原地改规则修正：认领结果没有反向索引，逐行回算既慢又容易留下半合并状态。新增通用维护命令：

```sh
bun run maintain reset-source --db <dataDir>/trace.db --source hermes_session --apply --approval-id <id>
```

它删除只有这一来源证据的请求行，摘掉混合行上的这一来源证据并清 `HAVE_SESSION` 位，删除该来源的游标与原始行，然后把受影响的会话组标脏。与淘汰路径不同，这里不写 `purged_evidence` 墓碑——重置的目的就是让同一批调用重新落库。命令默认只预览计数；未知来源直接拒绝。`hermes_session` 只是第一个使用者，任何本地会话来源都能用。

## Alternatives considered

**只修适配器，不新增匹配规则。** 开始时间可以估准，但网关侧长调用与本地开始估计仍会漂；旧规则实测仍有 12 条错并，且没有任何信号能在合并时判定对错。

**用开始窗但放宽到几分钟。** 长调用能进来，密集工具循环里又会撞上多笔候选；错并方向从「漏」变成「抢」，比多建行更难发现。

**完成窗要求模型相等。** 少认领 90 条，正确数不增，反而把本地 `sessions.model` 与网关模型名不一致的调用推回弱窗口。完成时刻唯一时模型不是必要证据。

**原地 UPDATE 修错主行。** 需要逐条重算 owner、重写证据与正文归属，还要处理同一行被多个本地副本引用的情形；失败后库里会留下既非旧规则也非新规则的混合态。重置后重摄入只有一个中间态：这一来源暂时没有数据。

**重置时写墓碑。** 墓碑会让重摄入把同一 ref 判为 `purged_skip`，正好挡住这次修复的目的。

## Consequences

收益：Hermes 本地行与网关行的对齐从「时间近似 + 模型相等」变成「完成时刻唯一」，可比样本零错并；`ms` 落库后，即使只有本地来源也能算出每次调用的时长；旧规则合并过的 58 条（其中 30 条错主）可以通过一条可预览、可审计的命令整体重建，不需要手写 SQL。

代价：一，多候选从 92 升到 105——完成时刻比开始时刻更容易在一批并发调用里撞车，这些行会多建而不是错并。二，仍有 1,046 条本地证据找不到完成窗内的网关行，其中 630 条所在会话根本没有网关数据；这些行保持独立展示，与多数据源规则一致。三，`started_ms` 对 Hermes 是估计值：取上一条展示行时间戳，误差等于该消息到下一次请求发出的间隔，页面上的开始时刻可能早几十毫秒。四，网关缺 `ms` 时完成窗不命中，本地行独立成行，可能出现同一调用的两条展示，但归属正确。五，重置会临时删除该来源的本地行与游标，重摄入完成前页面上这部分数据缺失；大库需要多轮回填才能追平。
