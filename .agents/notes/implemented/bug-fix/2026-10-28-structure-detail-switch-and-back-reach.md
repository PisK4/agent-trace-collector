# Agent Note: 结构详情的换选与返回可达

Status: implemented

## Problem

[结构折叠的默认面与返回](2026-10-28-structure-fold-click-and-back.md) 上线后在真实页面上留下两处缺口，都是那次修复没覆盖到的路径。

**换选停在旧详情。** 在结构列表里点开 `messages[2]` 的详情后，直接点中栏 `#3`：中栏高亮换到了 `#3`，右栏仍是 `messages[2]` 的正文，而且没有列表可点。读者要么先按「返回消息列表」再去找新行，要么以为自己看的是新消息。原因是 `selectRequest` 只写 `folds` 与 `structureReveal`，没动 `structureSelected`——列表的详情选择由结构自己持有，中栏点击管不到它，两者于是各说各的。

**返回被正文推出视口。** 「返回消息列表」原本排在详情下方。消息短时按钮就在视野内；长消息（请求 98 的 210 条里有 4 条）正文高度 700–1000px，按钮落到视口下方 169–439px 处，点开后必须往下滚才找得到返回入口。返回是退出详情的主路径，不该依赖读者先滚到页脚。

## Decision

中栏点中消息行时，一并清掉该请求的结构详情选择（`structureSelected.delete(id)`）。中栏点击的承诺是「看这一条在结构里的位置」，列表就是这个位置的呈现；上一轮在结构里开的详情让位给新的选择，读者要看新一条的正文，在列表里再点一次即可。请求级行不清——它不指向任何消息，折叠与结构选择都保持原样。

「返回消息列表」移到详情上方，与「加载更早」同侧。退出入口固定在折叠体顶部，正文多长都不影响它可达。

## Alternatives considered

**保留旧详情，只把列表高亮换成新行。** 列表已被详情替换，此时的高亮不可见；读者看不到任何「换选成功」的反馈，只是中栏一行变了色。否决。

**点中栏消息时把详情换成新消息的正文。** 等于回到被推翻的第一版：点击直接进详情，结构列表看不到。否决。

**返回按钮用 `position: sticky` 钉在折叠体底部。** 需要给 `fold-body` 一个滚动上下文，`overflow:hidden` 的折叠区要改，滚动行为与右栏自身滚动叠加后不好预测；改成把入口挪到顶部，一行改动解决同样的问题。否决。

**详情放进独立的滚动容器，按钮固定在容器外。** 折叠区高度受限，长正文要二次滚动才能读完；换来的只是按钮位置，代价是阅读路径多一层滚动。否决。

## Consequences

结构里开着详情时点中栏别的消息，会退出详情回到列表并高亮新行——这是有意的：右栏与中栏始终指向同一条消息。读者若只想换中栏选择而保留详情，先收起折叠再点。

返回入口在详情上方后，读者点开详情的第一屏就能看到退出路径；代价是按钮与正文之间多了一层留白（`.conv-tools` 的既有内距），长正文滚动时按钮会随内容一起滚出视野，此时按浏览器回退或再点中栏即可，与之前「按钮在页脚、要滚下去找」相比仍是净收益。

## Testing

合成：`tests/web.test.ts` 增加「返回入口排在详情之前」的位置断言（`data-structure-back` 出现在 `body-panel` 之前），原有「高亮不展开详情」「结构内点开详情可返回」继续通过；`bun run typecheck` 通过。

真实数据（生产 127.0.0.1:8320，只读交互，未改动采集器）：点 `#2` → 列表高亮无详情；列表内点开 → 详情 + 返回；返回 → 列表与高亮保留。点 `#2` 开详情后再点中栏 `#3` → 右栏回到列表、`#3` 高亮、详情消失。请求 98 逐条量返回按钮位置：修复前 40 条里 4 条需要下滚（169–439px），修复后全部在视口内。详见[验收记录](../../../../docs/acceptance.md)。
