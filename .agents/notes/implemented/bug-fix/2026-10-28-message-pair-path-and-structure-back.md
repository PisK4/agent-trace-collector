# Agent Note: 消息配对按结果路径确认，返回列表退出步骤选择

Status: implemented

## Problem

中栏改为按承载请求的 delta 分组后，点击轨迹行一律打开读数页，消息详情里的「配对两端」按钮成为进入工具页的主要入口。该按钮原先只按 `call_id` 查反向索引：旧 Responses 骨架按 `messages` 拆块、索引却记在 `input` 时，同 `call_id` 的结果会被挂到另一条消息的块上；消息位置未知时按钮同样出现，点开的是与当前块无关的调用。合并后新增的「返回消息列表」也失效：选中步骤会把结构折叠钉在消息详情上，按钮只清结构选择，点了没有可见变化。

同一轮核查发现两处跨请求依赖的拼接：右栏不随当前请求的已确认前驱换版重绘，消息详情的调用块配对仍用旧前驱的调用表；保留投影的结果行回退到依赖缓存取调用方摘要，会把依赖换版后的新调用名字与参数配到旧结果上。

## Decision

[body-model.js](../../../../web/body-model.js) 的 `messagePairIndexOf` 增加块路径参数：结果块除 `call_id` 外还要求块路径等于记录的 `result_path`，路径未知或不同就不给入口；调用块仍按前驱调用表的 `call_id` 匹配，前驱不在窗口或未读到同样不给。[body-view.js](../../../../web/body-view.js) 按正文骨架拼出块路径，Chat 的 `role=tool` 结果与后端同口径配到整条消息。

[app.js](../../../../web/app.js) 的 `affectsRail` 把当前请求的已确认前驱纳入影响面，前驱换版后重绘右栏；保留投影的结果行不再回退依赖缓存，降级为只显示工具名。「返回消息列表」在清结构选择之外，若当前步骤解析为请求侧消息就发出 `clear-step` 并重绘中栏，高亮与折叠一起退出。

## Alternatives considered

**只保留 `call_id`，配对页自己校验路径。** 按钮已经承诺了一个坐标，点开后再发现位置不符会把错误暴露在下一步；在入口处按同一份持久证据判定更直接。

**返回列表时只改结构折叠的局部状态。** 折叠的选中同时来自步骤选择与结构选择两个来源，只清一个来源按钮就没有效果；退出步骤选择与「返回列表」的语义一致。

**前驱变化时整页重绘。** 中栏已在每次快照变化时重绘，右栏只需要在前驱参与其内容时跟上；扩大重绘范围会让无关批次也重建右栏。

## Consequences

消息详情里的配对入口以「`call_id` 与原始路径都确认」为准，旧骨架混合键不再产生跨路径按钮，代价是位置未知时少一个入口。保留投影期间结果行可能只剩工具名，不再借用新依赖的摘要。前驱换版会多一次右栏重绘，不影响中栏提交。返回列表会同时取消步骤高亮。

## Testing

`tests/body-view.test.ts` 覆盖路径一致、路径未知、`input` 与 `messages` 混合键、同 `call_id` 落在另一条消息四种情况；合并后的前端窄测（body-view、trace-view、web、trace-pair、trace-commit、selection、trace-preparation、reader-store）177 项通过，`bun run typecheck` 通过。浏览器用 `prototypes/synthetic-server.ts` 复测：工具结果行打开读数页，消息详情显示 `messages[4]` 并给出指向调用方的配对按钮，点按钮进入工具页；「返回消息列表」回到 40 条列表与「加载更早（已读 5–45 / 45）」，步骤高亮消失。真实流量验收未执行。
