# Agent Note: 后台写入先准备意图并按任务归属计时

Status: implemented

## Problem

后台轮询在知道有无修改之前打开写事务。空队列派生、没有候选的 pending、稳定缺口和探针，以及费用请求之前的窗口重置，都占用 writer；累计耗时又没有归属，无法用观测验证哪些轮询已被消除。

## Decision

存储层提供同步的只读准备与具名提交，接口和任务批次见[进程模型](../../../../docs/architecture-design.md#系统边界与进程模型)。任务在持有写事务前决定是否需要修改，真实写操作保留在同一个同步事务内。写入统计来自 writer 包装层，指标仅保存在进程内。

本记录补充[进程内容量观测](../feature/2026-10-22-atc-capacity-metrics.md)的归属信息，并与[派生工作单元](2026-10-24-budgeted-derive-unit.md)分工；它不改变[保留与缺口策略](2026-10-20-retention-three-gates.md)的保留边界或恢复条件。这些决策仍有独立依据，均保留活跃。

## Alternatives considered

**把全部 tick 合成一个大事务。** probe 和 cost 包含网络 await，不能留在同步事务里；合并还会把独立任务的失败与延迟传播给其他任务。

**每轮照常提交，只增加任务名。** 能找出开销来源，但空转占用仍然存在，无法减少稳态事务数。

**泛化成异步写入队列和自动拆分器。** 当前 writer 同步执行，任务最小原子单位各不相同；通用队列既无法中断 SQL，也无法猜测哪些证据能分开提交。批次上限由拥有该语义的模块决定。

## Consequences

空闲和稳定状态不再产生写事务，按名计数可直接证明这一点。探针 `at`、pending `last_tried` 和未关联 hook issue 的时间表示内容或状态被首次确认、变化的时点，不充当每轮轮询心跳；任务计数和进程时间仍由容量指标给出。

费用页在成功校验后才提交窗口进度，费用冲突仍整页回滚，并单独提交冲突健康记录。进程在请求前退出时，无须恢复一个仅为了开始扫描而写入的窗口状态。

批次限制减少单次工作量，不能保证一笔任意大小的正文处理有严格时间上限；派生大组的限制仍见工作单元记录。

## Testing

[提交回归](../../../../tests/commit-unit.test.ts)验证重复空闲轮询零事务、稳定缺口和未关联正文不重复写、费用失败前进度不变，以及指标快照的具名计数稳定。[存储回归](../../../../tests/store.test.ts)验证具名成功、回滚和空意图。

[隔离性能实验](../../../../scripts/perf-work-units.ts)使用容量工具的临时根和独立采集器进程，测量稳态事务增量以及派生积压期间的 hook 投递；不读写真实采集器数据目录。
