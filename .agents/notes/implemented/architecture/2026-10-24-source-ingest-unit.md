# Agent Note: 来源摄入收成一个入口，文件形态交给两个适配器

Status: implemented

## Problem

路由文件的一批读取结果分三次写库：坏行记账、路由证据、游标推进各开一个事务。中途失败时三者可能停在不同的提交点上，排查时要分别判断哪一步已经落库。游标写入另有两份手写 SQL，列数不同。同代际与重写计数的单调保护只写在账本那份，路由游标是裸赋值。读取侧还有两种游标类型，`fileCursorOf` 与 `routeCursorOf` 只负责在两种形状之间搬运字段。

账本与路由的记录语义本来就不同：账本按物理身份区分同一路由下的多条计费行，路由按 `route_id` upsert 去重。把两种记录语义塞进同一个处理器会让它按来源种类分叉，合并抵不上这两处差异带来的复杂度。

## Decision

读取结果直接携带完整游标，在线账本与路由共用摄入入口，避免调用方搬运字段时遗漏身份或指纹。追加 jsonl 与封口 gz 的适配器只处理坏行引用基址的差异；账本与路由仍分别处理记录身份。接口、游标保护与具名提交见[增量读取协议](../../../../docs/architecture-design.md#增量读取协议)。

坏行、证据与游标同事务，失败只有一个提交边界。全量游标 upsert 共用一处，账本与路由的偏移保护随同一个实现维护。在线账本显式固定库内来源身份，避免配置改文件名时把游标和暂停缺口拆成两份。

坏行随事务回滚不丢信息：游标没有前进，下一轮仍从原位置重读同一批内容，坏行会被重新记一次。证据写入按物理身份或 `route_id` 幂等，重放不产生重复。这条推理是允许坏行与证据同事务的前提，不依赖任何补偿日志。

只有 `state = decoded` 的读取结果能进 `ingestSource`，其余状态直接抛错。读取失败的来源根本没有游标可写，未变来源由读取器返回 `unchanged`。

在线调度直接调用 `ingestSource`，没有调用方的 `ingestDecodedRouteFile` 包装随之删除。`ingestLedger` 和 `ingestRoute` 为现有测试保留：前者接收测试构造的账本批次，后者接收没有文件坐标的记录列表，两者复用摄入内核，不复制事务内规则。

不做 schema 变更，不引依赖。`source_cursor` 现有列同时容纳两种文件形态，封口 gz 的偏移字段只记解压后长度，不参与定位。

## Alternatives considered

**只补路由游标的单调保护，保留三段事务。** 这能修掉游标倒退，却把两份游标 SQL 与三段失败语义留在原地。坏行、证据、游标的提交点仍然分散，下一次改游标列还要同时改两处。

**让两种文件继续使用各自的游标类型，只在写库前转换。** 转换函数正是调用方需要记住的隐含契约：谁忘了传 fingerprint，gz 就会被当成可追加文件。统一形状后，读取结果本身就能回传，类型检查替调用方记住这件事。

**把账本与路由记录处理合成一个处理器，用来源种类分支。** 两条身份规则不同，合并后处理器内部仍要按来源种类分叉，只是把分叉从入口挪到了更深处。记录级内核分开、事务与游标共用，复杂度落在有差异的地方。

**为统一形状新增列或新建游标表。** 现有列已经覆盖两种形态，新增列只会制造第二套字段口径，还要处理旧库重建。首版前没有兼容包袱，但也不为已经不缺的表达力付 schema 成本。

## Consequences

- 路由批次从三个写事务降为一个。账本原本就是一个事务，现在与路由共用游标写入与缺口关闭的外壳。
- 任意来源的摄入失败都会同时回滚坏行、证据与游标，不再出现只落了一部分的状态。
- 路由游标获得与账本相同的同代不倒退保护；换代或重写计数变化后允许归零重读。
- `SourceRead` 为两种形态携带暂时不用的字段：可追加文件的 `fingerprint` 为 null，封口 gz 的头部基线为 0 与 null。字段为空表示不适用，不再靠类型区分。
- 只读到半行时，在线调度比较已保存的观察位置；重复轮询不再为相同位置提交事务。单独观察位更新也使用 MAX，防止较旧观察值拉回偏移。
- 行为保持不变：半行等待下一轮、原地重写与截断换代重读、重复证据幂等、gz 整份指纹跳过、读取错误不推进游标、暂停缺口仍按原区间关闭。

## Testing

`bun test tests/files.test.ts tests/reconcile.test.ts` 覆盖：读写结果直接回传的单一 seam、半行与换代重读、jsonl 与 gz 同形状但身份字段不同、路由批次只开一个写事务、事务失败后坏行与证据与游标全部回滚且下轮重读成功、游标同代不倒退与换代归零、未变与读取失败不进入摄入。

`bun test tests/hook.test.ts tests/magpie.test.ts` 覆盖保留的 `ingestLedger` 入口仍接受测试批次。`tests/main.test.ts` 用合成文件启动采集器，验证自定义账本路径仍写固定来源身份、两路在线摄入均按名计数，以及稳定半行轮询不增加写事务。`bun run typecheck` 检查全部调用方。
