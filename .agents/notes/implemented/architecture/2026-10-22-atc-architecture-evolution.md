# Agent Note: 以事实重建统筹 ATC 架构演进

Status: implemented

## Problem

ATC 要承载更多机器调用，也要集中处理不同 Agent 的请求语义。[类别注册表提案](../../proposed/architecture/2026-10-22-agent-request-kind-registry.md)与[字段保真提案](../../proposed/architecture/2026-10-22-magpie-parity-and-field-fidelity.md)各覆盖一类缺口，但分别实施会重复触碰版本、回填、正文解释和查询。mapper 修复不能修正全部请求写入路径，会话派生也不能重建来源字段；[联合评审](../../../../docs/agent-request-kind-review.md#与字段保真方案的联合评估)给出了源码依据。

扩展机制与容量同样需要分开判断。把规则挪进注册表能改善修改位置，却没有减少长会话祖先比较或历史文件解压。如果把所有工作都称为 Feature 插件化，后续容易把身份、协议、后台调度与页面交互一起放进 Agent Profile，增加调用者需要理解的 Interface。

## Decision

这一轮按[架构演进方案 v2](../../../../docs/architecture-evolution-v2.md)组织：以事实重建、请求语义和有界执行划分职责，把变更落在三个加深的 Module 上——来源字段与投影规则、Agent 专有解释、派生调度及恢复。在线摄入与离线重建共享事实规则；请求级解释与等待归属确认的会话派生分清触发时机。

判据是减少"一次正确修改需要同步理解的位置"：源码中的字段知识、Agent 语义和重算成本各有其主，调用者通过小 Interface 拿到完整行为。模块拆分必须改善 Depth、Locality 或 Leverage，不以文件数作为完成条件。

请求用途的待处理状态放在请求行上，分组队列保留会话依赖：actor 未定不妨碍判用途，直接关联成功后的补正文也需要可靠触发，写入完成后的内存通知不能替代事务内的持久标记。输入解释与技能清单按正文读取执行，不因统一语义规则而变成必须全库执行的后台任务。落地的形状见[请求用途与链](2026-10-22-request-purpose-and-chain.md)、[组发布前处理请求](2026-10-22-request-work-before-group-publish.md)与[服务端输入解释](../feature/2026-10-22-server-side-input-interpretation.md)。

来源投影同时持有投影规则与 owner 证据的收集和完整性判断，调用方只传已关联的身份和事务上下文；只提取字段计算会把关键知识散回多个入口。来源 kind 冲突保守保留，不用最后到达者隐式裁决；raw 过期后的部分重放不缩小长期合计，旧占位符也不被重复脱敏改变。形状见[来源投影与字段保真](2026-10-22-source-projection-and-field-fidelity.md)与[有界来源事实](2026-10-22-bounded-source-facts-and-provenance.md)。

稳定占位符依赖原盐，可恢复采集的备份因此保留匹配盐与绑定信息；仅恢复数据库后静默生成新盐会破坏跨记录关联，认证 token 独立处理。拒绝统计采用固定原因的有界观测，拒绝分支不写库，也不借此扩大并发或缓存正文。

正确性回归与容量基线分开推进：字段修复在对应反例固定后实施，完整负载入口不作为它的前置；来源版本、请求修订与保留状态在其结构变更前确定。计算代际随切片一起交付，切片迁移前冻结存储与查询契约，同步执行阶段不承担尚无测量依据的暂存成本。

步骤、次序与每项验收的家是[架构演进实施入口](../../../../docs/superpowers/plans/2026-10-22-atc-evolution-implementation.md)，本 note 不复制它们。完整重建先区分证据缺失与真实空输入、稳定身份与顺序依据，才为后续语义和性能改造提供可信对照；代码验证与历史对齐分别报告，不把保留旧值说成新规则确认。

magpie 补充调研围绕未决问题展开，优先借鉴缺失语义、来源归并、尝试解释和缓存失效，每项研究说明 ATC 中的实际消费者与代价。配置管理和网关执行不属于旁路记录器；direct、正文全文搜索和专有指纹保持独立决策。

## 与现有决策的关系

统筹范围里的两份提案仍保持 proposed：已交付的部分由各自批次的 implemented note 持有，未建的批次留在提案里作为待办，不互相改写。本轮交付扩展了[schema 显式回填](../../archived/architecture/2026-10-20-schema-v3-rejects-in-place-upgrade.md)、[容量三门槛](2026-10-20-retention-three-gates.md)、[隐私与本地访问边界](2026-10-20-privacy-and-local-access-boundary.md)、[任意祖先前驱](2026-10-20-semantic-fingerprint-and-ancestor-predecessor.md)、[标题与主链](../feature/2026-10-21-title-generator-and-main-chain.md)与[不可读请求保持中性](../bug-fix/2026-10-21-unreadable-requests-stay-neutral.md)，没有反转其中任何一项。schema 显式回填一篇后随破坏式替换作废并归档，见[旧库删除重建](2026-10-23-destructive-schema-replacement.md)；其余各篇仍在活跃区。

## Alternatives considered

**按原来的两篇提案分别实施。** 字段保真与类别规则有各自价值，但它们在版本、长期证据和回填处重叠；分别推进而缺少统筹，会留下修 mapper 却没修投影、升结构却没完成重建的空隙。

**继续扩展 RequestKind，容纳所有 Agent Feature。** 用途、输入包装和技能声明可以同时出现，互斥匹配会遮蔽结果；身份、协议和调度的变化原因也不相同。保留三个独立语义操作更接近实际数据。

**先完整对标 magpie，再决定 ATC 架构。** 已有源码研究足以支持已确认的修正。无问题约束的继续调研会把配置写入与网关能力带入范围，推迟可验证的改进；补充研究按阶段问题进行。

**一次替换全部目录与数据模型。** 更难区分字段纠错、语义改变和性能优化，也放大已有正文的迁移风险。分阶段穿过相同 Seam 验证，可以保留恢复入口和差异定位能力。

**仅增加写入完成回调，或让请求用途共用 actor 分组队列。** 前者在崩溃后没有工作依据，后者不能覆盖未知归属。请求行待处理状态与现有分组队列分别管理实际依赖，共用 writer 和调度入口即可。

**链算完即删队列，调用方随后重配工具。** 两步之间退出时没有恢复触发，合成库已经复现。同事务集中执行还必须统一逻辑顺序，并让依赖工具的摘要消费本次关联；单纯合并事务仍会保留排序差异与上一轮摘要依赖，反例见[补充评审](../../../../docs/agent-request-kind-review.md#派生排序与摘要依赖)。

**切片时原地覆盖派生值，只在查询侧屏蔽半成品。** 计算完成前若正文回收，已被覆盖的上一份标题或工具关系无法恢复。跨事务切片需保留已发布结果，将本次派生写入独立代际并短事务发布；不复制正文与请求事实。分批产物、WAL 与清理都需有预算。

## Consequences

- 三个 Module 各自持有规则、在线与离线共享同一份实现，因此字段修复、语义变更与性能优化可以分别交付和分别验收，不必同步理解全部位置。
- 长期解释结果只保留必需的短依据与有消费者的事实；`request` 与 `route_summary` 不参与正文回收，每一列都是永久成本。
- 代际结构只在切片模式需要时才承担暂存空间与清理工作。**实测结果是否定的**：10,000 笔单链的切片排空 878.7 s，同输入同步只需 1.96 s，超过提案的 120 s 上限，触发条件不成立。切片模式不启用，采集器继续走同步派生，5 rps 的产品目标保持未达成，见[容量决策](../feature/2026-10-22-atc-capacity-decision.md)与[运维手册的切片一节](../../../../docs/operations.md#派生切片与代际)。
- 后台切片若缺少失效检查会发布过期链结果，热组持续失效则长期无法发布；增量优化必须与完整重建比较，不能删除任意祖先候选换取速度。
- 容量基线在固定环境建立，不从设计图或注册表规模推导吞吐，也不假设引入 worker 就会改善单 writer 的工作量。基线与门槛归[架构演进实施入口](../../../../docs/superpowers/plans/2026-10-22-atc-evolution-implementation.md)的验收记录。
