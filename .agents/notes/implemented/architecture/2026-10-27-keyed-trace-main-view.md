# Agent Note: 中栏键控提交与视口锚点

Status: implemented

## Problem

中栏此前每次重绘都整体替换 `main.innerHTML`：同一条步骤即使可见内容没变，节点、焦点与浏览器文字选择也一起消失；选择变化、右栏补读、自动重读换新都走同一条整栏重建路径。位置补偿是另一套手接的快照：加载更早时提交前记锚点，提交后按滚动容器校正；`userScrolled` 一旦置位，本会话内所有补读都不再补偿。两套机制各自维护「什么算读者位置」，锚点规则散在调用方。

要让渲染输入没变就不动 DOM、让选择只改高亮、让补读与 prepend 不改写阅读位置，需要一层提交视图：按键复用节点，比较可见结果，自己维护唯一的视口锚点。

## Decision

新模块 [trace-dom.js](../../../../web/trace-dom.js) 提供 `createMainView(main)`。骨架固定为会话头、可选轮次带与步骤列表三段，常驻不重建；骨架被外部替换（例如换会话时的整栏提示）时下一次提交自建。请求组按 `group:<req_id>`、步骤行按稳定步骤键复用。组容器的可见结果为空串——容器换掉会连子节点、焦点与文字选择一起丢，行级比较在容器内部做。

比较只走 [planCommit](../../../../web/trace-commit.js)。一次 `inspect` 返回三种结果：全等则整次跳过；只有选择不同则只写 `aria-current`，不读布局、不换节点；其余走结构提交。判据是完整计划与键序，不用数量近似。

结构提交前 `captureAnchor` 记录锚点：优先选中组内的首条可见稳定步骤；选中组整体在视口内但还没有步骤（读取中的空组）时以组本身为锚；否则取全列表首条可见稳定步骤。提交后用同一节点的新视口偏移就地校正滚动，差小于 0.5px 不动；锚点节点被真实删除时不猜替代位置。桌面中栏是独立滚动容器，窄屏改由文档滚动，两种容器都从 `scroller()` 取。原生滚动锚定在 CSS 里关闭（`.col-main` 与根元素 `overflow-anchor:none`），补偿只有一处，避免两套机制在同一处位置变化上各移一次。

`commit` 的 `preferredReq` 只在首载未定位完成时传入，作用是把选中组钉在原地，不负责居中；用户滚走后选中组不在视口，锚点自然落回正在阅读的步骤。`userScrolled` 与会话级闩锁因此删除，`anchorSnapshot`/`compensateAnchor` 一并删除，加载更早只负责重绘，位置由提交自带。

选择不进入行 HTML：`renderTraceRow` 默认 `selected = false`，提交后由视图写回 `aria-current`。点选同一组的另一行不会替换任何节点。

## Alternatives considered

**仍整体替换 innerHTML，提交后恢复 scrollTop。** 保不住节点身份、焦点与文字选择；也只回答「整栏变没变」，回答不了「哪一行变了」，与本决策的目的相反。

**用 requestAnimationFrame 延后恢复锚点。** 中间隔一帧，补读与头部高度变化会先被看见再被校正；同一个任务里同步读写布局更稳，也不需要和用户输入抢时序。

**保留 `userScrolled` 闩锁。** 它是会话级状态，用户滚过一次就永久停止补偿，之后 prepend 与补读造成的位移没有兜底。锚点按「当前视口里第一条可见步骤」选择，本身就能区分「在读选中组」与「在读别处」，不需要闩锁。

**把位置稳定交给浏览器原生滚动锚定。** 浏览器的锚点选择不可测、不可解释，且会与手动补偿叠加；页面需要单一、可被合成验收覆盖的补偿点。

## Consequences

收益：可见结果不变的重绘不碰 DOM；点选只更新高亮；补读、轮次带出现、会话头高度变化与 prepend 都不改写阅读位置；位置规则收敛到提交层一处。

代价：每次提交都要生成完整模型 HTML 做比较，生成成本与旧路径相同，省下的是 DOM 操作；比较要求渲染输出稳定（属性顺序与空白确定），这是既有字符串模板本来就有的性质。加载更早会重新编号，所有行都算替换，节点身份按稳定步骤键在新编号下重建，位置靠锚点恢复。读取中的占位步骤被真实内容替换时，锚点节点可能恰好消失；占位组改以组本身为锚，见[中栏窗口读取的准备流水线](2026-10-27-trace-window-preparation.md)。
