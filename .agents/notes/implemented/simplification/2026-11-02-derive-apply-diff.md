# Agent Note: 展示列只写实际变化，derive_version 记内容变化次数

Status: implemented

## Problem

派生落库把整组计划原样写回。热组 3,019 笔的实测里，一次落库约一万条语句，真正改变的结果只有几十行：展示列计划 3,003 行、实际变化 11 行；链行 2,991 条、字段变化 8 个；链角色 1,881 行、变化 2 行；工具行计划插入 1,397 条、实际新增调用 9 条。落库单次最长 2,060 ms，同步阻塞 Bun 事件循环，页面在此期间无法响应。

`derive_version` 也跟着每次写入加一。它被文档写成"被重算过几次"，代码却在每一行展示写入时自增，包括内容完全没变的行。跳过无变化行会改变这个计数，所以口径必须先定下来。

## Decision

展示段先比较再写。`presentationWrite()` 额外读回当前行的 `summary_algorithm`、`summary_basis`、`summary_state`，把八个展示列与摘要三列一起与计划值比较，结果写进 `changed`；`writePresentationTx()` 在 `changed=false` 时直接返回。

同一事务、同一 CAS、同一计划，最终状态与改动前逐列等价。CAS 仍按 `group_epoch`、`input_revision`、`target_algorithm` 判，未变化行不写不改变组的发布语义。

`derive_version` 随之定义为内容实际变化的次数：重算但结果没变不加一，重算后内容变了加一。它依旧不是算法版本，也不表示结果是否最新。三处文档同步改口径：[trace 格式](../../../../docs/trace-format.md#版本字段)、[架构设计的派生算法版本](../../../../docs/architecture-design.md#派生算法版本)、[运维手册的重建报告](../../../../docs/operations.md#rebuild)。

维护 `rebuild` 仍报会话 `MAX(derive_version)`，语义变成"该会话单行最多变过几次"。既有生产库的历史值按旧口径累加，不回填：它是历史计数，没有需要修正的派生结果，回填只会改写历史。

## Alternatives considered

**保留旧计数，无变化行也加一。** 那就必须继续写整组，瘦身等于没做；或者对未变化行单独写一条只涨版本的 UPDATE，省下的语句又加回去。

**把 `derive_version` 改成算法版本号或批量加一。** 那会让"这一行变过几次"这条信息消失，且与 `summary_algorithm` 重复。算法覆盖已经由 `summary_algorithm`、`actual_algorithms` 与 `legacy_requests` 回答。

**同一提交里把链、角色、工具三段也改成差分写。** 三段各有自己的删除与重建语义：工具行整组先删后插，改差分要处理保留行、正文不可用行与配对重建。先把展示段做成可验证的一片，其余三段另起。

**把落库拆成多条短事务以缩短单次阻塞。** 会破坏组内原子性，中途失败会留下半组。整组一次提交是本仓的一致性底线。

## Consequences

- 生产热组一次整组重算的展示段只写 2–6 行，3,200 行上下全部跳过；落库计划语句从 11,444–11,704 条降到 8,245–8,445 条（2026-11-02 只读实测，见[验收记录](../../../../docs/acceptance.md#展示列差分落库生产部署真实流量2026-11-02)）。
- 最终数据与改动前等价；未变化行连 `updated_at` 都不动。
- 每行多一次读回摘要三列，已在原有单行查询里带上，不新增查询次数。
- `derive_version` 增长变慢：热组 357 秒内只有 7 行增长，旧值（最大 1,891）停在原地；按它做诊断的读者会看到新旧口径混合的数据。
- 链、角色、工具三段仍整组重写，是剩余 8,245–8,445 条语句的主体；热组落库上限不会降到接近 0。

## Testing

`tests/derive-presentation.test.ts` 的「重算不改变内容时 derive_version 不增长」：先排空一次，再排空一次断言版本与内容不变；随后只改第二笔回复正文，断言只有该行版本加一。既有展示、链、单元与维护测试全部通过，`bun run typecheck` 通过。真实流量上的语句数与版本计数见[验收记录](../../../../docs/acceptance.md#展示列差分落库生产部署真实流量2026-11-02)。
