# Agent Note: 配对页与工具页正常态静默

Status: implemented

## Problem

工具配对页每次都在面板之间挂固定说明：状态行「关联 已确认配对 · 正文加载 已读取 · 结果承载 N」、调用面板尾注「调用参数按原文保存…不代表工具执行成功」、每个结果正文后的 is_error 标签——连上游明确标 `is_error=false` 的正常态也挂。工具概览页另有四句常挂尾注，工具列表标题带交互说明，「本次回复」折叠行在正文未读取的正常态挂「正文未读取」标签。这些是[前端降噪原则](../process/2026-10-24-frontend-denoise-standing-rule.md)点名的正常态装饰；状态行的「结果承载」还与结果面板自带身份行逐字重复。此外状态行用的 `.detail-label` class 从未有样式定义，一直以裸 div 渲染。

## Decision

- 配对页状态行只在异常时渲染：关联未确认、正文读取失败或位置无效才出现；「结果承载」段删除，结果面板的 bp-meta（请求与 messages 路径）是它的唯一家。正常态（已配对且正文已读或待读取）整行不出现。
- is_error 展示三态分流：`true` 保留失败标签（面板已整块 warn 软色）；`null` 保留「未报告 ≠ 成功」的缺失口径说明；`false` 静默——上游明确未标错是正常态，静默本身即与未报告区分。三态语义（resolved 不当成功）不变，[工具结果按调用位置读取](../feature/2026-10-24-reading-identity-tool-results.md)的口径照旧。
- 调用面板尾注删除；「配对已确认只说明关联成立」由 is_error 行承担。
- 工具概览页尾注只留时长归属口径（模型响应时长归属承载它的请求；工具执行时长未采集）。
- 工具列表标题只留次数；「本次回复」折叠行只在正文状态异常（未到/不完整/回收/不支持）时挂状态词。
- 状态行 class 改用既有 `bp-meta`；Schema 页同名多定义的「来源」小标改用 `.label`。

## Alternatives considered

**保留 is_error=false 的标签（原测试锁定此行为）。** 三态分行是为「resolved 不写成成功」服务的，但 false 是上游明确给出的正常态，常驻标签违反降噪原则；静默与标签的对照仍可区分三态，语义无损。测试随本变更改锁新行为。
**「结果承载」保留在状态行。** 结果面板身份行已有同一事实，双处展示必有一处是装饰。
**保留「打开配对页自动读取一次」类行为说明。** 读取动作自动发生，结果面板的待读取文案与读取按钮已说明状态。

## Consequences

正常配对页从面板头直达正文，无中间说明层；异常路径的说明反而更聚焦。已知代价：is_error=false 从「读到一行文字」变为「没有标签」，依赖显式文字确认正常态的读者需要知道静默即正常。验证（2026-10-25）：`bun test tests/trace-pair.test.ts tests/web.test.ts`、`bun run typecheck` 通过。
