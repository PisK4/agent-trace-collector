# Agent Note: 中栏间距、历史提示与右栏读数修正

Status: implemented

## Problem

本篇只覆盖阅读界面的显示与入口，不修改采集、派生和存储。四个缺陷共享同一类根因：布局与边界重复表达同一件事，或者让入口态覆盖用户的阅读位置；它们都不影响账本数据的正确性，也都不会被测试捕获。

**中栏序号占了过宽的槽位。** 生产样式的 `.compact-meta` 宽 86px（1300px 断点 76px、620px 断点 22px），步骤渲染只放请求序号；1507px 视口下序号文本只占约 10px，标签起点 x=374、预览起点 x=445。序号位数不能按首次加载上限推断：`loadEarlier` 会累计追加历史，`windowLimit()` 的 100 只限制初始加载，序号按当前全部已载入请求编号。

**历史区常驻的起点提示多余。** `traceHtml()` 在 `olderCursor === null` 且存在请求时显示「已到会话起点」，而 `.history-loader` 自带分隔线与上下内距，顺序说明也常驻；边界由结构承担之后，这句文字不增加信息。

**用量排版和计时标签难以对照。** 计时与用量各排成一行，用 `·` 分隔平铺；640px 右栏内两行各高 20px，构成图例六类共高 113px，折叠区总高 284px。窄栏折行后标签与数字不易对照，图例又列出四个零值类别。`ttft_ms` 与 `first_text_ms` 数值接近或相等时，读者无法判断「首字」与「首个文本」是两个事实还是一种说法。上游 magpie 检出 `2374ffe1` 的 `usage.Record` 分别定义这两个结束事件，上报校验禁止首个文本早于首个内容：共享请求起点，测量事件不同。

**显式 URL 页签被会话选择覆盖。** 初始化和 `popstate` 都解析 `tab`，随后 `selectSession()` 无条件重置为 `facts`；`updateURL()` 按重置后的状态写回地址，丢掉显式声明。路由页还有读取前提：`railBody()` 只取路由缓存，现有 `ensureRoute()` 由页签点击触发，直接保留页签无法让 URL 直达、切会话后的路由内容自动就绪。

## Decision

### 一、序号槽：基准 28px，按窗口最大位数扩展

`.compact-meta` 的宽度规则统一为 `max(28px, 位数 × 1ch + 8px)`，三个断点不再各设固定宽度（1300px 断点保留 8px 字号）。位数由步骤列表按当前 `rows.length` 写进 `--ord-digits`，`1ch` 在序号槽自己的等宽字号上取值，断点字号变化随计算生效；整个当前窗口共用一个宽度，不按每行的数字单独撑宽，标签起点不参差。加载历史后随 `rows.length` 重算，不截断序号，也不限制历史加载数量。`title` 保留「请求 N」语义与现有步骤按钮。本项部分调整[中栏只呈现内容](2026-10-24-trace-content-only-and-wide-rail.md)的布局；36px 行高与不显示附加计量的决定继续保留。

### 二、历史区只留入口、反馈与顺序说明

`traceHtml()` 删除读尽终态文字的分支：读取中显示反馈，有更早记录显示按钮，读尽后只剩常驻的顺序说明；空会话走原有空态。游标与错误处理不变。

### 三、读数两列，首 token 与首个文本分立

计时与用量各用一个 `<dl class="chain">`（`.ledger-chain`），内部复用 `.chain-row` 的标签和值结构；数值列右对齐、等宽数字（11px mono、tabular-nums、行距 1.5、行内距 3px），样式只作用于读数范围，不改全局 `.chain-row dd` 的文字详情排版。`·` 分隔符与旧 `.strip-row` 样式删除（确认无其他使用者）；`.miss` 缺值标记同时覆盖 `.ledger-chain` 与 `.u-total`。

计时行按值展示：首 token（title 说明 TTFT 是到第一个内容，可能是文本、推理或工具调用）、总、速度（`输出 token ÷（总 − 首 token）`）、首个文本；合法的 0 不按缺失处理。用量任一基础字段有值时四个槽全保留，缺值「—」，全缺不渲染该组；命中与费用仍按可计算性出现。速度分母沿用「总 − 首 token」及其 `flow_ms` 回退；`fold-count` 的总/出/命中摘要不变。

构成条与图例共用 `tokens > 0` 的可见类别，图例按 token 数降序；没有正值类别时不留空的条和图例容器，总量、窗口、占用与估计说明保留。零值不能解释为没有该类内容——上游 `Prompt.calibrate` 按总量缩放后已估计类别也可能为 0；零值与缺失类别在图例中均不可见，这是本篇接受的展示取舍。

读数输出集中在模块级纯函数 `ledgerParts()`/`ledgerRowsHtml()`/`usageFoldHtml()` 并导出回归；`usageFoldHtml()` 的详情由调用方显式传入。窗口外请求显式传 `ledgerRowsHtml(read.detail, read.detail)`，避免漏掉详情中的 `first_text_ms`。用量折叠键仍是 `prompt:<req>`。本项部分调整[用量折叠](2026-10-24-usage-ledger-fold.md)的读数排版，其折叠位置、头部收敛与缺陷修复的决定不变。

### 四、页签声明保留，路由随导航读取

URL 的 `tab` 参数经 `railTabFromParam()` 解析（合法内容页签原样采用，无效或缺省回 `facts`），`updateURL()` 经 `railTabParam()` 只写回显式内容页签；`selectSession()` 不再覆盖已确定的页签，切会话仍清除请求内的步骤与工具选择。读取条件由 `routeReadTarget()`（页签为路由且请求已定）表达，导航完成处——`selectSession`、`refreshWindow`、`locateRequest` 与页签点击——共用；渲染函数不发起读取，无当前请求、窗口外或不存在的 trace 不预取。`routeBlock()` 的空路由说明改为「尚未读到：正在读取或上次读取失败；再次进入页签可重试」，不冒充无路由。

步骤点击的来源解析不变：调用与已配对结果进[配对页](../feature/2026-10-24-trace-pair-rail-page.md)，request/reply 来源进正文，无来源记录与辅助请求进读数，增量事件行续读——[角色与选择一致性](../bug-fix/2026-10-24-reader-role-and-selection-consistency.md)的导航规则继续有效。无声明时的读数默认与无来源 Event/Aux 的读数入口维持现状。

## Alternatives considered

**按 100ms 合并首 token 与首个文本。** 时间接近不能证明事件相同，两位小数秒也能显示 60ms 差异；分别命名并保留有值字段，没有阈值分支和悬停才能读到的指标。落选。

**固定 28px，并假定最多 100 笔。** 初始加载上限不约束累计历史；统一最小宽度加窗口级位数扩展，既缩短常见序号槽，也保留长会话完整编号。落选。

**只复用 `.chain-row`，不加局部样式。** 现有值列左对齐并允许任意位置折行，达不到数字右对齐；全局修改会波及路由等文字详情。落选。

**继续用平铺数字或改成 pill 加弹层。** 平铺在窄栏会散开，弹层增加读取操作。落选。

**删除 `selectSession()` 的赋值就完成 URL 修复。** 保住页签名却不能触发路由读取；导航需要同时确定显示目标和取得数据。落选。

**所有 `record` 保留当前页签或都进正文。** `record` 既有协议来源的未知回复块，也有无来源状态记录，类型标签不足以决定阅读目标。落选。

**保留起点文案和全部零值图例。** 信息更完整但持续占用空间；加载反馈、数据总量及异常说明继续保留。落选。

## Testing

`bun run typecheck` 通过；`tests/web.test.ts` 新增计时缺值（相等/60ms/仅一项/0/全缺）、用量缺值与全缺、图例正值过滤、URL 页签解析与写回往返、路由读取目标谓词的回归；`tests/reader-store.test.ts` 新增翻页 clamp 回归（见[加载更早按服务端上限收窄](../bug-fix/2026-10-24-load-earlier-server-limit.md)）；`tests/trace-view.test.ts` 既有来源解析回归通过；`git diff --check` 干净。

合成浏览器验收（临时实例，150 笔可用正文 + 1024 笔已回收正文两个会话）：

- 1507px 视口：序号槽 28px、行高 36px，序号 1/99/150 的标签起点同为 x=316（原 x=374，前移 58px），预览起点 x=387（原 445）；读尽历史后序号槽仍 28px、起点一致、无裁剪，历史区只剩顺序说明。
- 1024 行窗口（4 位数）：槽宽 29.7px（4ch+8），序号 1/99/100/999/1000/1024 无裁剪，标签起点同为 x=317.7；无横向溢出。1300/1241/620/400px 视口同样 28px 槽、36px 行、无溢出（620/400 为堆叠布局）。
- 右栏 640px：计时组 93px（4 行）、用量组 140px（6 行），数值右缘差 0；280px：折叠区 446px、逐行仍单行 16.5px、右缘差 0。折叠区总高 429px（640）/446px（280），高于旧平铺的 284px。样本值逐项核对（0.42 s/71 tok/s/0.48 s/9,000/51%/$0.0034）；相等计时（7.64s×2）分立成行；零费用 $0、缺缓存槽「—」、无用量只剩计时组；窗口外请求读数含首个文本。
- 页签：`?tab=route/body/tools` 在自动选会话与带 session/trace 入口都保留，URL 写回后刷新一致；无效页签回读数且 URL 不落参；切会话与路由页签上的窗口刷新都保留页签并自动读取路由（无路由请求显示 absent 说明）；hero 请求的路由内容（去向/状态）正常渲染。

## Consequences

序号槽让出约 58px 给预览，长会话的位数扩展自动生效；常驻信息少一句起点文字、少四个零值图例类别。代价有两处：两列读数把折叠区从 284px 增高到 429–446px（两个宽度下逐行单行、数字完整，接受这次增高换纵向对照）；读者无法从图例区分零值与未覆盖类别，总量不能恢复这层信息。页签保留只覆盖页签偏好，不承诺跨请求的正文定位、工具四页或滚动位置；没有工具或路由的请求仍给出对应空态，不自动跳回读数。路由读取跟随实际选中请求，失败不伪装成无路由，可重试入口是再次进入页签。
