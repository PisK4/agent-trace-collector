# Agent Note: 计时与用量并入「用量与上下文」折叠行

Status: implemented

## Problem

头部读数条在四个页签各占两行等宽数字，而它统计的同一本账在读数页另有出口：构成条与「提示总量」要切到读数页才看得到，头部「共」与 u-total「提示总量」是同一个数（入 + 缓读 + 缓写）的两个口径。验收中另暴露四处显示缺陷：账本 `flow_ms` 存在 1ms 这类退化值（req 122 实测 `ms=7769, ttft_ms=7636, flow_ms=1`），速度按「出 ÷ flow」直算出 247000 tok/s；费用按原始 float 直出，`$0.012832399999999999` 带浮点尾差；上下文构成展开后先画一根占用率进度条再画构成分段条，两根叠着被读成一根样式坏掉的柱；「当前结果 · 总量已校准」是正常态却每次渲染，违反本篇前作确立的规则一。

## Decision

头部收敛为一行身份：req 号 · 时间 · 客户端 · 模型（加粗，`model_served` 缺失回退 `model_requested`）＋状态点，四个页签常驻；数字全部移出头部。

读数页末位的折叠行由「上下文组成」改为「用量与上下文」（稳定键仍是 `prompt:<req>`，默认展开）：状态提示（仅非常态）、构成单条柱、图例、u-total、口径注；读数本体现按标签和值两列展示（计时与用量各一组 `<dl class="chain">`，数值列右对齐），该排版由[中栏间距、历史提示与右栏读数修正](2026-10-24-reader-layout-and-entry-fixes.md)部分调整，首 token 与首个文本在该篇定名并分立成行。速度分母沿用「总 − 首 token」，缺首 token 才退回账本 `flow_ms`；费用按 6 位有效数字渲染（`fmtCost`）；「共」删除，提示总量由 u-total 一处承载且缺值显「—」不再落 0；占用率删除进度条，只保留 u-total 文字（占用 X%）。折叠行收起时摘要给「总 / 出 / 命中」三项关键读数。窗口外请求分支复用同一读数的无折叠版本（`ledgerRowsHtml`）。

## Alternatives considered

**模块并到读数页第一位**：数字第一眼可见性最高，但用户拍板保持在最底下——先读回复，账目沉底备查。落选。

**头部连 req/时间/模型也并入模块（字面全并）**：头部最干净，但主栏不显示请求标识，正文/工具/路由页签将没有任何「这是哪笔调用、谁服务的」上下文。落选。

**占用率编码进构成条宽度（轨长 = 窗口，柱长 = 占用）**：一根柱带两个事实，但占用小时构成分段被压扁，构成可读性让位于占用，且占用已有文字出口。落选。

## Consequences

四个页签的头部少两行，正文/工具/路由页签不再可见任何数字——req 号与模型保留在身份行，其余读数在读数页末位备查。构成条与总计明细在同一个默认展开的折叠行里互证；速度、费用、状态提示、提示总量四处显示缺陷随迁移一并修复。取代[右栏读数条与「无则不显」收敛](2026-10-24-rail-usage-strip-and-absence-hiding.md)中「头部读数条四页签常驻」的陈述，其规则一（异常才提醒）与规则二（缺值「—」）继续有效；该篇删除用量与时间构成 section、`model_time` 兜底标题不渲染、模型全页只显示一次的决策不受影响。

## Testing

`bun run typecheck` 通过；`bun test` 全量 541 例通过（读数页排序用例随新契约更新：用量与上下文默认展开置底）。浏览器验收（真实恢复数据 + 合成播种）：头部身份行单行含加粗模型；模块默认展开置底、单构成条、正常态零状态提示、异常态出现「缺失 · 本地估计」；退化 `flow_ms=1` 的合成行速度显示 1,857 tok/s（分母改用总 − 首字），真实恢复行同验；`fmtCost` 数值单验（`0.012832399999999999 → 0.0128324`），priced 分支渲染路径沿用原实现未变；窗口外请求分支读数行正常。
