# Agent Note: 上下文矩阵布局与点击明细

Status: implemented

## Problem

上下文矩阵树状图应帮助阅读者判断本笔请求由什么构成，以及哪个文件、工具结果或对话片段占用了较多上下文。旧图形的面积、标签和明细入口没有形成完整的阅读路径：低占用请求留下大块空闲区域，文字错位并越过色块边界，较宽的右栏仍只展示少量合并块，点击色块也无法阅读内容。

2026-10-26 的用户反馈样本中，提示总量为 231,866 tokens，窗口为 1,048,576 tokens，实际占用约 22.1%。旧图形采用 `share^0.35` 分配已用区，导致已用内容占约 59% 的面积、空闲区占约 41%。图中的面积既不能直接读作窗口占用率，也没有把空间充分用于区分已用内容。文件引用占提示总量约 55.3%，却主要呈现为前端再次合并的另外 23 项；同一样本的第 1 轮对话（55,056 tokens）与上游合并的 14 项文件引用（18,418 tokens）都缺少可直接查看的内容。只读核对时该请求正文状态为 pending，没有骨架或消息块，因此当时只能解释统计、无法展开正文；这是该样本的覆盖缺口，不推广为所有请求都缺正文。

## Decision

读数页的上下文构成图是已用上下文的两层矩形树状图，全部内容块、图例项与内容列表行可点开同一个居中明细弹窗；正文对应是独立的只读解释，不回写 `parts_json`、不改变提示总量、不冒充采集时 Magpie 的精确分类。统计继续消费已采集的 Magpie 分解，正文从 ATC 保存的脱敏请求按需读取；不读取磁盘上的当前文件替代历史输入，不依赖 Magpie GUI 或其近期内存正文。

与[读数页上下文分布 treemap](2026-10-26-context-distribution-treemap.md)的关系：本次部分取代它关于非线性空闲区、面积下限、标称宽布局、仅原生 title 与暂不提供正文点击的决定。类别来源、七类颜色身份、未知类别保名、只读查询与不覆盖上游分类的原则继续有效，该 note 保持活跃并互链。[前端降噪约束](../../implemented/process/2026-10-24-frontend-denoise-standing-rule.md)继续适用：新增信息优先放点击后的明细，主图不堆叠提示标签；[轮次两端阅读](2026-10-25-turn-pair-reading.md)的结算判据未动，上游上下文轮次与 ATC 结算轮次分开展示，轮次编号不用作正文定位依据。

### 布局与面积

- 面积按真实 token 值两层分配（squarify，Bruls et al.），铺满全部绘图区，绘制时扣固定 2px 间隙；窗口容量不进图，占用由读数行表达。`share^0.35` 与 `TILE_FLOOR` 的数值抬升删除。分解之和与报告总量不一致时展示差异并说明分母，不补造未知类别凑数。
- item 清单不覆盖类总量时（上游只逐项列大头），差额渲染为「未逐项余量」显式块参与该类布局，不抬高各 item 的面积份额；逐块 token 合计因此不等于 parts 合计，几何按类别守恒，差额如实可见。
- 碎项（布局面积低于 950px²，≥2 块）并入一个成员集合块再重排一次，成员身份列表随块保存；类别矩形最短边低于 24px 或面积不足两块下限时整类一块，不硬拆 item 层。
- 渲染为绝对定位的 HTML button：名称与数值走正常文本布局、单行省略、容器裁剪，SVG `clipPath` 与像素级字宽估算删除。文字取舍按实测尺寸判定：高度不足 44px 去数值行、不足 24px 或宽不足 47px 全部隐藏，被隐藏的信息由同页列表承担。容器高度按 `aspect-ratio:2.4` 夹在 160–240px；ResizeObserver 批量重排（rAF 合并），不触发正文读取；折叠、离屏尺寸无效时延后补算。
- 图例项与内容列表行同为 button，与 tile 走同一选择动作，键盘 Enter/Space 等效；上方构成色条删除，与图例重复。类别颜色保持身份稳定，skills 色槽换为浅色表面方案校验过的值（亮 `#6250d6` / 暗 `#9085e9`），tile 底色为类别色 16% 混入表面、边界 30%、文字用主题墨色（对比度实测 11–14:1），亮暗两模式通过 dataviz 校验脚本。
- 轮次在图中按大小排、明细里按输入顺序读；上游轮次标「上下文第 N 轮」「更早上下文 N 轮」，折叠桶标「另外 N 项」，列表折叠摘要按已保存条目计数（「显示全部 N 个已保存条目」），不把保存条目数说成原始文件或调用总数。

### 点击明细与正文对应

- 选择范围以稳定身份解析：item 块与列表行按 `kind\01tag\01name` 从已保存统计反查名称与数量词；集合块与整类按类别范围查询，成员名单在弹窗内如实列出。图形、列表、键盘与触摸使用同一范围；上游 `more`/`turns` 合并项展示所属类别并明确范围，不冒充精确子集。
- 目录查询 `GET /api/requests/:id/context-item` 绑定 reading token 与 `CTX_EXPLAIN_VERSION=1`，与正文、工具结果同一套认证、输入校验与 409 语义。定位规则按类别：results/files 用 `tool_call` 配对表列（零消息块解压），files 再按调用参数路径与条目名对齐，未对齐时降级为承载块并说明；tools 读骨架的 `tools`/`functions` 字段；system 合并顶层字段与 role=2 块；chat、memory 与 skills 给承载块并说明片段未分离（解释规则 v1，轮次与消息块的成员对应未建立）。未知类别返回 `unsupported` 与原因；正文 pending、evicted、summary 与协议不支持按事实返回，不用空数组冒充完整。
- 每响应最多 80 条目录条目，游标绑定请求与类别，跨请求或跨类别复用一律拒绝。条目带承载请求、消息序号、内容块路径、定位精度（片段/承载块）、工具名与失败位；片段正文走既有正文分页与工具结果端点，弹窗不新增正文端点、不在打开时预读全部正文。同名工具的多个配对结果全部保留；派生只确认一个结果位置的调用，其余结果不在目录里，这是配对表的覆盖边界而非全集。
- 弹窗居中、宽度上限 860px、内容区滚动，Esc、关闭按钮与点击遮罩三种关闭途径，关闭后焦点回触发控件；打开弹窗不触发右栏重绘，矩阵与列表的滚动位置、展开状态与所选块保持不变。每次目录或正文读取捕获弹窗代次，晚到响应不进入已切换或已关闭的弹窗；换请求重绘关闭弹窗。读取期间阅读依据变化返回 409，弹窗显示可重试的说明。

## Alternatives considered

**所有格子打开同一个原始 JSON 面板。** 目录不按类别定位，正文对应只剩整笔请求的原始对象。原始 JSON 只证明保存覆盖，不证明分类对应，回答不了「这个文件为什么占这么多」；需求评审时明确否决。落选。

**窗口容量画进图里。** 有窗口时把空闲也当一类布局，面积永远守恒到窗口。空闲块会吃掉已用内容的面积，低占用请求重演旧图形四成面积是空闲的读法；占用由读数行表达后，图内不再需要它。落选。

**保留 SVG `clipPath`，只修文字横坐标。** 改动小，但像素级字宽估算与标称坐标拉伸的错位来源还在，宽栏仍只有 340px 标称布局的明细密度。改为绝对定位 HTML button 后，省略、裁剪与键盘焦点都是浏览器原生行为，估算代码整体删除。落选。

**打开弹窗时预读全部目录条目的正文。** 一页目录最多 80 条，全部预读要解压整笔消息块，与「目录查询不解压消息块」的开销约束冲突。改为目录先到、条目展开才按落点读正文，正文走既有分页与工具结果端点。落选。

**扫描本笔请求正文重建候选清单再核对覆盖。** 对应精度最高，但要解压整笔正文，重复打开重复付出；配对表列已给出结果位置，承载块规则覆盖其余类别，缺口在弹窗里明示。未启用，重开条件是承载块说明不够用的真实案例。

**沿用 Magpie 的全屏弹窗与内存正文端点。** Magpie 的 `/api/context/text` 依赖其常驻内存正文，ATC 的正文在块库里且可能已回收；全屏弹窗压掉右栏读数。采用居中 860px 弹窗与既有正文端点。落选。

## Consequences

- 面积可以直接读作已用内容的份额；小项的点击便利由同页列表按钮承担，不靠扩大数据值换面积，零值也不补面积。
- 分类对应只覆盖到配对位置与承载块级：记忆、技能与上游轮次的片段分离，以及「用完整正文重建候选清单再核对覆盖」的路线，都未在本次交付，明细里明示为承载块或缺口，不虚构片段级对应。正文完整只证明保存覆盖，不证明分类对应完整。
- 未逐项余量块带来「显示值合计 ≠ 类总量」的读法：几何按类别守恒，差额在块里可见，弹窗按类别范围给出全部已保存条目。
- 供应商持有历史、密封推理与图片按实际可读性呈现，不生成虚构正文；带 `previous_response_id` 的请求只展示本笔保存的输入及声明的历史引用。
- 目录查询不解压消息块，首次打开的开销落在骨架一次解压与配对表查询上；「扫描本笔请求重建候选清单」一类会带来解压尖峰的路线因此未启用。
- 合成环境上的浏览器 DOM 验收已执行（几何、交互、三态、亮暗与窄栏重排，见[验收记录](../../../../docs/acceptance.md)）；像素截图与触屏目标尺寸检查未取得——`Page.captureScreenshot` 对该页持续超时，视觉口径以 DOM 断言为准，不宣称截图级视觉通过。

## Testing

合成验收全部进 `bun test`：布局守恒按类别断言（六状态 × 三宽度）、无重叠与越界、文字取舍阈值、碎项合并、未逐项余量、整类块、上游叫法、联动与明细属性、旧口径渲染；目录查询覆盖配对表列、名称过滤与降级、顶层与 role=2、承载块说明、分页与游标绑定、缺口状态、阅读冲突与端点校验；弹窗渲染覆盖状态机、成员标注、单项默认展开与正文呈现。全量套件 810 例通过，`bun run typecheck` 通过；另有合成库临时实例上的浏览器 DOM 验收（tile 几何、三种入口、片段与降级、三态读数、亮暗主题与窄栏重排），像素截图仍超时，见[验收记录](../../../../docs/acceptance.md)。真实统计核对未执行。
