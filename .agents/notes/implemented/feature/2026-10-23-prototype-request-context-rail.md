# Agent Note: 原型右栏请求上下文

Status: implemented

## Problem

紧凑轨迹便于扫描动作，但仅有回复摘要无法核对请求携带的工具、技能与历史消息。用户希望在右栏复用生产详情的能力与结构信息，并确认同一请求的多条步骤共享数字序号；逐行重复时刻占用了摘要空间。

## Decision

[本机原型](../../../../prototypes/README.md)右栏按请求能力、请求结构、本次回复排列。能力清单和请求消息默认折叠，结构展开时按片读取，点击消息在原区查看全文并可返回；回复完整显示。渲染复用生产纯函数，保留能力缺失、部分正文、未知增量等状态。请求结构的读取独立于中栏增量片段，避免把未读历史当成完整结构。

中栏数字表达当前载入请求的顺序，同一请求的步骤共享数字。它不是逐行步骤号，也不是数据库 ID。逐行时刻移入右栏请求身份区，首字与时长仍在中栏按请求显示。右栏同请求重绘保留滚动与已展开能力清单，换请求重新定位。

本记录部分取代[本机读取决策](2026-10-23-local-trace-prototype-reader.md)的逐步骤阅读序号选择，保留其只读、本机和样本限制；补充[单一轨迹决策](2026-10-23-single-timeline-prototype.md)的右栏展示。活动树检索未发现其它拥有原型右栏上下文决策的记录，生产界面和接口保持原有实现。

## Alternatives considered

**一次加载完整会话或所有请求历史。** 用户只在核对单笔请求时需要完整结构，按需分页避免为折叠内容解压大量历史。

**把结构消息混进中栏步骤。** 请求重发的历史不等于新增动作，混排会重复旧消息。中栏保留增量阅读，右栏按协议原始顺序核对上下文。

**每行独立编号并重复时刻。** 用户确认希望表达请求归属，同请求多个新增消息共享数字更符合这个目的；时刻可在选中后的右栏查看，移除后为摘要腾出宽度。

## Consequences

右栏能核对声明能力、完整请求消息与回复之间的关系，也能区分原始消息位置和中栏请求序号。长上下文仍需逐片加载，阅读量与当前请求有关；能力声明不表示技能或工具被实际调用。真实数据样本和合成分页验证的范围见[验证记录](../../../../prototypes/README.md#验证范围)，不外推为生产性能验收。
