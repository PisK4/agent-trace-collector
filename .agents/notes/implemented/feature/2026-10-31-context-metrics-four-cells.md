# Agent Note: 读数页四格上下文指标与折叠的用量明细

Status: implemented

## Problem

2026-10-30 把上下文读数提到 treemap 上方时留了三格：已用上下文与同一行的总上下文、窗口进度、提示词缓存。三格里同一批数字说了不止一遍。总上下文既是已用上下文的后缀，又是进度格的分母；缓存格给命中率，下面再写「缓读 X · 新入 Y」，与用量两列里的缓读行是同一本账。图下的计时四行与用量五行也一直摊开，占了折叠行大半高度，读者每次都要先跨过九行逐笔账目才看到 treemap。

2026-10-31 用户在生产截图里圈出三处：`/ 总上下文 1.0M`、`已用 ÷ 总上下文`（连进度数字）、缓存条加「缓读 · 新入」；计时四行合并成一个指标，用量五行收进折叠。看过原型后用户删掉「剩余可用」，其余认可。

## Decision

构成区顶部四格：已用上下文、固定开销、提示词缓存、耗时。

- **已用上下文**仍是 `prompt.tokens`，与 treemap 面积同源。窗口与进度合成副行：`总 <窗口> · 已用 <整百分点>%`；窗口未知写「模型的窗口大小未知」，旧结果与缺失写「总 <窗口> · 不计算进度」。异常 pill 都挂在这一格标签行：「本地估计」（`counted=false`）、「接近占满」（≥75%）、「占满」（≥90%）。
- **固定开销**是系统提示、工具定义、技能、记忆四类的 token 和，类别登记在 `web/parts.js` 的 `isFixedKind`。副行写它占已用上下文的整百分点，分母是已用，不是窗口，窗口未知不影响这一格。没有构成分类时写「—」与「没有构成分类」，不写 0；分类存在而四类全为 0 是真实读数，照常给 0。
- **提示词缓存**只给命中率，不画条、不并列缓读与新入。
- **耗时**是整笔 `ms`，副行依次写首 token、首个文本、速度，缺项跳过，全缺写「没有计时读数」。首个文本只在详情里有，未读正文时副行没有这一项。
- 计时口径抽成 `timingReadingsOf`，指标与窗口外请求的读数行（`ledgerRowsHtml`）共用；`ledgerParts` 的 `headline` 删除，摘要不再需要它。
- 入、出、缓读、缓写、费用与 effort 收进二级折叠「用量明细」（`data-fold="usage:<req>"`，默认收起）；折叠行摘要不挂任何读数。
- 窄栏两列，已用与耗时各占整行；宽栏四列。断点是折叠行正文的容器查询（560px），不跟视口走：右栏宽度本身是 `clamp(280px, …)` 的弹性值，同一视口下的实际宽度差别很大。

每格缺值写一句缺什么，四格始终渲染——没有 prompt 分析时也一样，不整块隐藏。

本篇部分取代[读数页上下文窗口三指标](2026-10-30-context-window-stats.md)：它的窗口进度独立成格、缓存条与「缓读 · 新入」副行由本篇撤掉；它不建模型窗口表、窗口未知不用默认分母、不拆第二个折叠行、不显示 live 态的结论继续有效。与[计时与用量并入「用量与上下文」折叠行](../simplification/2026-10-24-usage-ledger-fold.md)的关系：账目仍归同一个折叠行，但摊在正文里的计时与用量两列改为二级折叠，摘要不再挂读数。

## Alternatives considered

**保留窗口进度为独立一格，只删缓存条。** 分母文字可以少一半，但进度数字与副行里刚写的百分比仍是同一事实，宽栏多一列还会把每格挤到 110px 以下。落选。

**「剩余可用」作为第四格。** 在原型阶段做过，用户复核后删除。它等于窗口减已用，与进度互为补数；副行已经给出比例，这格不再增加信息，只占宽度。落选。

**耗时并入提示词缓存格。** 缓存是输入侧的构成比例，耗时是整笔请求的等待，两者没有同一分母。并成一格会让 97% 同时表达两件事。落选。

**用量明细默认展开。** 折叠省下的高度会还回去；五行动态账目是回看核对用的，不是每次阅读的必经。落选；想默认打开时只改 `open` 一处。

**窄栏保持四列。** 280px 时每列不到 60px，读数与副行都会折断；两列加大号数字在窄栏更可读。落选。

**固定开销按窗口做分母。** 占窗口的百分比能回答「窗口被常驻部分吃掉多少」，但固定开销与已用上下文同属提示内容，读者通常问的是「这笔提示有多少与对话无关」。分母选已用，与 treemap 面积同一口径。落选。

## Consequences

- 默认态折叠行少九行逐笔账目、多一行指标；treemap 随之上移，首屏能同时看到四个指标与构成。
- 固定开销按类别集合算，未知 kind 不计入：magpie 新增固定类别时要在 `FIXED_KINDS` 登记，否则这笔类别会落进对话侧。
- 容器查询要求 `@container` 支持（Safari 16+、Chromium 105+）；不支持时退回两列，指标不丢。
- 旧结果与缺窗口时，副行只留总上下文，原因进悬停 title 与折叠行的状态提示，不再单独占一格。
- 不升 `PURPOSE_VERSION`，不改 schema、接口与派生；所有字段都在现有读取行与详情里。

## Testing

`bun test tests/web.test.ts` 34 例通过（四格的已知、未知与合法 0，固定开销的缺失与零和，耗时副行与首个文本只从详情取，pill 归属，用量明细默认收起与摘要无读数），`bun run typecheck` 通过。提交前按仓库约定只跑能对该回归失败的最窄测试；生产页面做只读核对，不写库，真实请求正文不进日志或提交。
