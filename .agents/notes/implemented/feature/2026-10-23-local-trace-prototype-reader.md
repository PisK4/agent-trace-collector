# Agent Note: 本机真实轨迹原型读取

Status: implemented

## Problem

合成数据无法判断真实会话中工具调用密度、输入包装和缺正文状态是否适合紧凑单行排版。用户明确要求使用本机指定会话的前一段内容审阅原型，并选择连续数字作为阅读序号。

## Decision

[本机原型入口](../../../../prototypes/README.md)在只读连接中定位指定会话，通过现有 collector GET 接口读取正文与解释，不启动采集或派生，不导出正文到文件。样本可按时间正序截取前 50 条步骤，后续未载入的边界明确显示。真实内容留在本机服务和浏览器，不进入静态原型、fixture、日志或在线发布。

编号展示由[右栏上下文与编号决策](2026-10-23-prototype-request-context-rail.md)接管，交互身份继续保留请求和原始位置。用户输入只使用当前派生确认的增量与服务端解释，实际回复按内容块顺序展示；工具结果只在配对已确认时按具体结果路径读取，未确认时保留状态。

本记录部分取代[单一轨迹原型决策](2026-10-23-single-timeline-prototype.md)中的合成数据范围与请求编号展示选择，保留其单行布局、折叠、模型计时归属及延后生产重构的理由。检索活动树未发现其它拥有本机原型读取决策的记录。

## Alternatives considered

**把真实正文写进 HTML 或 JSON 快照。** 运行简单，但会形成可误提交或传播的真实内容副本；按需只读可以直接评审而不留下快照。

**直接启动另一套 collector。** 原型只需要读取，启动采集会引入重复任务和写入。复用已运行的 GET 接口与独立只读窗口查询更符合范围。

**继续使用请求号或全会话固定步骤号。** 用户选择简单数字；全会话固定步骤排名又依赖尚未载入的正文与派生结果。当前窗口的阅读序号足以辅助查看，精确定位留在详情与内部位置键中。

## Consequences

真实会话可以直接用于布局评审，合成入口仍适合公开演示。读取入口依赖本机默认数据目录与已运行的 collector，读取请求和正文不保证跨接口处于同一快照；它只用于原型评审，不能当作生产步骤查询契约。

验证需要覆盖指定样本的数量、连续编号、默认折叠、工具参数与结果展开，以及 Host、Origin 和请求方法限制。实际验证范围与尚未覆盖的最新窗口分页见[原型说明](../../../../prototypes/README.md#验证范围)。
