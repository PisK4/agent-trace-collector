# Agent Note: 切片派生的等价性判据与容量门槛

Status: implemented

## Problem

切片派生的前五个阶段把"算得起"解决了，但"两条路径给出同一份结果"还没有判据。这类等价性最容易骗过自己的地方恰恰是"看起来等价"：字段对得上、值为空时用 COALESCE 回退一下旧列，旧标题就变成了一次新结果，一整套比对随之失去意义。容量门槛也一样。没有等价性作前提，"切片更快"只说明它算得更少。

判据必须落在能失败的地方，而且要覆盖那些只有特定输入才会走到的分支：排除用途、正文不可读、关系判不出来、标题请求与普通请求混在一条链上。

## Decision

**等价性的定义是逐行相等，落点在测试里，对照值不手写。** 同一份种子分别喂给同步入口与切片入口的两个独立库，逐行比较两处事实：请求行的关系（`prev_req_id`、`prev_relation`、`delta_ordinals`）、角色（`chain_role`）、四个展示列（`title`、`title_source`、`input_preview`、`input_preview_kind`、`reply_preview`），以及工具行的八个列（`req_id`、`ord`、`call_id`、`tool_name`、`result_req`、`result_ord`、`result_path`、`state`）。同步侧读 `request`／`tool_call` 旧列，切片侧读已发布代的 `derive_request_result`／`derive_tool_result`。对照值来自同步路径在同一份种子上的另一次运行。手写的期望值会在实现改动时过时，也覆盖不到模糊组。

**切片侧把预算压到每批一行、每步一个写事务**，页边界因此落在每一笔请求之间。页边界不该改变结果，这正是要压的地方。带工具往返的模糊组把候选额度给到 2。这个额度同时是"单笔请求能整笔算完"的下限，比一笔请求的候选还小就只能丢弃。

**固定用例之外加固定种子的模糊组。** 乱序到达、同毫秒偏移、缺正文、回收墓碑、重复 `call_id`、结果早于调用、标题旁路、排除用途与关系判不出来都在同一个种子池里生成。序列由写死的线性同余发生器给出，随机序列就是可复现的输入。任何一行不同即失败，并打印第一处差异的那一行。

**判据不为某一列让路。** 标题、来源与摘录是折叠行里唯一可读的东西，容忍其中一列等于把判据降级成"大体一致"。

## Alternatives considered

**逐字段 COALESCE 回退到 `request` 旧列（新代没有值就用旧值）。** 反例是把旧标题当成本次结果。正文不可读的标题请求，旧 `title_source='user_delta'` 会被原样读成"这一代算出来的"，而正确结果是标题分支把来源提升为 `model_time`。旧列在切片模式下不再被写，它们承载的是同步模式的历史值，读切片结果不能碰。

**把未发布代的暂存行当可读结果。** `derive_request_result` 在物化阶段就有一行，标题为空、保留态按正文可读性标好。它是一代构建到一半的中间产物，读它等于发布一半的产物。读口径必须由 `published_generation` 指针决定，见[派生代际与发布指针](../../../../docs/architecture-design.md#派生代际与发布指针)。

**手写期望值。** 把同步结果抄成常量能让测试先绿，但实现一改就过时，且模糊组的期望值无法手写。

**用真实流量或生产库做样本。** 合成数据是硬约定，真实正文、账号与用户配置不进 fixture。等价性判据不需要真实数据，它需要的是确定的输入。

**让切片跑完整规模再比对结果。** 规模问题由容量实验回答，等价性只需要小而确定的输入。把两件事绑在一起，判据会既慢又难定位失败。

**只比"发布成功"不比内容。** 那正是"算得更少"能蒙混过关的形状。

## Consequences

- 切片与同步的形状差异（写哪里、读哪里）在测试里被显式编码。改任一侧的取值实现都会让这个文件失败，这是有意的。判定与取值只有一份（`previewOf`、`deriveTitle`、`toolResultPreviewOf`、`replyInfoOf`、`firstUserPreview`、`tailUserPreview`、`messageAt`，前三个在[判定内核](../../implemented/architecture/2026-10-23-derive-decision-kernel.md) `src/derive/decision.ts`，其余在 `src/derive/sync.ts`），两处调用必须保持同形。
- 模糊组覆盖的是分支组合，不是规模。两个种子各 50 组、每组最多 20 笔，压缩预算下跑完在秒级。
- 比较范围只含两条路径都在场的字段。切片独有的阶段游标、`staged_bytes`、代际状态不在判据里。它们不是展示结果，也没有同步侧的对照物。
- 第一个被这个判据抓到的缺陷是排除用途行标题兜底的分支位置，修复单独提了一条，见[排除用途行的标题兜底不挂在增量分支下](../bug-fix/2026-10-23-atc-slice-aux-title-branch.md)。
- 判据覆盖不到的部分要说清。真实规模下的收敛、丢弃率与 WAL 行为由容量门槛回答，不由等价性回答。
- 10,000 笔单链的长组门槛实测判负在 `drain_ms` 上：切片排空 878,696 ms、3,600 次轮询，同步同输入 1,959 ms、1 次轮询。结构不变量全过（发布 1 代、丢弃 0 代、增量与全量逐字一致）。慢的来源不是算得少，而是切片入口每笔请求一个读事务、每页一个写事务，长链把事务开销放大成分钟级。切片模式因此保持关闭，采集器继续走同步派生。要改变这个结论，得改事务边界（按请求批量读写、把一页的读合并进同一个事务），不是改判据。读数见[baseline record](../../../../docs/superpowers/capacity/2026-10-22-atc-capacity-baseline.md#切片长组实测)。
- 两份报告的 `result_sha256` 不可跨运行比较。播种用 `Date.now()`，标题的时间兜底精确到分钟。长组报告因此只证明切片内部"增量 = 全量"；跨路径等价的证据始终是固定种子样本。

## Testing

`bun test tests/capacity-slice.test.ts`：固定用例（一条四笔的链、一笔缺正文、三笔展示定点）逐行相等，并断言三个定点的取值：不可读的标题请求来源提升为 `model_time`；可读且 `model_title` 为空时用时间兜底而不沿用库里的旧标题；排除用途的非标题请求保留模型标题且不取用户增量；末尾断言队列回到 `clean`。固定种子的模糊组逐行相等：修复前第一处差异即上述标题列，修复后两条路径逐行相等。

长组门槛按 [baseline record](../../../../docs/superpowers/capacity/2026-10-22-atc-capacity-baseline.md) 的「切片长组实测」一节两条命令重跑。场景跑完写报告，门槛读报告与预算并退出 0 或 1；这一轮的实测失败项是 `drain_ms`。
