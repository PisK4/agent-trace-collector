# Agent Note: 不可读 trace 的默认阅读投影

Status: implemented

## Problem

本机库里有一批请求没有可读正文。它们有账本、路由和用量，HTTP 可能成功，但 `body_state` 停在 pending 或已回收，中栏只剩一条组级缺口状态行。一次本机会话的只读核验里，5 笔这样的请求连续占据对话时间线，读者从行内看不出它们是辅助调用、采集缺口，还是仍在加载。

这些请求是真实发生的。删除请求记录会同时丢掉费用、耗时、重试和证据。需要解决的是阅读投影：默认对话时间线该不该为没有内容的请求留一行。

另一面是内容并非全部消失。后续请求会携带前序对话，ATC 已能把这些消息显示在承载请求下。一次只读核验还发现，Claude Code 的会话 JSONL 保存了可重建的 API 请求快照和 assistant 响应身份，5 笔缺口中有 3 笔能确认请求与回复，2 笔在该文件里没有记录。这个结果只证明该版本、该会话的记录形态，不能直接推广到全部会话或全部 agent。

需要同时决定两件事：默认阅读投影怎样处理无内容请求；恢复通道是否进入产品，进入后怎样标注来源。现行缺口行决策见[中栏证据缺口记录行的收敛](../bug-fix/2026-10-28-evidence-gap-row-collapse.md)，增量投影的不变量见[中栏按请求新增消息分组](2026-10-28-request-delta-trace-groups.md)。本记录部分取代现行缺口行的默认阅读决定，证据折叠、状态行结构与缺口判定口径保持不变。

### 已知证据

- 五笔缺口都有账本和路由，HTTP 200，缺 hook 正文；派生态为 unknown。
- 后续请求携带了缺口期间的 Assistant 消息与工具结果，现有增量投影已把它们显示在承载请求下。
- JSONL 的请求快照按 base、keep、tail 重建后摘要校验通过；快照与 hook 请求的消息语义相等，但缺 metadata、stream 和一个 system 块，不能替代 hook 原文。
- JSONL 中 Assistant 记录的 message id 与 ATC 账本的 `response_id_norm` 直接相等，可确认三笔缺口；另两笔在该文件没有响应 ID、请求快照或裁决记录。
- 现有缺口状态行由存储状态生成，不含对话内容；真实失败、重试和压缩由其他记录表达。
- 本机库调研快照 36,464 笔请求，缺口 18,435 笔（50.6%）；采集器在线，复核时计数有少量漂移。`archive` 字段全为空，magpie 的请求归档已有字段与文档，但本机未开启。

### 候选恢复通路

| 通路 | 能恢复什么 | 证据强度 | 本机现状 | 边界 |
| --- | --- | --- | --- | --- |
| 后续请求前缀 | 缺口请求的输入消息、回复与工具结果 | 中：消息内容可读，逐笔归属缺少响应身份 | 已有增量投影 | 不能证明某条消息属于哪笔缺口请求 |
| Claude Code JSONL 请求快照 | 请求快照、Assistant 回复、工具结果 | 高：响应 ID 与账本相等，快照摘要校验通过 | 会话文件存在，记录形态已抽样确认 | 缺 metadata、stream 与部分 system 块；版本与路径可能变化 |
| magpie 请求归档 | 已脱敏的完整请求与回复 | 高：上游归档，带保留 | 未开启，`archive` 全为空 | 正文出本机进 S3，属于隐私决策 |
| OTLP `body_ref` | 外部 harness 的请求与回复文件 | 中：取决于导出方是否提供正文指针 | 已有接收端 | 当前只覆盖部分 harness，摘要居多 |
| 路由 `prompt.parts` | 上下文构成与 token 分类 | 低：没有消息正文 | 已有 | 只能解释上下文构成，不能恢复对话 |

### 调研结果（2026-10-31）

全库快照 36,464 笔请求，缺口 18,435 笔（50.6%）。采集器在线，复会计数有少量漂移。

| 类别 | 笔数 | 说明 |
| --- | ---: | --- |
| evicted | 12,675 | 正文按预算回收，库内没有残留材料 |
| pending · hook_absent | 5,228 | 账本已到，等满 1 小时仍无关联 hook |
| pending · disk_body_paused | 505 | 323 笔未满 1 小时，182 笔超过 1 小时 |
| pending · 无原因 | 26 | 未满 1 小时 |
| summary | 1 | OTLP 只有摘要 |

后继与恢复等级：

| 等级 | 笔数 | 占比 | 判定 |
| --- | ---: | ---: | --- |
| A | 1,809 | 9.8% | 同会话后继可读，`prev_relation='confirmed'` 且有 `delta_ordinals` |
| B | 4,488 | 24.3% | 有后继，关系或增量不确定 |
| C | 12,138 | 65.8% | 没有后继可读请求 |

A 级全部落在 pending·hook_absent；evicted 的 A 为 0。A 级也不能唯一确定缺口请求的输入边界：后继 delta 全部以 assistant 开头，缺口自身的 `msg_count`、`delta_ordinals`、`input_preview` 都是空，后继的 `prev_req_id` 等于缺口请求的为 0。能从后继增量给出候选上界，确定不了唯一值。

Claude Code 转录存在性：94 个 claude 会话，91 个有缺口，91/91 转录文件存在；16,632/16,709（99.5%）缺口请求落在可解析的会话键内。91 个缺口会话文件都含 `api-request`、`api-request-blob`、`api-request-shape`。抽样 5 个文件，`api-request` 301–944 条，明显低于库内对应会话的请求数；逐笔覆盖率仍未知。时间近邻抽样 498 笔，60 秒内命中 446 笔（89.6%），只能作退化匹配，不能当身份证据。

库内没有正文回放材料：`archive` 非空 0，`raw_hook` 的 `request_z` / `response_z` 全空，缺口行 `skeleton_z` 全空、`request_block` 为 0，`otlp_body_ref` 与 `raw_otlp_log` 为 0。`raw_otlp_span` 只有元数据。magpie 请求归档未开启，开启只覆盖未来请求。

结论：第一版只做展示投影。转录恢复值得单独立项，但要跨过不扫描 Agent 会话文件的边界，需要解码器、身份匹配、脱敏与安全评审。

## Decision

第一版只做不改变观测事实的阅读投影，恢复通道另立提案。

### 1. 默认中栏省略空组

成功但没有可读正文的请求，投影只剩一条组级状态行时整组不生成。判定是 `web/trace-view.js` 的 `isEmptyGroup`：投影已备齐，步骤集合里只剩 `flag` 行。准备行、保留投影、辅助、失败、压缩、截断、读取中与读取失败各带一条记录行，都不判空。用步骤集合而不是行数：缺口组总有一条状态行；步骤集合为空同样不渲染任何行，一并算空。

`web/app.js` 的 `mainModel` 跳过空组。`stepsOf`、`retainedSteps`、`tailEligibleIds` 不动；末尾回复组仍单独成组，不随承载组隐藏。

### 2. 选中、证据与请求记录

- 选中的请求与选中轮次的起点临时留下这一组：`state.reqId` 或 `turnOf(state.turn)?.start_req` 命中时，空组照常渲染状态行。
- `railFacts` 在选中空组、且读者没有步骤选择时直接给证据折叠区，入口不依赖中栏的状态行。
- 会话头的已加载 Request 数下新增请求记录折叠，列出当前窗口里没有可读正文的请求（窗口序号与正文状态），只在该数量大于 0 时出现；点条目走现有的 `data-summary-req` 请求定位。
- 默认选中与「回到开头」「回到最新」跳过空组：`contentAnchorId` 取第一笔或最后一笔有内容的请求，`settleAnchor` 在窗口准备完成、读者没有另选时把锚点从空组挪走。准备前判不出空组，先落在首笔。

### 3. 首版不建恢复通道

- 观测事实不变：hook、账本、路由、OTLP 的现有记录不重写。
- 后续请求携带的消息继续显示在承载请求下；它们不标成缺失请求的原文，也不回填 `body_state`、`have` 或 `miss_reason`。
- 外部 transcript 与 magpie 归档作为后续提案的候选。本机转录覆盖不完整，归档未开启且只覆盖未来请求，都不进入第一版。
- 恢复通道进入产品前，需要单独的身份匹配、来源标注、脱敏与安全评审。

### 4. 展示边界

- 窗口行、加载游标、请求计数、费用与用量统计继续用完整集合。
- URL 里的缺口请求仍是页内目标；定位时临时显示该组，再滚动。
- 轮次带仍用完整请求集合生成；点到被省略的轮次起点时，中栏临时显示该组。轮次点击不改变请求侧选择，沿用现行语义。

### 5. 数据与 schema

不改 schema，不改存储状态，只调整渲染、选择和右栏入口。若后续引入外部恢复记录，再单独提案，并按首版前地基规则提供可执行 backfill 或明确拒绝路径。

### 与提案的出入

- 判空条件从「只有 flag 与加载记录」改为「只有 flag」。加载记录同时承载读取失败可重试的入口，把它算空会把重试入口一起隐藏。
- 请求记录入口没有替换已加载 Request 数，而是计数下方的同款折叠：计数留在身份行，列表按需展开，不为入口另造一种控件。
- 默认锚点跳过空组在准备完成后生效。空组判定依赖投影，准备前只能先落在首笔；锚点意图本身不渲染，`settleAnchor` 自己补渲染与路由读取。
- 轮次带点击不改变请求选择（现行语义），中栏只临时显示该轮起点组；提案里写的「请求被选中」按这条实现。

## Alternatives considered

**保持现状，每笔缺口一条状态行。** 落选于默认阅读：状态行不含对话内容，连续出现时打断阅读。状态行仍保留在证据视图与选中态，不删除信息。

**先建恢复通道，不改默认投影。** 落选于第一版：阅读干扰是当前问题，恢复只覆盖少数请求。转录匹配还没验证逐笔覆盖率，先做会把不确定内容带进阅读。

**只做 ATC 内部 A 级恢复并回填。** 落选：A 级只占 9.8%，边界不唯一，回填会改写观测事实。现有承载投影已经能读到这些消息。

**删除缺口请求。** 落选：请求真实发生，删除会丢掉费用、耗时、重试和证据，也会改变会话统计。

**按时间近邻把后续消息归给缺口请求。** 落选：已有证据显示 50 ms 窗口下会错配，且响应身份缺失时无法证明归属。

**把后续请求的前缀直接回填成缺失请求的 body。** 落选：归属没有身份证据，回填会改写观测事实，把恢复内容冒充 hook 正文。

**立即接入 JSONL 作为一等来源。** 暂不采纳：91/91 缺口会话有转录，但抽样 `api-request` 条数低于库内请求数，逐笔覆盖率未知；还要跨过不扫描 Agent 会话文件的边界。先单独立项验证身份匹配。

**扩展 OTLP 白名单来补正文。** 已有[被否决的扩展提案](../../rejected/feature/2026-10-26-otlp-harness-expansion.md)，且 OTLP 正文口径只到摘要，不能解决逐笔请求恢复。

**把加载记录也算成空组。** 落选：加载记录也是读取失败的重试入口，算空会把它一起隐藏。只有状态行才算空。

**给请求记录入口做常驻列表或第二种导航。** 落选：常驻列表会在会话头再加一层目录，和轮次带、请求定位重复。折叠按需展开，点条目复用现有请求定位。

## Consequences

收益：默认对话时间线不再被没有内容的请求切碎；请求记录、计量、费用、重试与证据都保留；选中缺口请求时中栏临时给出状态行，右栏直接给证据；不改 schema，也不写库。

代价与风险：

- 省略后读者可能以为请求不存在。会话头保留请求计数与请求记录折叠，选中缺口请求时中栏照常出现状态行。
- 锚点在准备完成后挪动一次，首屏可能有一次位置变化。挪动只在默认、开头或最新的锚点落在空组时发生，读者已经另选就不动。
- 选中的缺口请求临时显示状态行，读起来可能像常驻记录。用选择高亮区分，离开选择后回到省略。
- 轮次起点被省略时，轮次带仍在，中栏要等点了轮次才出现这一组。轮次面板本身仍按现行语义给出回收态的说明。
- 恢复通道仍未建。transcript 与归档只作为候选，需要独立提案、身份匹配与安全评审。

### Testing

- `bun test tests/trace-view.test.ts tests/web.test.ts`：空组判定的几种形状（只剩状态行、失败记录、内容行、准备行、保留投影、空步骤集合）；请求记录折叠只在有省略时出现，按窗口序号与正文状态列出。
- 合成数据页面 `prototypes/synthetic-server.ts` 的 `conv-synthetic-hook` 会话：默认落在第 2 笔，第 1 笔空组不生成；会话头折叠列出它，点条目后第 1 笔临时出现，右栏证据折叠可见。`conv-synthetic-reading`、`conv-synthetic-window`、`conv-synthetic-turns` 的请求组数与改动前一致，失败、截断与工具结果行仍在。
- 生产库只读：worktree 的 `prototypes/serve-local.ts` 转发本机采集器，640 笔请求的窗口里列出 129 笔无正文请求，中栏 512 个请求组；点序号 14 的条目后 URL 指向 `57237`，该组临时出现，右栏证据折叠可见，请求计数不变。做法与结果见[验收记录](../../../../docs/acceptance.md)。
- 未覆盖：窗口内全部请求都无可读正文的边界只有合成用例；默认锚点在准备完成后的挪动只在合成会话上观察过。

### Deferred

- 77 笔 claude 缺口请求的 `conv_key` 不是会话键，是否仍在某个转录里未知。
- 转录 `api-request` 条数低于库内请求数，逐笔覆盖率未知。
- `api-request` 的 base、keep、tail 与 blob 精确语义未从源码确认。
- 时间近邻匹配未做身份校验，真实可还原比例未知。
- magpie 请求归档未开启，开启需要单独的隐私决策。
