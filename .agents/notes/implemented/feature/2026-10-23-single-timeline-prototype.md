# Agent Note: 单一轨迹阅读原型

Status: implemented

## Problem

请求列表连续出现同名工具时难以辨认实际动作，固定侧栏和常驻说明又压缩了正文空间。三种布局的比较有助于确定阅读偏好，但用户已选定步骤轨迹，继续保留切换入口会分散定位与展开操作。用户希望先在原型中审阅融合后的布局。

## Decision

[原型入口](../../../../prototypes/README.md)只提供连续单行步骤轨迹，用户消息、助手回复与工具调用各占一行。数字和时间与消息摘要同排，模型名进入详情；同一请求的计时放在最后一条步骤右侧，只显示一次。阅读编号与本机真实数据入口由[后续读取决策](2026-10-23-local-trace-prototype-reader.md)接管。选中与展开独立，助手全文、工具参数和结果可原位展开。侧栏折叠、详情调宽与复制会话 ID 保留，生产页面和数据处理保持原有行为。

所有详情默认折叠。初始窗口按页面高度估算并留出余量，避免少量记录造成大块空白；更早记录由顶部按钮向上追加，并保持原先记录的位置。完整上下文与路由按需展开。窗口数量与行高记录在原型说明，属于评审参数。

工具结果按调用 ID 匹配，结果存在只证明已记录。模型请求计时不充当工具执行耗时，也不绘制暗示真实时间比例的工具轨迹。

活动记录检索确认，本记录完整接管同轮未提交的 `2026-10-23-trace-reader-prototype-comparison.md`，按合并规则删除该文件并保留其独有依据：比较曾覆盖请求扫描、动作扫描与长回复阅读；保留请求计量边界、合成数据约束和延后生产修改的理由。三方案入口及其独立渲染函数已移除。生产账本布局与派生机制的记录不被取代。

## Alternatives considered

**保留三种视角供切换。** 比较阶段可以帮助用户选择，但当前目标已明确为融合单一轨迹。放弃独立对话和账本入口会失去各自布局的直接对照；只有用户重新提出必须独立完成的阅读任务时才考虑恢复。

**直接改生产界面。** 用户要求先过目原型，当前布局仍待评审。合成数据交互不证明真实规模下的正文读取性能，也不证明后端已提供向前分页。

**把工具步骤当作请求账本行。** 一次模型请求可以产生多个工具调用，逐工具计费或显示模型计时会造成归属混淆。保留请求分组可以同时容纳紧凑动作行与请求读数。

**立即实现按时间比例绘制的全局轨迹。** 当前没有工具执行时间，图形容易暗示不存在的计时证据。原型使用请求顺序和记录定位回答阅读问题。

## Consequences

原型可以审阅单行轨迹的扫描、展开和历史追加体验，长回复与工具细节也能在原位阅读。折叠摘要会截断长内容，需要展开或右栏才能读全；生产落地仍需处理定点正文缓存、增量去重、结果定位与读取一致性。

必需核验覆盖默认窗口与展开、顶部追加和滚动位置、独立展开操作、工具详情与窄屏宽度。实际操作结果及截图超时、窄屏指针遮挡和真实规模未覆盖的限制均记在[验证范围](../../../../prototypes/README.md#验证范围)，不能据此宣称已完成生产验收。
