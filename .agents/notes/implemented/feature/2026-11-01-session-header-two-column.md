# Agent Note: 会话头双列常驻与分组识别

Status: implemented

后续：[方向 A 对齐修正](../bug-fix/2026-11-02-direction-a-alignment-audit.md)部分取代本记录的分组顺序、严格单行与 chip 收缩取舍；本记录保留当时的高度权衡与备选依据。现行可读性规则以该修正为准。

## Problem

中栏顶部同时承载会话身份、资源合计、性能、工具、路径和 Skill。折叠区完整展开时，各组依次纵向堆叠，操作按钮与无正文记录入口各占一行。头部吸顶后持续占用正文阅读空间，查找一个数字也需要逐行辨认类别。

2026-11-01 样张评审选择左右分区的 B 方案，并认可图标加短标签、工具与路径保留身份色的版本。进一步评审指出，分组标题旁或下方的统计范围、调用总数和路径总数形成了过多副标题，干扰阅读。目标是保留主要信息与证据入口，让分组一眼可辨，同时减少常驻高度。

## Decision

会话头在身份行之下挂一块双列分组板（`cue-board`）：左列依次是资源、结构、性能，右列依次是工具、Skill、写入尝试、读取请求；两列由对齐、间距和一条列间细分隔线区分，不加嵌套卡片或整组彩色底板。每个分组的数据严格一行（同日二次评审追加，见下节）。会话标题与刷新、回到开头/最新按钮共用顶行（`head-top`），其下身份行保留 Harness、可复制的会话 ID、已加载请求数与当前窗口时间范围。桌面沿用会话头吸顶，轮次带贴其下沿；中栏容器宽度不超过 650px 时（container query）双列退成单列。

每个分组一个 14px 线性图标加短标签：资源＝数据堆叠、结构＝分支、性能＝秒表、工具＝扳手、Skill＝四角星、写入尝试＝铅笔、读取请求＝打开的书。名称承担含义，颜色主要留给条目与异常：工具 chip 沿用[工具身份配色](../../../web/body-view.js)与[现有 CSS](../../../web/app.css)，Skill 黄、写入橙、读取蓝，失败保留文字加警示符号。

### 七处常驻副标题删除，统计范围转入按需说明

折叠区收起行与四分区不复存在。原副标题的信息去向：

- 资源、结构的「整个会话」→ 组标题悬停与键盘聚焦说明。
- 性能旁的「已加载 N 笔」→ 请求数在身份行；性能标题说明只统计当前已加载窗口。
- 工具下的「N 次调用」→ 各工具次数继续可见；调用总数与覆盖情况（未配对、未判定、中断判定缺失）进工具标题说明，复用[会话信息汇总](2026-10-25-session-trace-summary.md)的覆盖度文案。
- Skill 下的「显式调用」→ Skill 标题说明保留显式调用限定。
- 写入尝试、读取请求下的「N 条路径」→ 总数进各自标题说明，`+N` 的悬停同时保留。

按需说明放在组标题的 `data-desc` 属性里：标题可聚焦（`tabindex="0"`），悬停与键盘聚焦都以浮层显示，`aria-label` 给出「组名：说明」的复合名。资源沿用整个会话的统计，性能沿用已加载窗口的统计，范围区分遵循[会话汇总评审](../../../docs/session-trace-summary-review.md#5-同一会话头部优先统一统计范围)，计算口径不变。

### 每个分组严格一行（同日二次评审追加）

落地当天的对照评审指出，统计与 chips 换行堆叠抵消常驻收益：截图会话在 840 px 下工具一组占四行，资源、性能各占两三行，「无正文」入口独占一行。修订为每个分组严格一行：左列统计合并成一段（`cue-line`），分隔符统一「 · 」，放不下整段尾部省略；右列 chips 按调用次数取前三直接可见，其余进 `+N` 展开，失败与中断入口保持常驻；「无正文」入口并入性能行尾。展开 `+N` 时该行临时恢复换行（`open-wrap`，toggle 捕获监听切换，重绘按 `data-fold` 恢复展开态时在构建时带上），收起即回单行。

列宽配比从 `.8fr/1.6fr` 调到 `1fr/1.3fr`：统计行不再换行后左列需要足额宽度，否则 1040 px 就开始省略，右列放不下由 chip 收缩承担。chip 显式 `min-width:0`——缺了它 chip 被内容宽度钉死不收缩，溢出时被裁的是 `+N` 而不是 chip（840 px 下复现过）。性能标签同步缩短：`首字 p50` → `首字`、`平均时长` → `平均`、速度省去「输出」前缀，p50 限定进组标题说明；结构组「上下文峰值」→「峰值」，资源组「缓存命中」→「缓存」，完整口径仍在悬停说明里。

### 分组按数据显隐

分组只在有可展示事实时出现，隐藏后由后续分组补位；整列都空时不保留空列与列间分隔线（`cue-board solo`）。无 Skill、无工具、无读写路径的会话不渲染对应组，不给「未使用」「0 次」替代文字。结构组在请求存在但没有工具调用与路径时也会出现（主链/旁路是它自己的事实）——旧折叠区在这种会话里整体不渲染，是本次修正的过度隐藏。资源组在没有可用读数（窗口无用量读数且汇总不可用，或就绪汇总三项合计皆空）时整组不渲染，旧的「这批记录没有报告的用量」文案随之移除。

工具组内：各工具 chip 沿用身份色与未判定悬停，按调用次数取前三，其余进 `+N`；失败数只在非零时给出「⚠ N 失败」入口；中断计数只在非零时出现（0 次不占位，与失败同一规则）。汇总派生过期（dirty）在板上方保留一条可见警示。

### 汇总未就绪的回退与证据导航

汇总快照读取中或不可用时，资源组回退为已加载窗口的相加，并以可见的「已加载窗口」标记（warn 软色 tag）标明口径更换，不只在悬停里更换；读取中与不可用在标题说明里分开表述，两者都不显示成 0。

工具、失败、路径、Skill 条目继续复用现有右栏证据列表与配对页导航（`data-summary-*` 委托不变）。完整路径、其余 Skill 与无正文请求清单按需打开：`+N` 与无正文入口沿用内联 `details`，不引入浮层；展开会抬高头部，轮次带吸顶位置与滚动让位随后同步（见下）。无正文请求入口从独立折叠行移进性能组，`data-fold="hidden:<key>"` 的开合记忆与条目定位不变。路径保留完整原值与同名文件消歧，统计仍表示写入尝试和读取请求。

### 滚动让位跟随头部实际高度

会话头从「收起 155px 上下」变成随数据伸缩的常驻块，写死的定位留白（`.trace-group` 155px、带上方 187px、`.req` 168px）改为 `--head-h` / `--band-h` 变量：`syncBandTop` 在重绘、视口变化与会话头内 `details` 开合后，把头部与轮次带的实际高度写入变量，`scroll-margin-top` 用 `calc()` 消费。会话头自身成为 inline-size 容器，窄中栏的单列切换按容器宽度判定，不按视口宽度。

预计落点为[会话头展示](../../../web/session-view.js)、[页面样式](../../../web/app.css)与[页面控制器](../../../web/app.js)，复用现有汇总数据，不新增依赖、数据库字段、派生算法或采集行为。

## Alternatives considered

**A 全宽平铺。** 合成样本在 840 px 中栏为 230 px，比原 B 更低；样张评审选择 B 的左右分区，优先使用固定区域查找信息。

**C 摘要加展开。** 收起态能显著降低高度，但工具分布、路径与性能不直接可见，不符合本次尽量平铺信息的目标。

**分组使用彩色 Tag。** 与图标版比较过；工具、Skill 和路径已经有身份色，再给每组增加彩色 Tag 会形成更多色块。选择图标加短标签，颜色主要留给条目与异常。

**保留图标版全部副标题。** 用户在截图中明确删除七处。统计范围与总数仍需可查，移入身份行或按需说明，不再各占一行。

**只有图标或给每个数字加图标。** 单图标容易混淆模型、上下文和 Agent；每项都配图标又会挤占文字空间。每组保留一个图标与明确名称。

**按需说明用原生 `title`。** 悬停可用，但键盘聚焦在主流浏览器上不触发 title 浮层，不满足键盘可达。改为 `data-desc` + CSS 浮层，悬停与聚焦同一来源。

**`+N` 与无正文清单改浮层或右栏承载。** 浮层需要处理焦点、关闭与窄屏布局，还可能形成第二层滚动区域；内联 `details` 复用现有开合记忆与键盘语义，展开的高度代价由动态滚动让位吸收。

## Testing

合成覆盖由 `tests/web.test.ts` 锁定：

- 双列结构：左右两列、七个分组标签、身份行已加载数、路径条目定位。
- 七处副标题不常驻：无 `<small>`、无「会话合计」、无「N 次工具」，且没有换成同义副标题。
- 按需说明键盘可达：组标题带 `tabindex` 与 `data-desc`。
- 空 Skill 不渲染组与条目；工具、路径全空时右列消失、板退单列且保留左列。
- 失败入口与中断计数只在非零出现；未判定结果在 chip 悬停如实说明，不冒充失败。
- 费用缺值不给 0，缺值笔数与缓存分母口径进说明。
- 结构条件字段非零才出现；dirty 警示只在过期时出现。
- 汇总读取中与不可用都回退窗口相加并可见标明「已加载窗口」，两者文案分开；窗口无用量读数时资源组不渲染。
- 无正文入口在性能组，`data-fold` 键与窗口序号定位不变；标题转义保留。
- 输出速度分母仍只统计计时与输出都在的行。
- 工具组前三直接可见、其余进 `+N`（details 内条目可定位），三把以内不出 `+N`。
- 统计行合并为单段 `cue-line`：首字/平均/速度同行，p50 限定只进组标题说明。

高度实测（同一样本会话在两种代码下各测一遍，会话在已加载列表第一页内、汇总就绪、无附加提示行；样本 `d0e0e432…`：164 笔请求、8 工具、写入 7 / 读取 16 条路径、1 Skill、无正文入口 1 笔。旧布局测「收起」与「完整展开」两态，新布局为常驻单态）：

| 1040 px | 231 px | 518 px | 250 px | −52% |
| 840 px | 231 px | 585 px | 293 px | −50% |
| 640 px | 231 px | 643 px | 347 px | −46% |

| 中栏宽度 | 多行双列 | 单行修订 | 差 |
| --- | --- | --- | --- |
| 1040 px | 250 px | 229 px | −21 |

四档宽度零截断。840 px 收益最大，换行消失直接兑现；1040 px 该窗口的多行版本就没换行，只省出板高的自然差；640 px 以下退单列，高度由七个分组行决定。展开 `+N` 时头部 229→249 px，`--head-h` 随 toggle 同步，收起即回。

交互复核（本机生产数据只读）：分组条目点击打开右栏条目列表、失败入口直达失败清单、`+N` 与无正文清单就地展开、组标题 Tab 聚焦出现说明浮层、轮次带贴头部下沿且滚动定位落带下沿。这些结果与生产部署验收分离，生产服务未重启。

## Consequences

- **半高目标在 840 px 及以上宽度达成。** 同数据前后对照：1040/840/640 px 降到旧展开态的 48–54%，400 px 只到六成；相对旧收起态，常驻多约 62 px。单行修订后在同一窗口再降一档：840 px 315→229 px、400 px 513→301 px、640 px 347→281 px，1040 px 只降 21 px。不靠缩小字号或裁掉条目，窄栏差距如实记录。
- **前三以外的工具要点开才可见。** chip 按调用次数取前三，低频工具收进 `+N`，寻找它们多一次点击；失败与中断入口不参与收纳，异常仍常驻。
- **窄中栏统计省略号会藏数值。** 双列区间内左列放不下时整段尾部省略，悬停说明只有口径没有数值；650 px 以下退单列后放得下。数值不被藏进的 `+N`，是直接看不见。
- **删除常驻统计范围后，更依赖稳定分组与按需说明。** 性能不能被读成整个会话的性能，窗口回退有可见标记兜底；覆盖缺口从悬停可见变成工具标题说明的一部分，发现成本略升，换取常驻正文少三行。
- **左右分区减少每组可用宽度。** 工具多、路径长或出现子代理时右列仍会增高；窄中栏退单列，不横向挤压条目。
- **内联展开仍会抬高头部。** `+N` 与无正文清单打开时头部变高，轮次带与滚动让位随 `toggle` 同步；与浮层方案相比少了焦点管理，代价是展开瞬间的布局位移。
- **定位留白变成运行时变量。** `--head-h` 依赖 `syncBandTop` 在重绘、resize 与会话头内折叠开合后执行；新增改变头部高度的入口时若不触发同步，滚动定位会落回旧让位——这是后续改动需要知道的隐式契约。
- **结构组与资源组的显隐边界变了。** 有请求、零调用的会话现在能看到主链/旁路（旧折叠区整体不渲染）；完全没有用量读数的会话不再显示「合计为空」文案。两处都是「有事实才占位」规则的直接结果。
