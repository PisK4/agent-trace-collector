# Agent Note: 版本恢复期间保留旧投影

Status: implemented

## Problem

409 作废时 reader-store 清空正文缓存并落 `invalidated`，中栏按当前缓存投影，整组步骤缩成一条「阅读版本已变化 · 自动重读中」占位；自动重读带回详情与两片增量后，步骤再逐批长回来。正在阅读的历史会话里，这个塌缩与重建既丢位置，也让读者分不清眼前的行属于哪一版。

另一层噪声在成功路径：自动重读换新后组头出现「已更新 · 自动重读换新」，它占一行高度；点进组里清除标记时，下面的行整体上移。标记与它要安抚的跳变互相制造。

## Decision

显示层为每笔请求保留最近一次完整投影：`retainedSteps`，在 [app.js](../../../../web/app.js) 内，不进 reader-store。投影规则集中在 `stepsOf(row)`：

- 详情在手：用当前读取投影，并把结果记为保留投影。
- 详情不在（`invalidated`、`failed` 或 token 更换瞬间的短暂 `reading`）：有保留投影就显示它，组上写 `data-stale`。
- 没有保留投影：照旧显示读取或缺口记录。

`data-stale` 的文案由快照状态决定：「旧版本 · 重读中」与「旧版本 · 重读失败」。标记在组内绝对定位、不占高度，组内首行右侧留出让位，出现与消失都不改行高。旧投影只用于显示：不发请求、不写回 store、不参与证据判定；点中旧行时右栏仍按当前读取态说明（作废时给「阅读版本已变化 · 自动重读中，点击立即重读」，失败时给失败原因）。换会话与显式刷新清空保留投影。

移除组级「已更新 · 自动重读换新」标记，以及 reader-store 的 `updatedSinceSeen` 与 `clearUpdated`。自动重读成功后不再有额外提示：组里显示的就是换新后的当前版本；恢复失败由 `data-stale` 的「重读失败」表达，缺口行仍保留立即重读入口。

提交层在 [trace-dom.js](../../../../web/trace-dom.js) 的 `GroupModel` 上增加 `stale` 字段；`commitGroup` 只在状态变化时写或删 `data-stale`。旧投影的行内容与上次提交相同，因此恢复期间的结构提交不动任何行节点，只更新组属性。

## Alternatives considered

**让 reader-store 返回带过期标记的旧快照。** 这会把「作废记录不作为可用快照返回」的读取契约翻过来，旧证据与新派生并排返回，右栏与工具读取都可能拿到过期正文。保留投影只活在页面显示层，store 的边界不动。

**保留「已更新」成功标记，只把它改成零高度。** 零高度能消除位移，但成功提示仍会在每次自动重读后出现、点击后消失，`updatedSinceSeen` 与清除动作也要继续存在。换新后的行内容本身已经说明版本；正常态不加装饰、异常才出标签，符合前端降噪约束。

**作废后先清空再逐批重建。** 这是改动前的行为，位置与选择在重建过程中反复丢。保留旧投影加旧版本标记让读者停在原处，同时不把旧行冒充当前事实。

## Consequences

收益：409 与读取失败期间中栏不再塌缩，阅读位置、焦点与文字选择保留；旧版本归属由组级标记明说；成功换新不再插入和移除占高度的提示。

代价：页面多一份显示缓存，按当前会话的请求数计，换会话与刷新即清；它保存的是旧投影对象，不是证据。旧行上的工具摘要与来源坐标可能落后于当前读取，点击后右栏按当前状态说明，不会用旧坐标读新正文。自动重读成功时的「请求已变化」不再有独立提示，这是有意放弃的可见性：变化体现在步骤内容里，恢复失败仍有标记。保留投影不承诺内容完整，详情换新、增量还没到齐时，组里显示的是当前版本的半成品，先备齐再提交留给准备阶段。

## Testing

`bun test tests/reader-store.test.ts tests/trace-view.test.ts tests/web.test.ts tests/trace-commit.test.ts tests/http.test.ts` 共 104 项通过（2026-10-27）：自动重读测试改为只断言换新后的状态与 token、不再断言成功标记；投影的缺口文案测试原样通过。`bun run typecheck` 通过。保留投影与 `data-stale` 的 DOM 行为属浏览器合成验收，本轮未执行；真实流量验收需单独授权。
