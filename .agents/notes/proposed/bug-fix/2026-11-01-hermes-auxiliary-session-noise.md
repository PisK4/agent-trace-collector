# Agent Note: Hermes 视觉辅助调用误列会话与技能包装标题修复

Status: proposed

## Problem

### 背景：只开了一个聊天，ATC 却出现多个 Hermes 会话

2026-11-01，项目所有人反馈：最近只在 Hermes Agent 中新开了一条对话并持续聊天，ATC 左栏却出现多个 Hermes 会话。截图顶部两条分别为 20:01 的 12 笔、19:41 的 274 笔，标题都以 `[IMPORTANT: The user has...` 开头；其下还有两条 19:37 的 `Fully describe and explain...`，各 1 笔，以及 GLM 模型名和无标题条目。页面无法说明这些记录与正在进行的聊天有什么关系，看起来像把同一对话拆散了。

这次调查先核对记录归属，再判断是否需要合并。ATC 和 Hermes 原生 SQLite 库均以只读连接查询；正文只在内存中比对，不写入 fixture 或仓库。截图中的七条记录均已定位。下面是当时的观察，不作为实施时固定候选数量。

| 截图条目 | 只读证据 | 可作出的判断 |
| --- | --- | --- |
| 20:01，12 笔，技能包装标题 | ATC 首条用户消息逐字匹配 Hermes 原生 `source=cron` 会话；原生 API 调用数同为 12，消息数同为 28 | Hermes 后台定时任务，属于独立执行 |
| 19:41，274 笔，技能包装标题 | ATC 首条用户消息逐字匹配 Hermes 原生桌面对话；ATC 末笔请求消息数和原生消息记录数同为 567 | 对应用户正在使用的主对话 |
| 19:37，两条各 1 笔 | 请求 74339、74341 都含视觉工具固定提示和一张图；提问分别逐字匹配主对话同秒发出的两次 `vision_analyze` 参数 | 主对话发起的视觉辅助调用，被误列成独立聊天 |
| 19:34，GLM，1 笔缺正文 | 请求 74306 状态 200，`have=6`、`miss_reason=hook_absent`，没有可读正文 | 用途无法确认；该缺失标记只说明没有关联 hook |
| 19:32，GLM，1 笔 | 请求 74303 状态 499，有账本和路由，无 response ID | 一条客户端取消记录 |
| 19:32，无标题，1 笔 | 请求 74302 是失败视觉 hook，耗时约 120 秒，无回复、无 response ID；与 74303 的请求起始时间相差约 28 毫秒 | 两份证据很可能相关，尚不足以证明属于同一调用 |

用户只打开一条聊天，与 Hermes 同时运行定时任务、发起工具内部模型调用并不矛盾。两个大组分别对应主对话和 cron，没有证据证明它们由同一对话错误拆分。缺陷在于视觉辅助请求作为普通聊天占据左栏，以及技能包装把不同执行命名成了相似标题。把所有 Hermes 条目直接合并，会把真实独立的定时任务混入主对话。

原生主对话计 273 次 API 调用，ATC 计 274 笔请求。本次未逐笔核对失败与重试，不把这个差异认定为重复采集，也不将它解释成已完成对账。

### 为什么视觉调用各自成为会话

本机 Hermes 的视觉工具会另发模型请求，在唯一一条 user 消息中放入图片和固定包装 `Fully describe and explain everything about this image, then answer the following question:`。该措辞已与本机安装源码 `tools/vision_tools.py` 的 `_handle_vision_analyze` 对照。它是工具内部调用，不是用户另外打开的聊天。

这批请求没有 Hermes 原生 session ID，路由为各次视觉请求给出不同 magpie `conv`。[会话身份选择](../../../../src/evidence.ts)在 session 缺失时回退到路由 conv，[会话列表](../../../../src/queries/sessions.ts)又按 `conv_key` 聚合，因此两个请求各形成一个单笔组。回退键保留不同请求的证据边界，本身不应为了减少条目而改成一个共享 Hermes 桶。

[Hermes 用途规则](../../../../src/harness/hermes.ts)只识别命令审查与标题生成。[用途编排](../../../../src/harness/purpose.ts)将未识别的可读请求回退为 `unrecognized`、`chat`、`participate`。74339、74341 正是这个结果；会话列表要求全组都是排除主链用途，才标记为旁路供页面折叠。已有旁路展示能力没有缺失，缺的是视觉调用用途识别。

### 为什么不同执行看起来同名

Hermes 把技能加载说明放在 user 消息里，以 `[IMPORTANT: The user has invoked the ...` 开头。[输入解释](../../../../src/input-interpretation.ts)不识别这个包装，[组派生](../../../../src/derive/decision.ts)按可用用户文本首行生成标题，于是主对话和 cron 都显示内部加载提示。

包装后可能带技能正文，也可能带真正的用户指令。整段判成注入并清空，会把实际任务一并丢掉；只删除第一行，又可能把技能正文当标题。修复必须先确认单技能、组合技能与用户指令的结构，再决定哪些文本可作为用户输入。

### 已验证范围与未决证据

现有 `tests/hermes-purpose.test.ts` 两项测试、10 次断言通过，覆盖命令审查与标题生成，没有覆盖视觉调用。合成单消息视觉模板复现了 `chat/participate`；合成技能包装复现了前缀原样保留。这些是当前缺陷的复现，不代表新规则已实现或修复通过。

[hook 关联](../../../../src/hook.ts)只认可核验的 response ID。19:32 两份证据都没有该 ID，当前不能自动合并；19:34 请求没有正文，不能根据同模型或相邻时间认定它也是视觉调用。缺 hook 的成因与主对话调用数差异继续保留为未决项，不作为本提案必须消除的已确认缺陷。

### 与已有记录的关系

已检查活动 note 树。[Hermes 用途识别](../../implemented/feature/2026-10-27-hermes-purpose-recognition.md)继续持有审查器、标题生成器及其优先级，本提案增加此前未覆盖的视觉用途，不取代这两条规则。[Hermes 接入提案](../feature/2026-10-27-hermes-agent-integration.md)继续持有其历史用途升级、宿主预算实验与真实窗口对比的未完成范围，本次截图暴露的视觉与技能包装问题由本文持有。两篇保留活跃并互链，无须归档或拒绝旧记录。

[Harness 静态扩展](../../implemented/architecture/2026-10-26-harness-semantics-adapters.md)继续约束专属用途和共享输入解释的归属。[空 session 身份修复](../../implemented/bug-fix/2026-10-27-empty-session-identity-migration.md)解决的是空串身份，本次不反转其回退规则。[hook 投递诊断](../../implemented/feature/2026-10-27-hook-delivery-diagnostics.md)继续持有投递与关联缺口的分层诊断；本文不将未关联直接归因于投递丢失。

## Proposal

先修有直接证据的两处解释错误，复用现有旁路折叠和标题生成流程。首轮不改会话键、不新增持久化父子关系，不建设新的 Hermes 采集通道。

### 视觉辅助调用识别

在 [Hermes adapter](../../../../src/harness/hermes.ts)增加视觉辅助用途判定，暂定规则 ID 为 `hermes.vision-analysis.v1`，用途为 `vision-analysis`、`chain='exclude'`、`modelTitle=null`。命令审查与标题规则保留既有优先级；通用分派、结算和页面不新增 Hermes 品牌分支。新用途名称实施时按[词汇表](../../../../GLOSSARY.md)准入规则登记。

判定限定为已登记 Hermes 标签下的已知视觉模板，并结合单 user 消息、实际图片内容、无工具声明等请求形状。文本模板必须位于实际用户文本块开头，不能对正文任意位置做包含匹配。回复成功、回复措辞和 HTTP 状态不作门槛；缺回复但请求可读的失败视觉调用也应识别。

先核对现有 [PurposeView](../../../../src/semantics.ts)和[用途取数](../../../../src/request-purpose.ts)能提供哪些必要事实。视图若缺图片形状，只增补有界的图片存在事实，复用块引用读取，不把图片字节或整条请求暴露给 adapter，不为判定重新恢复全部消息。损坏或不可读时沿用既有缺失、保留和错误语义。

独立视觉组识别后，复用列表 `bypass` 标志和页面旁路折叠。与主请求同组时，视觉调用排除祖先候选，不改变真实主对话的链与工具配对。正文、原始调用、失败、费用和用量全部保留。没有可靠父会话证据时，旁路记录仍保持独立身份；不能把成功折叠描述为已恢复父子归属。

首轮只覆盖本次已核对的图像模板。视频、压缩、其他辅助调用和未知 agent 标签不凭近似措辞扩展；遇到新的真实形状，另补证据和反例。

### 技能包装与可用标题

在[共享输入解释](../../../../src/input-interpretation.ts)处理已核对的技能加载格式，保留 `original`、存储对象、块哈希和语义指纹。规则按完整结构识别，不以 `[IMPORTANT:` 作为通配删除前缀，也不因一条消息含技能包装就把整个请求判成旁路。

至少区分仅技能注入、附带用户指令的单技能、组合技能三种情形。去除可证明属于加载提示和技能正文的内容；存在可明确提取的用户指令时，保留该指令供标题和输入摘要使用。没有可靠正文边界时不猜测、不截取技能正文冒充用户任务，沿用现有其他标题候选或模型时间回退。

包装定义继续遵守共享解释的无 agent 门控约定。实施前用相同文本在 Hermes、其他标签、未知和空标签下验证，并补用户引用的反例；不借这次修复收紧既有共享格式。若证据表明只能安全地按 agent 门控，应另写适用范围与代价，再评审，不能悄悄改变共享规则。

cron 是独立执行，本轮只消除内部包装造成的标题失真。ATC 当前没有足够来源事实把它可靠标成定时任务；本提案不根据时间、模型或用户首句猜测来源，也不为它增加未经采集支持的常驻标签。

### 历史版本与交付

用途分类和输入解释均有可观察行为变化。实施时在最新基线上提升 `PURPOSE_VERSION`，并核对同步组与切片组持久化标题、摘要的算法版本，分别更新受影响算法；不把 `derive_version` 的更新次数当作算法版本。不依赖普通 tick 自动重算 clean 历史行。

历史按[显式 rebuild](../../../../docs/operations.md#rebuild)交付。实施前只读枚举候选请求与实际 `conv_key`，范围包含有正文的视觉组、含技能包装的主对话和 cron，以及未知 actor 的 hook-only 视觉行。重建以整个键为作用域，报告同键其他 agent 和用途的影响。不可读、缺证据、保留旧版本、错误终态与剩余项分别计数；已有入口不能覆盖的范围明确拒绝或补齐，不用直接 UPDATE 用途和标题列绕过结算。

重建只修用途和派生，不改变 `conv_key`、原生 session 或来源身份。真实库操作按[运维手册](../../../../docs/operations.md)安排维护窗口和备份，代码交付、合成验收与真实库重建分别记录。本提案本身不执行任何写库、配置调整或服务重启。

跨文件实现走 worktree 分支，按用途规则、输入解释和历史升级各自的回归范围推进；实施后将现行规则写入架构设计、维护步骤写入运维手册、验收结果写入验收记录，本文只保留依据与取舍。

2026-11-01 视觉辅助识别与技能包装解释已交付，实际决定、否决项与代价见[实现记录](../../implemented/bug-fix/2026-11-01-hermes-vision-title-noise.md)；显式重建的真实库执行与真实列表复核仍按上文范围待办，不因代码交付而关闭。运维手册无需新增命令：重建入口已同时覆盖用途升级与标题重算。

## Alternatives considered

**把所有 Hermes 请求合并为一条会话。** 截图已经包含独立 cron，合并会破坏真实执行边界，也会把并行对话和子代理混在一起。

**按时间、模型名或相似标题绑定视觉请求与主对话。** 并发工具调用、定时任务和相同模板都可能重叠；19:32 两份无 ID 证据说明时间接近仍不足以确认同一请求。首轮只排除辅助用途，不猜父子关系。

**在页面隐藏所有单笔或缺正文条目。** 单笔可能是真实新会话，缺正文也是需要保留的采集事实。由页面另做模板匹配还会重复服务端语义。

**把技能包装所在消息整段丢弃，或只删第一行。** 前者可能丢失实际用户指令，后者可能让技能正文进入标题。必须按已证实结构提取可用文本。

**先建设原生 session 与调用 ID 传递，再处理本次问题。** 原生身份是可靠关联的后续方向，但跨 Hermes、magpie 与 ATC 的接入成本更高；当前已有请求正文足以修正视觉用途和标题解释。身份接入不能作为延迟修复的前置条件。

**部署后直接改写历史派生列或删除噪音记录。** 会掩盖旧版本依据，或丢失真实调用和费用。历史使用显式重建，缺证据保持未知。

## Acceptance criteria

### 合成回归

- 使用合成图片和问题，经生产正文存储、`readPurposeViewTx` 与结算路径证明已知图像模板命中排除主链用途；同时覆盖成功、缺回复、未知 actor 的 hook-only 行。不把手工构造 matcher 视图作为唯一验证。
- 普通 Hermes 对话、正文引用模板、多轮主对话包含旧视觉内容、无图片、存在工具声明、非 Hermes 及未知标签均有反例。规则变体和指纹优先级的预期写清，不以放宽包含匹配补漏。
- 两个无 session、不同 conv 的合成视觉请求保持两个独立证据身份，列表均标旁路并默认折叠；普通单笔会话继续显示。相同 conv 中混合主请求与视觉调用时，主会话仍显示，前驱、增量和工具配对正确。
- 对单技能、组合技能、纯注入和附带用户指令的格式，标题与摘要不取内部包装或技能正文；可明确提取的实际用户指令完整保留。用户引用、普通 `[IMPORTANT:` 内容、不完整和未知格式不被宽泛清空；原文、块身份和共享标签行为保持约定。
- 旧版 clean 行部署后不冒充新结果；显式重建后用途和标题按目标版本发布。不可读行保留真实旧依据；无 actor 的视觉行可以结算用途但不凭空确认身份或创建派生组。
- 无 response ID 的 hook 和账本继续保持未关联，不因本次降噪强接。请求、原始证据、正文、别名、用量和费用在重建前后守恒。

### 真实复核与完成条件

- 部署前冻结统一截止时点和候选范围，按可读性、身份状态、用途与实际版本报告分母；不用本次截图笔数代替实施时范围。
- 完成显式重建后，74339、74341 如仍有可读正文，应显示视觉辅助用途并进入旁路区域；74302 如仍可读，也应识别其视觉用途，但保持归属未知。历史已回收时报告保留或拒绝，不伪造恢复。
- 主对话与 cron 保持各自会话身份，内部技能提示不再成为其可用标题；没有可提取任务时允许已有回退，不承诺两个标题一定不同。
- 74303 与 74306 的关联缺口保留真实状态。真实复核不得宣称解决无 ID 关联、恢复缺失正文或解释 273 与 274 的计数差异，除非另取得可核验依据。
- 运行能对本次回归失败的最窄测试、类型检查和提交前 `verify:notes`。代码验收与真实流量验收分开，只有合成通过不能关闭真实列表复核。

## Risks

视觉模板由上游维护，措辞或消息形状变化会退回未识别；真实用户也可能提交相同模板和图片。组合条件与反例只能限制误判范围，不能把文本指纹当身份凭证。错误排除会隐藏真实聊天，实施时宁可保留未知，不扩大通配规则。

技能格式可能将说明、技能正文与用户指令放在同一消息中。边界提取错误会丢任务或污染标题；完整未知格式必须有保守路径，不能以消除重复标题为由任意删文本。共享规则还会影响其他标签，跨标签回归属于本次必要范围。

历史重建会读取正文、重算长组并产生写入负载，与[采集期间交互延迟提案](2026-11-01-collection-interactive-latency.md)涉及的长同步任务风险重叠。实施前先报告候选规模并安排维护窗口，不把大规模在线重建作为普通部署副作用。

首轮交付后，ATC 仍可能显示主对话之外的 Hermes 定时任务和未知记录。视觉请求被折叠也不意味着已找回父会话。可靠来源与父子关系需要采集链路提供原生事实，作为后续范围单独评审。
