# Agent Note: 首页超时中的重复宽表读取

Status: proposed

## Problem

[生产只读排查](../../../../docs/acceptance.md#生产首页超时排查只读2026-11-06)复现首页 15–20 秒无首字节。当前实例 145 次监控采样有 69 次失败；主线程采样持续在 SQLite 读取，pending 任务单次最长约 21.8 秒。hook 缺席候选沿时间索引回表检查历史请求，stats 的正文状态分组也扫描带骨架的请求表。写事务很短不能证明候选准备读取很短。

## Proposal

保持 v14，优先让 hook 缺席候选显式匹配现有部分索引；stats 从覆盖索引统计非 available 状态，再由同快照的总数计算 available。保留缺席判定、NULL 比较、迟到合并、统计字段与缓存新鲜度。

监控日报只对成功且带实例标识的样本比较实例变化。失败样本继续参与失败与告警判定；没有可比较标识时报告未知，不宣称进程稳定。

[hook 缺席语义](../../implemented/bug-fix/2026-10-25-hook-absent-body-aging.md)和[监控批次决策](../../implemented/bug-fix/2026-11-04-monitoring-health-batch-fixes.md)仍然有效，本提案仅补足它们的读取成本与报告缺口，不替代或归档原记录。实施与发布顺序见[计划](../../../../docs/superpowers/plans/2026-11-06-homepage-timeout-repair.md)。

## Alternatives considered

**立即新增专用索引并升级 schema。** 当前等价谓词已能使用既有索引，先量测完整同步任务；只有候选回表、反查或排序仍无法满足验收时，才评估存量建索引的成本。

**缩短等待队列或调整重试策略。** 现场只有 7 个带 response ID 的等待项会查询候选，当前证据不足以支持改变迟到合并、歧义重试或孤儿 TTL。

**改为延迟缓存或新增 Worker。** 放宽 stats 新鲜度会改变可观察行为；新增执行位置也扩大了查询一致性与生命周期责任。先消除重复宽表读取，再用持续窗口判断是否需要这些方案。

**性能越界立即回退旧版。** 旧版已存在约 48% 的采样失败。正确性错误、启动失败或明显恶化必须回退；只有残余长尾而整体改善时应保留证据继续定位，不把退回已知故障版当作恢复。

## Acceptance criteria

- 实际生产函数的查询计划回归锁定现有部分索引与覆盖索引，空命中与满批保持原语义。
- 合成宽行实验、窄测试、类型检查和 notes 门禁通过；实验门槛与做法见[实施计划](../../../../docs/superpowers/plans/2026-11-06-homepage-timeout-repair.md#task-4整合显式负载与文档)。
- 停服备份后部署，持续 HTTP、自然流量、monitor 恢复和浏览器验收分别记录，不用重试覆盖首次失败。

## Risks

部分索引仍可能随 pending 历史增长而变慢；本批不承诺任意规模常数时间。同步任务中的其他摄入、费用与派生操作仍可能产生长尾；查询修复通过不等于整机可用性已恢复。本批不执行 schema 迁移、历史正文订正或重建。
