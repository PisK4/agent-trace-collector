# Agent Note: 上下文矩阵布局与点击明细

Status: proposed

## Problem

上下文矩阵树状图应帮助阅读者判断本笔请求由什么构成，以及哪个文件、工具结果或对话片段占用了较多上下文。当前图形的面积、标签和明细入口没有形成完整的阅读路径：低占用请求留下大块空闲区域，文字错位并越过色块边界，较宽的右栏仍只展示少量合并块，点击色块也无法阅读内容。

2026-10-26 的用户反馈样本中，提示总量为 231,866 tokens，窗口为 1,048,576 tokens，实际占用约 22.1%。图形采用 `share^0.35` 分配已用区，导致已用内容占约 59% 的面积、空闲区占约 41%。图中的面积既不能直接读作窗口占用率，也没有把空间充分用于区分已用内容。文件引用占提示总量约 55.3%，却主要呈现为前端再次合并的另外 23 项。

同一样本的第 1 轮为对话类别中的 55,056 tokens；另外 14 项属于文件引用，是上游合并的 18,418 tokens。两者缺少可直接查看的内容，容易被理解成两组轮次。只读核对时该请求正文状态为 pending，没有骨架或消息块，因此当前只能解释统计，无法从 ATC 展开正文。这是本次快照中的覆盖缺口，不能推广为所有请求都缺正文，也不能据此推断采集失败原因。

### 已确认的实现问题

| 位置 | 当前机制 | 后果 |
| --- | --- | --- |
| [矩阵输出](../../../../web/context-map.js)，`contextMapHtml` 的文字坐标 | 矩形横坐标带 `%`，文字横坐标遗漏 `%` | 标签被放到左侧几十像素，无法对应色块 |
| 同函数的 `clipPath` | 裁剪只绑定在矩形上，文字在裁剪之外 | 名称、路径和数值能够盖住其他块 |

| 同文件 `floored` 与窗口分区 | 抬高小值面积，并对已用区做非线性变换 | 面积与 token 比例不一致 |
| 同文件 `itemLabel` 与 `contextRowsHtml` | 上游合并条目、前端合并块都显示另外 N 项，明细跨类别混排 | 合并的来源、范围与分母不易判断 |
| [读数构成区](../../../../web/rail-facts.js)，`usageFoldHtml` | 构成条、矩阵、图例、条目列表重复呈现相邻信息 | 视觉密度增加，点击路径仍然缺失 |
| [矩阵测试](../../../../tests/context-map.test.ts) | 断言存在百分比坐标和裁剪定义，没有核对文字实际使用；多宽度测试绕过固定宽度渲染入口 | 几何断言通过，真实显示仍然错误 |

### 与现有决策的关系

Supersession check：本提案拟部分取代[读数页上下文分布 treemap](../../implemented/feature/2026-10-26-context-distribution-treemap.md)关于非线性空闲区、面积下限、标称宽布局、仅原生 title，以及暂不提供正文点击的决定。类别来源、七类颜色身份、未知类别保名、只读查询与不覆盖上游分类的原则继续有效。原 note 保持 implemented；本提案获准并交付前不改写现行机制，也不归档它。

[前端降噪约束](../../implemented/process/2026-10-24-frontend-denoise-standing-rule.md)继续适用。新增内容优先放在点击后的明细中，主图不堆叠提示标签。本提案不改变[轮次两端阅读](../../implemented/feature/2026-10-25-turn-pair-reading.md)的结算判据；上游上下文轮次与 ATC 结算轮次分别展示，不能复用同一个轮次编号作为正文定位依据。

## Proposal

将矩阵改为已用上下文的构成图，使用全部可用绘图区表达类别和条目；窗口容量与占用使用独立读数。所有内容块、图例和列表项提供点击明细，单项直达正文，集合先展示其成员。统计继续消费已采集的 Magpie 分解，正文从 ATC 保存的脱敏请求中按需读取。

本次完成目标包含可读布局、准确范围的点击、正文缺失时的统计明细，以及有正文请求的实际内容阅读。只增加 hover 或把点击统一跳到整份原始 JSON，不能视为完成。

### 需求与范围

1. 图形占满容器可用面积，块面积表达已用内容中的相对份额；空闲容量不再占用矩阵面积。
2. 名称和数值各归属一个可辨认的块，文字不相互覆盖，右栏变宽后能够呈现更多有意义的明细。
3. 点击前能区分所属类别；点击后能回答这一块包含什么，以及数字来自哪里。
4. 已有条目的名称和数值长期可读；正文未取得、部分保存、已回收、损坏和协议不支持分别表达。
5. 保持真实正文在本机，不读取磁盘上的当前文件替代历史输入，不依赖 Magpie GUI 或最近请求的内存缓存。
6. 不新增第三方依赖，不预建通用图表框架，不在本次加入会话趋势、评分、矩阵与网格切换或动效系统。

### 面积、层级与排序

矩阵固定两层：类别和类别内条目。矩阵几何分母为正值类别之和，提示总量仍显示上游报告值。分解之和与报告总量不一致时，展示差异并说明构成比例的分母，不补造一个未知类别来凑数。缺少有效正值类别时不渲染空矩阵；不能把未知、非法或负数当作零值事实。

删除 `share^0.35` 与 `TILE_FLOOR` 的数值抬升。布局先按真实值分配面积，绘制时扣除固定像素间隙；验收分别检查扣间隙前的面积比例与扣间隙后的可见边界。小块不靠扩大数据值获得点击面积，改用成员合并、名称隐藏和等效列表入口。

类别保持稳定的语义次序，避免请求间因大小变化而重排全部类别；类别内条目按 tokens 降序，同值以稳定身份定序。轮次在矩阵中允许按大小排，明细阅读按输入顺序排。稳定身份由请求读取依据、类别、tag 和完整名称组成，不使用 basename 或屏幕下标；同名同 tag 原本已聚合的条目保留多片段语义，不假装单个文件版本。

沿用两层 squarify，按实际容器尺寸计算布局。尺寸观察只负责提供宽高，布局仍为纯函数；折叠后宽高为零时延后，首次展开补算。批量处理尺寸通知，只在有效尺寸变化后重绘，不触发正文读取。卸载、切请求或替换容器时解除观察，防止重复观察和重绘循环。

高度采用受限的宽高比，初始候选为 `clamp(160px, 容器宽度 / 2.4, 240px)`，通过 280、340、592px 容器的视觉验收调整后固化。高度不随条目数无限增长。主图显示有限数量的条目；拆分预算以实际面积与最短边为依据，不沿用固定标称宽下的面积阈值。类别过小时保留类别块，类别内碎项合成一个成员集合，点击后可逐项读。

布局提交实现定稿（2026-10-27）：合并阈值固化为 item 布局面积 950px²（≥2 块才并）、类别最短边 24px（不足整类一块），绘制间隙 2px，容器高度按 `aspect-ratio:2.4` 夹在 160–240px；文字取舍按实测渲染尺寸判定——高度不足 44px 隐藏数值行、不足 24px 或宽不足 47px 全部隐藏，不做像素级字宽估算。另有一处提案未预见的缺口随本提交补上：item 清单不覆盖类总量时（上游只逐项列大头），差额渲染为显式余量块参与该类布局——若按原方案只摆已列 item，几何面积会平白多出一块；几何因此改按类别守恒断言，逐块 token 合计与 parts 合计的不一致如实可见。

### 标签、颜色与主区降噪

优先采用绝对定位的 HTML tile：保留纯布局计算，渲染原生 button，名称和值使用正常文本布局、单行省略和容器裁剪。这样能共用键盘操作、焦点、触摸点击与文本溢出规则，避免继续维护百分比 SVG 坐标和文字宽度粗估。若实施评审保留 SVG，必须对整个 tile 标签组裁剪，并提供等效按钮语义；两种实现不并存。

有空间时显示文件 basename、工具名或带类别含义的轮次名称；完整路径放在明细中。名称优先于数值，不同时塞入目录、token 数和百分比；文字不足以容纳时依次隐藏次要值和名称，完整数据仍可在列表读取。上游轮次标为上下文第 N 轮，并在明细中解释它包含的内容；不把它显示成 ATC 已结算的命令到回复轮次。

类别颜色保持身份稳定，不能随排序变化重新配色。尝试以浅色类别表面、适度边界和主题文本色替代大面积高饱和填充，避免用白字覆盖所有类别；高亮与键盘焦点不能只靠微弱亮度变化。对候选亮暗配色分别运行 dataviz 色彩校验，记录结果后再确定最终值，不以当前七槽已存在为由跳过文字对比度检查。

移除矩阵上方重复的构成色条，保留类别图例、条目列表和总量/窗口/占用读数。图例也作为类别明细入口。类别、单项与聚合块的身份在明细标题中写清，不向主图添加成排二级标签。占用阈值仍按现有读数语义处理；本次不顺带重定义异常阈值。

### 点击明细的范围

点击后打开居中弹窗，矩阵与列表留在原位：滚动位置、列表展开与所选块不因查看明细而改变，弹窗头部标明所属请求身份与所选范围。弹窗的尺寸、结构与关闭方式以 2026-10-26 已获用户认可的原型为参照（宽度上限约 860px、内容区滚动、Esc、关闭按钮与点击遮罩三种关闭途径，关闭后焦点回到触发控件）；不照搬其全屏布局、网格切换与动效。切换请求、会话或阅读依据变化时清除不再成立的弹窗内容，晚到的正文响应不进入已切换的弹窗。图形和列表调用同一个选择动作，按相同范围返回结果。

| 入口 | 默认展开范围 | 阅读行为 |
| --- | --- | --- |
| 单个条目 | 本请求中该条目的全部已确认片段 | 默认展开，重复读取或同名工具结果按出现顺序列出 |
| 前端为排版合并的块 | 该块持有的成员集合 | 先列成员；若其中含上游合并项，保留这个成员自身的覆盖限制 |
| 类别块或图例 | 该类别全部已保存条目 | 逐项展开；恢复出的附加条目与已采集统计分开表达 |
| 上游 `more` 或 `turns` 合并项 | 已确认的聚合成员；无法确认时显示所属类别并明确范围 | 不把整个类别伪装成聚合项的精确子集 |
| 只有统计、没有正文的条目 | 名称、类别、上游 token、比例、聚合数量 | 显示当前正文缺口，保留统计与返回能力 |

列表中的显示全部改为展示已保存明细条目的数量，避免让 53 个条目被理解成 53 个原始文件或调用。条目应能识别类别；聚合项名称使用其余文件 N 项、更早上下文 N 轮等带对象的短名称。前端合并成员数与上游 n 分开保存，不能相加后宣称已知原始条目总数。

悬停与键盘聚焦显示相同的轻量摘要：类别、名称、上游 token、占提示总量的比例；聚合块补若干成员与余项数。复杂正文只在点击后读取。摘要不能截断关键数值，也不能成为读取数据的唯一途径。小块提供同页、相同功能且满足目标尺寸的列表按钮；不扩大色块导致面积失真，也不让相邻透明点击区互相覆盖。

### 统计与正文对应

统计由 `prompt.parts` 持有；正文对应是单独的只读解释，不能回写 `parts_json`、改变提示总量或冒充采集时 Magpie 的精确分类。现有条目仅有 `name/tag/n/tokens`，没有消息位置；不能按名字找第一处命中，也不能用矩阵条目下标读取重建列表。

正文索引至少返回原始请求字段或消息序号、内容块路径、片段顺序和覆盖结果。优先复用[协议形状表](../../../../src/protocol-shape.ts)、[正文分页](../../../../src/protocols.ts)及现有能力解释。工具定义读取本笔请求的 tools/functions；文件读取、工具结果通过本笔输入中的调用与结果 ID 建立对应，扫描范围是该请求携带的上下文，不局限于本笔新增消息或最新回复的工具配对表。多个相同路径、同名工具或同一调用的多个结果全部保留，不取首项。

系统提示、记忆、技能与对话在同一文本块内可能被 Magpie 拆分。完整系统消息不能直接冒充其中某一类别的精确内容。解释器能确认片段范围时展示片段；只能确认承载消息时展示原始来源，并明确尚未分离的范围。未知包装或格式不得通过新的 harness 门控改变现有输入解释规则。

正文对应结果区分已定位片段、仅定位到来源、存在歧义和正文不可用。对于上游合并项，先尝试用完整正文建立候选清单，再核对已保存条目的身份、分组规则与覆盖情况；无法证明补集时不标记为精确恢复。正文完整只证明保存覆盖，不能自动证明分类对应完整。对话轮次必须使用单独、带版本的上下文解释规则，禁止借用 ATC 的轮次结算结果凑编号。

同一片段若因多文件 shell 输出而对应多个文件，标明共享来源，不能复制后宣称每个文件都具有独立逐文件 token 实测值。不能恢复的供应商持有历史、密封推理和图片均使用其实际可读性，不生成虚构正文。带 `previous_response_id` 的请求仅展示本笔保存的输入及声明的历史引用，不把该引用展开成已保存完整历史。

若为了完整七类点击引入与 Magpie 对齐的提取逻辑，应限定在单个只读解释模块，记提取版本、来源位置和已支持规则；用合成样本核对其与固定源码的分组关系。该模块只负责正文归属，不重新发布权威 token 分类。按名称加宽松文本搜索只能作为明确标记的来源候选，不能成为全功能交付的替代品。

### 按需读取、失效与容量

打开矩阵只使用现有统计；点击后先取条目目录，展开某项再取片段。优先复用既有请求阅读依据与正文页缓存；需要专用查询时，接入同一只读连接、认证、输入校验与读取一致性机制。精确端点和参数由实施阶段在[架构设计](../../../../docs/architecture-design.md)统一登记。

首次构建正文目录可能需要扫描本笔请求，需限制每次处理的消息数、解压字节与返回字节，并在步骤间让出事件循环；扫描未完成时如实返回继续位置和部分覆盖，不在 HTTP 请求中同步解压全会话。后续片段按来源位置读取；长文本分段呈现，不能只在前端分段而后端一次返回整类正文。目录元数据与正文分别测量，不能用少量名称响应掩盖后台全量解压。

目录查询实现定稿（2026-10-27，随目录查询提交）：端点 `GET /api/requests/:id/context-item`，`if_reading` 必填、`kind` 必填、`name/tag/cursor` 可选，解释规则版本 `CTX_EXPLAIN_VERSION=1`。定位放弃「扫描本笔请求重建候选清单」：results/files 用 `tool_call` 配对表列（结果请求、结果序号与内容块路径）零消息块解压，files 再按调用参数路径与条目名对齐、无对齐降级列全部结果块并说明；tools 读骨架 `tools`/`functions`；system 合并顶层字段与 role=2 块；chat/memory/skills 给承载块并说明片段未分离。骨架只在响应头需要时解压一次；每响应最多 80 条，keyset 游标绑定请求与类别，跨请求或跨类别复用一律拒绝；类别白名单先于正文状态，未知 kind 返回 `unsupported`，正文缺口按事实返回。上游合并项「用完整正文重建候选清单再核对覆盖」的路线未启用，重开条件是承载块说明不够用的真实案例。

所有读取都绑定请求正文修订、投影依据及解释版本。切请求或返回时取消请求或忽略晚到响应；读取期间发生正文回收、关联变化或重解析时，沿既有阅读一致性约束拒绝混合版本并允许重新打开。缓存有上限，只在当前阅读生命周期保留，失效后不靠旧缓存继续呈现已回收的正文。

初次实现不新增 schema，不复制正文，不运行 backfill，不为缺正文的历史请求启动隐式回填。若来源位置持久化确有测量收益，再独立评审版本、预算、回收与显式重建。本样本的 pending 原因另查，不以本 UI 提案授权补抓 Magpie 内存或重启生产服务。

### Magpie 参考与取舍

以下静态结论使用 `开源源码@magpie-3173440ca`，来源等级为版本锁定，只判定该提交的实现，不证明本机应用启用相同行为。

| 上游机制 | 本提案的采用方式 | 依据 |
| --- | --- | --- |
| 读取真实宽高并在尺寸变化后重排 | 采用容器尺寸观察，布局计算与 DOM 分离 | `context.js:527–548,591` |
| HTML tile、溢出省略、窄块隐藏文字 | 采用正常文本布局和选择性标签 | `context.css:354–369` |
| 单项直接展开，类别先列条目 | 采用；前端合并块优先显示精确成员 | `context.js:1016–1106` |
| `more/turns` 与前端 rest 点击均打开整类 | 保留为无法确认聚合成员时的显式退化，不宣称精确子集 | `context.js:515–521,1041–1043,1093` |
| 从请求体重建全部条目，不受摘要 24 项限制 | 借鉴正文索引方式，使用 ATC 持久化的脱敏正文 | `prompt_text.go:98–156` |
| 重建条目重新缩放、排序，索引不等于卡片索引 | 不跨列表复用下标；不要求重建细项之和与已保存聚合统计强行相等 | `prompt.go:216–236,306–342`；`prompt_text.go:111–155` |
| 原生数值之外显示聚合成员前五项 | 用轻量摘要解释块内容，点击承载正文 | `context.js:463–489` |
| 最近 10 笔、单笔 32 MiB、总计 64 MiB 的内存正文 | 不引入该保留方式，不调用其 GUI 接口作为历史正文后端 | `prompt_text.go:24–59` |
| 密封内容显示不可读，图片按是否带内联数据处理 | 保留不可读状态，不把占位信息当文本正文 | `context.js:998–1012` |

来源等级定义：版本锁定指针对特定客户端版本或特定源码快照逆向得到的实现事实，包括本地文件布局、落盘结构与源码控制流；实测指受控采集下可复现的行为，未被任何官方文档承诺。本文的 Magpie 表为版本锁定；用户反馈样本与 ATC 只读统计为 2026-10-26 实测；全部拟议方案均为设计建议，不代表上游承诺。

## Alternatives considered

**只修百分号和裁剪。** 能消除最明显的文字错位，但空闲区、固定宽度、二次合并和无法点击仍然存在，不能完成本次需求。可以作为首个独立修复提交，不能作为本提案最终验收。

**把完整窗口继续放进图里，改用线性面积。** 比非线性面积更忠实，但本样本约 78% 的面积将用于空闲容量，明细更难读。矩阵的任务是解释已用构成，容量由独立读数承担，因此不采用。

**通过最低面积或最低宽度放大每个小类别。** 提升点击便利，却改变了比较依据。改用同页列表按钮提供等效操作；合并时只合并真实值，不能给零值补面积。

**用排序条形图完全替代矩阵。** 条形长度更适合精确比较；矩阵更紧凑地表达类别与条目的两层包含关系，也是用户指定的阅读入口。本次保留矩阵，列表提供精确数字和条形比较，不再添加第三种可切换图形。

**改用 resquarify 或固定空间布局保持每次切请求的位置。** D3 文档明确，resquarify 可保持前次邻接关系，但后续更新可能形成次优布局。ATC 主要切换不同请求，不是持续播放同一树；本次采用稳定身份和确定性排序，不引入跨请求布局历史。实际视觉验收若证明跳动妨碍比较，再评审该算法。

**为每个类别固定比例栏宽，追求位置不变。** 会让面积失去比例意义。保留颜色身份和类别顺序，几何仍由值决定。

**直接请求 Magpie `/api/context/text`。** 上游接口只服务同一 GUI 持有的近期内存正文，不能覆盖 ATC 的历史请求，重启也会失效。不作为本次正文数据源。

**从本机文件系统打开同名文件，或从会话其他请求补正文。** 当前文件内容不等于当时输入，其他请求也未必具有相同版本或片段；无法用来证明本请求消耗了什么。不采用。

**复算一套 token 构成并覆盖历史统计。** 提取版本、脱敏位置和分类启发式可能不同，容易产生两份冲突事实。仅计算带覆盖状态的正文对应，不覆盖采集统计；新增推算量必须明确区分，不能悄悄填入旧读数。

**照搬 Magpie 的全屏弹窗、网格切换与滚动动画。** 2026-10-26 用户确认采用 Magpie 式居中弹窗，采纳的只是弹窗这一交互形态：全屏布局、网格切换与滚动动画不进本次范围，弹窗尺寸与关闭方式以已认可的原型为准。此前「复用右栏面板」的方案随这一决定废弃。

## Acceptance criteria

### 布局与语义

- [ ] 在 280、340、592px 的实际容器中铺满可用绘图区，扣除间隙前的矩形面积按有效正值类别与条目守恒；无空闲矩形、无最小值抬升、无负宽高或越界。
- [ ] 容器从窄变宽、拖拽右栏、折叠后展开均按新尺寸重新布局；小项选择与标签可见性来自实际尺寸，不仅测试 `tilesOf` 的参数。
- [ ] 名称、路径与数值在所有宽度及亮暗主题下无跨块覆盖；最大文件能以文件名辨识，不被相同目录前缀占满。
- [ ] 构成分母、窗口占用分母与缺失值分别正确；窗口未知、超窗、零总量、正值分解与总量不一致、retained/missing 旧结果均有测试。
- [ ] 上游 `more/turns`、前端合并集合与类别块可以区分；界面不会把文件项数显示成轮数，也不把保存条目数说成原始调用总数。

### 点击与正文

- [ ] 每个内容块和图例都有点击入口；单项默认展开，集合准确限定成员；弹窗打开期间矩阵与列表的滚动位置、展开状态保持不变。前端合并集合包含上游合并项时正确嵌套表达。
- [ ] 图形、列表、键盘与触摸使用同一个选择范围；Enter/Space 打开，Escape、关闭按钮与点击遮罩关闭，焦点能够回到触发控件。小目标具有满足尺寸要求的同功能列表按钮。
- [ ] 合成数据覆盖工具定义、文件读取、工具结果、系统提示、记忆、技能、上下文轮次；重复路径、多次结果、多文件共享来源与跨类别文本不被首项匹配吞掉。
- [ ] 上游合并项能恢复时展示带依据的明细；不能确认补集或轮次映射时不伪造精确成员。恢复细项的取整差异不通过篡改采集数值掩盖。
- [ ] pending、partial、evicted、损坏、不支持协议及 `previous_response_id` 场景保留统计与可解释缺口；密封推理不生成正文，图片不可用时不标成空文本。
- [ ] 读取只用当前请求已保存的脱敏内容，不读取同名本机文件，不向 Magpie 请求近期正文，不混入本次回复作为已发送的上下文。

### 容量与交付

- [ ] 无点击不预读全部正文；目录扫描、片段读取与长文本返回均有消息数/字节上限及继续位置。合成大请求测试记录实际解压次数、返回字节与事件循环可继续服务的证据。
- [ ] 切换请求、关闭明细、正文回收或关联变化时，晚到响应不会污染当前面板；错误可重试，缓存受预算与读取依据约束。
- [ ] 使用生产同一页面和合成数据完成浏览器截图及交互检查；合成验收、真实统计核对与真实正文验收分开记录。没有截图时不得把 DOM 断言报告成视觉通过。
- [ ] 只跑会因本次回归失败的最窄测试，并执行类型检查、note 门禁和新增本地链接检查；本提案文档完成不代表功能验收通过。
- [ ] 实施时在[架构设计](../../../../docs/architecture-design.md)登记最终阅读机制，在[验收记录](../../../../docs/acceptance.md)登记执行结果，更新被部分取代的 note 双向链接及事实；不把拟议接口提前写成已交付行为。

## Risks

正文已保存不等于分类可精确复现。Magpie 的原始分类、脱敏后的文本和 ATC 的解释规则可能不同；尤其是一个文本块内的记忆/技能拆分、供应商持有历史与上游合并成员，需要明确覆盖结果。若实现只能显示来源候选，应在交付范围中保留未解决项，不能以所有块都能打开同一个正文面板宣称完成。

精确面积会使小类别更细，宽高比与合并规则需要真实视觉判断。通过选择性标签和等效列表补足，不用数值放大掩盖这一代价。HTML tile 是推荐实现，采用前需验证其布局、焦点和大条目量下的开销。弹窗原型已获用户认可（2026-10-26，交互方向与弹窗结构），生产实现的浏览器截图与移动端视觉检查仍未执行，不能据此宣称视觉验收通过。

按需正文索引仍可能产生同步解压尖峰。索引扫描预算、分页与缓存应在有代表性的合成大请求上验证；不能把 Magpie 前端每次追加 20,000 字符当成后端读取已经有界的证据。

本提案不解决历史正文缺失的采集根因，不保证补回样本的 pending 正文，也不承诺解密推理或取得供应商持有的历史。没有运行 Magpie 上游测试，没有升级本机 Magpie，没有对真实库执行重建或写入。
