# Agent Note: 轮次两端阅读:命令直达最终回复

Status: proposed

## Problem

trace 的一种高频读法是问答式的:这一轮我下了什么命令,agent 最后给了什么答复。agent loop 把一轮撑成很多笔请求,中间全是工具循环。中栏轨迹按请求粒度投影,命令和结论隔着几十行折叠行,想从命令走到最终回复只能沿时间线一段段往下翻,自己认哪一笔是收尾。

工具配对解决过一次同类问题:一次工具调用的两端靠 call_id 硬关联,配对页一屏读完,见[Trace Pair 配对页与右栏就地阅读](../../implemented/feature/2026-10-24-trace-pair-rail-page.md)。轮次没有这种硬 ID。那条 note 的「其他配对候选的边界」否决过「模型请求 / 模型回复」,理由是输入含全部历史、单条 User 与单块 Assistant 不是一对一问答。这个否决只覆盖请求级口径,留下一个真实缺口:轮次级口径,跨多笔请求的「命令 → 收尾回复」。维持现状,这个缺口继续靠人眼翻轨迹来填。

2026-10-25 讨论给出的需求原话:点进一个入口,快速看到这一轮我的命令是什么、最终回复是什么;点第二个,是第二轮的命令和最终回复。逐轮翻阅整个会话。

## Proposal

### 回复形状:三态,收尾判定先于轮次判定

轮次结算的前提是能回答「这笔回复是不是收尾」。不能拿「工具调用计数为零」当答案:`anthropicReplyCalls` 对缺失回复、不识别的形状、多 choice、缺 ID 的工具块都返回空数组,截断的回复也满足零计数,拿它判收尾会把中断和未知显示成最终答复。

派生层为此新增回复形状位,三态枚举:

- `final`:协议形状可识别、无有效工具调用、回复完整。只有它能当轮次终点。
- `tools`:识别到有效工具调用。
- `unknown`:reply 不可读、形状不识别、多 choice、存在缺 ID 的工具块、`stop_reason` 表明截断(如 max_tokens 的半截话)。存量行无法回填的也归这里,不默认成无工具。

### 轮的判据(已定)

- **起点**:主链上一笔请求的确定新增里出现用户主动文本。检测与路径污染判定共用派生时写下的 `input_preview_kind = 'delta'` 一份判定:它是 interpretMessage 经 previewOf 在派生期的产物,正文回收后随派生列保留,读模型不对中间请求重解读正文。`state='text'` 含 wrapped 与 midturn 插话,queue 追加的命令经 midturn 前缀剥出后照常成起点。同笔多条用户输入归**一个命令组、一个轮次入口**,不拆多轮。读模型重解读 `delta_ordinals` 只发生在起点请求内,用于筛出用户主动文本的 ord 列表定位命令全文;`input_preview` 只作摘要,不承担全文定位——它不返回 ord,且同一请求可以有多条新增用户消息。
- **正文回收不隐藏轮**:起点按派生时的 kind 位判定,该位与形状位一样在回收后保留,起点轮照常进带;命令全文读不到时右栏命令面板落正文已回收态,与轨迹视图保留 retained 摘要同一立场。
- **终点**:起点请求自身的 reply 是 `final` 时,终点就是起点这笔(纯对话轮,两端同笔);否则在起点的后代里找——沿确定的 parent 前驱边可达、**路径上不经过其他用户命令请求**、时间最早的 `final`。路径含两端:终点请求自身的增量里出现用户主动文本时,它同时是下一轮的起点,旧轮按污染不结算,不把回答新命令的回复配给旧轮。后代分叉导致多个可达 `final` 终点时,该轮不结算,不出现。
- **未收尾的轮不呈现**:没有可达 `final` 终点的轮不进列表,不显式标注「未收尾」,也不造终点。这比[读数缺口诚实行](../../implemented/bug-fix/2026-10-25-reading-gap-honest-row.md)更进一步,连状态行都不给,是讨论里明确的取舍。
- **打断即消失,不借新回复复活**:旧命令与新命令之间没有收尾回复时,旧轮的终点搜索不会穿过新命令——路径纯净性保证旧轮不拿新命令之后的回复当自己的终点。queue 追加场景(A 未收尾、B 到达、agent 先总结旧任务再处理 B)里,旧任务总结在 A 的洁净路径上,A 的终点就是它,各归各轮。命令参与的是路径污染判定,不是切分点:语义仍是「这条命令引发的流程在哪收尾」,与被否决的定义 B(取下一条命令前的最后一条 assistant 文本)不同。

### 排除范围与链语义

subagent 会话组(`subagent`/`parent_agent` 字段)、`req_kind='title'`、`purpose_chain='exclude'`、`chain_role='branch'` 都不参与轮次结算。注意 `chain_role='main'` 是主根的全部可达后代,不含「向后只有一条路径」的保证:A→B、A→C 可以同时 confirmed 且同属 main。所以终点搜索显式沿确定的 parent 边遍历后代,并对分叉给出上面的保守规则,不依赖任何线性假设。

### 实现方式:三层,不落轮次表

1. **派生层写回复形状位**。进派生列的整组选源体系:队列带发布指针时随组写 `derive_request_result`,否则写 `request` 同步旧列,与标题、摘要、关系同一套选源,不出现标题取发布代、形状取同步列的混拼。判定进 `derive-decision.ts`,同步与切片两条路径共用一份。schema 变更,按仓库立场带可执行 backfill 或明确拒绝路径:backfill 只对正文可读的行重算,算不出的行标 `unknown`。正文回收(`body_state` 离开 available)后该位保留派生时的值,不清除不重算。
2. **读模型即时结算轮次**。沿确定 parent 边遍历后代,判形状与路径纯净,产出轮次列表(起点 req_id 与命令组 ord 列表、终点 req_id)。起点检测与污染判定消费派生时的 kind 位,不读中间请求正文;命令 ords 只对选中轮的起点请求重解读。消费约束:只消费 `derived_state='current'` 的组,结算在同一个只读快照内完成;dirty、retained、形状为 `unknown` 的行不产生确定轮次。不落轮次表的理由:判据还在定型期,固化进 schema 后改判据要 backfill 重算;判据稳定后再评估落表。
3. **HTTP 与前端**。轮次接口接收累计窗口下界(浏览器已加载的最早请求),服务端按累计范围结算。单页响应结算不出跨页的轮:最新页含终点缺起点、更早页含起点缺终点,合并两份单页列表也补不出来,所以结算单位必须是累计窗口,不做跨页增量合并。行摘要用现有 `input_preview`。

### 前端形态(已定:中栏样式不动,只往上添)

中栏 session-head 与第一条轨迹行之间加一条轮次带:

- 一行高度、横向滚动,高度恒定,轮数多少都只占一行。每轮一块:轮号加 `input_preview` 截断,旧轮在左,与轨迹时间方向一致。轮次带消费的是派生时确认过的 delta 摘要,不拆步骤、不等正文读取,与轨迹视图「读取未完成不得把请求级 input_preview 拆成确定用户步骤」的口径不冲突。
- 轮次带吸顶:贴在 session-head 下沿随滚动常驻,滚到轨迹深处仍能翻轮。目录层的可达性不随滚动深度衰减,这是它与轨迹内入口(滚走即失)的本质差别。
- 点击选中,右栏进入轮次内容态;点下一块就是下一轮,逐轮翻阅靠带内顺序点击。
- 无可结算轮的会话整条带不渲染,不占位、不留空态。
- 块上不加「第 N 轮命令」这类二级标签,位置和顺序自己解释。

右栏轮次内容态:

- 身份行换成「轮 N · 命令 req X · 回复 req Y」,上下文靠请求号手动定位,不做跳转,沿配对页的既有立场。
- 正文区两个面板:命令组全文在上(同笔多条用户消息按序展示)、最终回复全文在下,默认同时展开,复用 `body-panel` 组件语言。
- 读数 / 正文 / 工具 / 路由页签行在轮次态隐藏,它们是请求作用域。点轨迹任意行回请求态,轮次带选中清除。右栏短暂离开请求态有先例:窗口外请求详情。
- 命令全文读起点请求正文,回复全文读终点请求的 reply,跨两笔请求的 owner 协调沿用 tool pair 的机制。

轮次带是轨迹的目录层,不是新视图:轨迹本体一行不动。

### 与既有配对边界的关系

配对页 note 否决的是请求级「模型请求 / 模型回复」,本提案不推翻它,是它边界外的第三种口径。那条 note 断言「窄口径的『本次新增输入 vs 本次回复』就是时间线同一请求组内的 User/Assistant 步骤」,在 agent loop 多笔请求的场景这句不成立。实施本提案时,同一变更更新那条 note 的边界段落并互相链接,它保持活跃。

## Alternatives considered

**机械收尾信号:起点之后第一条无工具回复。** 初稿判据,review 指出两处破绽。一处是零计数不等于收尾,缺失回复、未知形状、截断都满足零计数,已在形状三态里修掉。另一处是打断场景 A(旧命令)→ B(新命令)→ C(收尾):机械判据把 C 同时给 A 和 B,C 可能只回答 B,被打断的 A 靠 B 的回复复活,违背「打断轮不呈现」的既定取舍。被路径纯净规则取代。

**接受共享终点,描述为「命令之后的首个候选收尾」。** review 对机械判据的温和修补:明确允许共享,不再保证打断轮消失。否决:答非所问的配对会出现在带里,「未收尾不呈现」的精神被打穿。

**分叉时取时间最早的收尾。** 处理多后继的启发式。regenerate 场景里时间最早的收尾常是被抛弃的尝试,后续对话续写的是后一条,启发式会把错答交出去。否决,保守不结算。

**定义 B:下一条命令切分。** 终点取下一条用户命令出现前的最后一条 assistant 文本。打断与队列输入场景下与定义 A 结果不同,打断的轮两边都找不到收尾文本。讨论选了收尾信号:回复自身形状是证据,不从相邻命令反推。

**未收尾轮显式呈现「未收尾」状态。** 对齐诚实立场的第一反应,讨论中否决:列表里不出现,被中断的命令回轨迹视图找。轮次视图与轨迹互补,不是替代。

**落表 turn pair(仿 tool_call 表)。** 查询稳、天然带反向索引,但判据未定型就固化 schema,回头改判据要 backfill 重算;新请求到达还要把先前未收尾的轮补结算,增量推进比 tool pair 复杂。读模型先行。

**中栏视图切换(轨迹 ⇄ 轮次)。** 讨论中一度推荐,用户否决:中栏保持当前样式,Trace 的直观简洁优先,可以往上添但必须克制。轮次带由此收敛为一行高度横滚。

**右栏第五个页签。** 页签挂在选中请求下,轮次没有请求上下文,作用域错位。排除。

**轨迹行内「直达终点」入口。** 动线要沿轨迹滚着找命令,逐轮翻阅体验碎。第一刀不做;轮次带用起来后,若「读到一半想看结论」的需求仍真实再补。

**头部按钮加浮层列表。** 仓库没有浮层形态,目录层要求常态可见,且多一次点击。排除。

## Acceptance criteria

- 判据单源:回复形状判定在派生内核一份,轮次结算在读模型一份,同步与切片两条派生路径不各写一套。
- 形状三态测试:缺失回复、不识别形状、多 choice、缺 ID 工具块、`stop_reason` 截断判 `unknown` 且不作终点;可识别形状无工具且完整判 `final`;识别到有效调用判 `tools`。
- 轮次结算测试:纯对话轮两端同笔;工具循环轮跨笔;打断场景(A→B 命令→C 收尾)A 消失、B 配 C;queue 追加场景(旧任务总结在新命令之后但路径洁净)A 配旧任务总结、B 配自己的收尾;midturn 起点场景(queue 追加经 midturn 前缀剥出照常成起点);终点带命令场景(终点请求增量含新命令且 reply 为 `final`,旧轮不结算,回复归新轮两端同笔);后代分叉多 `final` 不结算;subagent / title / exclude / branch 不参与;同笔多条用户输入归一个命令组;正文回收后形状位与起点 kind 位保留旧值,回收起点照常进带且命令面板落回收态;非 `current` 组不产生确定轮次;起点检测与 previewOf 判定同源(同一包装消息不会在检测与污染两处得出不同结论)。
- 跨页结算:服务端按累计窗口下界结算,「起点在更早页、终点在最新页」的轮可结算;backfill 可执行,不可回填的行标 `unknown` 且所在轮不出现。
- 前端:轮次带一行高横滚、无轮不渲染;点选后右栏两端默认展开,命令组多条消息按序;点轨迹行回请求态并清选中。
- 真实库只读核验:对生产实例跑轮次结算,抽轮人工核对起点命令与收尾回复的对应;浏览器逐轮点击链路显式验收。合成数据验收与真实流量验收分开写。
- 提交前 `bun run verify:notes` 与 `bun run typecheck`;行为变更只跑能对该回归失败的最窄测试。

## Risks

- 收尾信号是推断,不是硬证据。轮次两端没有 call_id 式关联 ID,靠链结构、路径纯净与回复形状推。被打断的轮直接消失,不记得的人要回轨迹视图才找得到;regenerate 分叉的轮保守不结算,也不出现。这些是既定取舍。
- 形状位是 schema 变更,且 `unknown` 会静默吞轮。存量行派生版本未升级或不可回填时标 `unknown`,这些行参与不了终点判定,所在轮整轮不出现——升级窗口期轮次带会比应有的少,backfill 完成前是预期行为,不是数据丢失。
- 判定同源已由结构保证:起点检测、路径污染与命令 ords 都源自派生时 interpretMessage 的同一份产物(kind 位与 `delta_ordinals`),读模型不再有第二套「什么算用户命令」的判定。残余风险是 kind 位口径与派生判定漂移——比如未来 interpretMessage 改了包装规则,已发布代要等重派生才跟上;测试覆盖「起点检测 = previewOf 判定」这条一致性。
- 轮次带与轨迹信息重复。带是目录层,接受这份重复;若阅读价值不成立,撤掉时轮次列表、接口与前端入口一起撤,形状位列与其回填代码是撤销时仅剩的 schema 成本,要一并处理。
- reply 文本与 tool_use 同存的笔按形状判 `tools` 不算收尾,要等下一笔。若真实数据存在「说完就停但带 tool_use」的形态,轮会被判未收尾而不出现。真实库抽验时重点看这类。
