# Agent Note: 前端主界面按方向 A（Geist 中性 + Apple 校准）重制视觉语言

Status: proposed

## Problem

2026-11-01 对生产前端做了一轮系统评估，结论是：三栏结构与信息密度已经合格，观感差距集中在视觉语言，而且集中在浅色主题——

- 中栏 pending 行的米黄软底连成串占满首屏，是最大的噪音源；
- 同屏 soft 底色超过 10 种（角色五档、工具七档、语义三档叠加），色彩没有预算；
- 表面层级靠 1px 边框硬分，明度差不足；
- 徽章、图例、行内标签铺色过多，重点信息反而沉底。

深色主题的三层表面加语义色关系成立，可以当基准。需求侧的目标（Pis 原话归纳）：简洁，让用户一眼找到最重要的信息；不要很多副标题、不要冗余信息；视觉负担要低。这与仓库常备约束[前端降噪常备约束](../../implemented/process/2026-10-24-frontend-denoise-standing-rule.md)同源。Pis 同时明确认可 Apple 的设计语言，要求把 Apple HIG 纳入校准。

外部参考取用截图加 token 加组件解剖的方式（Braintrust、Langfuse、Sentry 的 trace 界面；Geist Colors、Dark Developer UI、Radix Colors、Mars Dashboard 指南），链接只当索引。本提案的规格来源是作者本地的参考库、四方向对比页与方向 A 细节样张（含明暗双主题切换），这些工作产物不随仓库发布。

## Proposal

总原则：**换视觉语言不改结构**。三栏布局、轮次带与读数卡的分组方式、数据接口全部不动；全部动作只有删减与换值。accent 换 Apple 系统蓝（浅 #007AFF / 深 #0A84FF），三档字色对齐 label / secondaryLabel / tertiaryLabel，字体栈本就是 Apple 栈。设计规则五条：

1. 状态色只给异常与选中：失败红、选中蓝、缺正文灰，其余灰阶。
2. 数字一律等宽（mono + tabular-nums），耗时、token、费用、百分比全部如此。
3. 分组靠间距与对齐，不立标签行、不配图标。
4. 角色徽章保留软底 pill，四档识别色封顶；工具七档色删除。
5. 每个数字自带语境（41.1k 后面跟总 1.0M · 已用 4%），Apple 质感：细线内缩、与文本对齐，深浅两套同时交付。

落地分六步，每步独立可验收（走 worktree 分支，每步按非平凡判据带 note 或豁免，提交前跑 verify:notes 与能对该回归失败的最窄测试）：

1. **token 值替换**：按样张附录的 token 映射表改浅深两套色值，纯值变更，行为不变。--page #FAFAFA/#0A0A0A、--surface #FFFFFF/#111111、--inset #F5F5F4/#181818、--line #ECECEA/#DEDEDB、三档字色 #171717/#52525B/#A1A1AA、accent 换系统蓝。
2. **徽章与工具降噪**：tool-* 七类删除；角色徽章 pill 化并重映射四档——user 蓝、system 灰、assistant 紫、tool 橙（浅 #0066CC · #8E44AD · #B45309，深 #409CFF · #C77FEA · #FFB340）；k-field 并入语义最近的一档（并入前逐消费点核对）；选中行加 2px accent 左缘加浅蓝底；pending 行改透明底加虚线左缘。中栏、右栏、会话列表 chip 三处共用规则一次改齐。
3. **会话栏与顶栏**：搜索场改 raised 无框圆角（聚焦才描 accent 边）；Agent 筛选三个 chip 换成一段分段控件；选中会话灰底圆角（导航中性，内容区才用蓝）；会话行两行制，时间右对齐 mono，计数进标题行；logo 重描为圆角端点 trace 标记加单个 accent 分支节点；面包屑带会话标题；图标按钮 ghost 化；顶栏高度收 44px。
4. **头部摘要块两栏收噪**：两栏分工保留（见下），删七个行标签与七个图标，失败数并入对应工具 chip 作红字，Skill 并入工具行，中间 1px 细线替代两侧小标题。
5. **工具列表页与配对页**：列表页删逐行重复工具名 chip，行内放调用摘要首段，右侧 req 与耗时 mono 弱化，页头右侧补计数与失败数；配对页给调用/结果两段补角色标签，来源路径降为 mono 弱化，中间弱化连接语交代因果，JSON 块换 raised 底，子页签换分段控件。
6. **树图单色化**：用量树图从四系彩色改单色四档透明度（浅 rgba(0,122,255,.16/.12/.08/.05)，深 rgba(10,132,255,.18/.13/.08/.04)）；「新增 N」横幅删除，改右栏一条蓝缘。

## 已定决策与样张的对应

- **方向 A（Geist 中性）**，2026-11-01 Pis 从四方向对比页选定；同日补充 Apple 校准。
- **头部摘要块保持两栏**，2026-11-01 Pis 否决单栏合并方案；与 [会话头部两栏](../../implemented/feature/2026-11-01-session-header-two-column.md) 的交付一致，本提案只做收噪。
- **角色辨识选甲（徽章底回归）**，2026-11-02 Pis 定。三个方案做过同数据对比样张（甲徽章底回归、乙图标前缀、丙角色词上色），我方推荐丙，Pis 权衡后定甲：辨识优先于极简。甲的代价（同屏多四块软色）用三条控制：pill 化把底色面积压到最小、低饱和软底、色相数封顶四档。丙样张保留在细节页区 4 讨论稿；两方案共用同一 DOM，只换徽章 CSS，甲实际使用显吵时可低成本切换。
- **思考与耗时的分档变色机制原样保留**，2026-11-02 Pis 明确要求。口径不动：`web/duration.js` 的 TIER_LIMITS（思考 5s/30s、读写 1s/10s、命令 5s/30s、联网 15s/60s、子代理 30s/120s）与 tierOf 分档，中栏行尾经现有类名上色，正常档弱灰、超限琥珀（--warn）、再超红（--bad）；等待型工具不上色的规则保留。新设计只换色值，不改阈值与判断位置。
- **选中态**：点选请求里的某一条消息，该行浮现 2px accent 左缘加整行浅蓝底；中栏消息行与右栏结构行共用同一样式，单选；hover 仍是灰底。这是 2026-11-02 Pis 提出的硬性要求——选中必须可见。

## Alternatives considered

- **方向 B（Linear 暗色密度）/ C（Radix 演进保留青绿）/ D（观测台时间轴化）**：对比页存档。B 的暗色密度与浅色主题诉求错位；C 保留青绿主色但收敛有限；D 的瀑布化动结构，违背「换视觉语言不改结构」的边界。
- **乙（角色前加图标）**：图标是第二层解码，10px 下糊成墨点，图形不解释含义、旁边还得留字，每行多一列间距成本；Apple 自家列表也不给每行配图标。否决。
- **丙（角色词上色，无底）**：我方原推荐——hue 缩到一个词上，噪音最小。Pis 选甲后降为备选，保留样张与「换 CSS 即切换」的退路，理由见上。
- **头部单栏合并**：把资源/性能与工具/写入/读取并成一栏。Pis 明确两栏更好，否决。
- **引第三方组件库**（分段控件、树图）：仓库约束不引第三方依赖，全部用现有 vanilla 结构实现。

## Acceptance criteria

- 浅深两主题下，同屏 soft 底色种类收敛到角色四档加语义三色以内；tool-* 七类色在生产页面无残留消费点。
- pending 行无满铺底色，呈透明底加虚线左缘。
- 选中一行消息，浅深主题下都能看到 2px accent 左缘加浅蓝底；hover 与选中两态可区分。
- 行尾耗时按 duration.js 档位着色的行为与现状一致（现有最窄测试钉住阈值与档位判断，本提案不改动它们）。
- 会话列表、右栏、中栏三处 chip 规则一致；逐项对照细节样张的八个区域走查生产页面。
- 全程无新增第三方依赖；正文与路由内容在页面一律转义的约束不受影响。

## Risks

- **chip 规则三处共用**：中栏、右栏、会话列表共享基础类，任何徽章调整必须三处同批改，分步验收时容易漏。缓解：步骤 2 明确一次改齐，走查清单含三处对照。
- **甲方案的密度代价**：长会话里四档软底持续在屏。已留丙方案的低成本切换预案（DOM 不变）；若切换，本 note 更新决策记录而非另起炉灶。
- **k-field 并档影响面未逐点核对**：落地步骤 2 前先盘点 --k-field 的全部消费点，按语义并入 tool 橙或 system 灰，核对结果写进该步的 implemented note。
- **树图单色四档在深色主题的区分度**：alpha 档是示意值，需用真实会话数据验证后定稿；不达标就在深色套单独调档，不改结构。
- **样张与实现的偏差**：细节样张的树图比例与部分行内容为示意，落地以真实渲染为准；样张数字取自生产截图的汇总值，不进 fixture、不进提交。
