# Agent Note: 空状态蜘蛛插画——只在没有选中 trace 时出现

Status: proposed

## Problem

### 现状：三个空状态都只有 24px 通用图标

ATC 现有空状态一律是「24px 标记 + 一句说明」：

- 右栏「未选择请求」——[app.js](../../../../web/app.js) 里 936、1016、1173 三处渲染同一段 `rail-empty`，都是 24px `empty-select` 图标；
- 中栏「这个会话没有已记录的请求」——同一文件 756 行的 `.sess-empty`，`<p>` 从列表区左上角开始排，图标居中、文字左对齐；
- 左栏零会话——也是 24px 图标。

这些空状态是界面上面积最大、注意力最空的位置，但视觉上仍是一套通用占位符，与已经选定的品牌形象（B1 蜘蛛）没有任何关系。2026-11-01 至 11-02 的方向 A 降噪与重制已把静态界面收拾到可用状态（[方向 A 重制](./2026-11-02-frontend-direction-a-restyle.md)），空状态是剩下少数还能承载品牌、且不增加信息噪音的位置。

### 为什么只能落在空状态

空状态没有数据、没有决策、没有状态语义，插画放在这里不会与任何读数抢注意力；一旦离开空状态，任何停留点都会与 trace 行、会话头、顶栏的实际职责重叠，也会与刚交付的降噪规则冲突。

### 发布面约束

前端静态发布面是 [STATIC_FILES](../../../../src/http.ts) 白名单加 `readFileSync(entry.file, 'utf8')`。它只发白名单里的文本文件，没有二进制路径，也没有 Range 支持。因此这条能力不能靠「再发一个 MP4/GIF」实现：要么加白名单条目与 MIME，要么把图形塞进已有文本文件。后者更小、更快，也不会扩大发布面。

### 资产现状与一条更正

B1 形象已由用户选定并批准，真实位图资产在 `atc-ip-motion/B1-{16,32,64,256,512}.png` 与 `B1-transparent-*`（设计工作目录，目前不在本仓库内）。矢量化版本只有一个 1161 B 的静态 `spider.svg`，带薄荷底色 `#B6F9D6`，只够 favicon/单色标记用。**目前没有与 B1 完全等价的 SMIL 动效源**，这是本提案的待补项，不是可以直接拿来用的既有资产。

实测更正：B1 原图**没有腮红，也没有瞳内高光**。之前以为的近白像素是背景薄荷 `#B6F9D6` 的边缘反光。后续任何重绘都不要凭空补这两项。

## Proposal

**本提案只做一件事：在没有选中 trace 的空状态里显示一只吊在丝上的 B1 蜘蛛。其余全部不做，见下方「明确不做」。**

### 落点与尺寸（按优先级）

| 位置 | 尺寸 | 依据 |
| --- | --- | --- |
| 右栏「未选择请求」 | 内接方形 160px | 栏宽 `clamp(280px, …, 640px)`，`.rail-empty` 内宽实测 244–604；160 在两端都留出最匀的四周留白，上下也不会压到说明文字 |
| 中栏「这个会话没有已记录的请求」 | 内接方形 200px | 1440 视口下中栏 544×约 560，是唯一能舒服容纳 200 的位置；再大就会挤压说明文字 |
| 左栏零会话 | 不做，保留 24px 图标 | 250px 栏里 128px 的图占掉一半，头顶「会话」标题、搜索框与列表全部失去层级，图比列表本身更抢眼 |

中栏需要一处明确的布局改动：现状 `.sess-empty` 从左上角起排（[app.css](../../../../web/app.css) 的 `.sess-empty` 规则只给了 16px 内边距），改为水平居中、并在列表可视区内垂直居中的单列。这是布局改动，不是换图；会同步调整该空状态的外层容器，使说明文字仍紧跟插画下方。

右栏三处 `rail-empty` 调用点共用同一段标记，实施时收敛成一个拼装函数，避免三处各写一份 SVG。

### 落地方式：内联 SMIL SVG，不用位图

- **MP4 发不出去**：发布白名单只有文本文件 + `readFileSync(..., 'utf8')`，二进制没有路径，也没有 Range。
- **位图抠底留光晕**：吊丝和腿尖外沿在深色界面会留一圈薄荷色边，压缩与 `background` 都消不掉。
- **SVG 天生透明**：`fill` 走 CSS 变量，深浅跟随 `data-theme`；体积 2–4KB，现有静态 `spider.svg` 只有 1161 B，内联后不增加任何网络请求。

内联的 SVG 也必须去掉原文件里的薄荷底 `rect`，只保留角色与丝。

### 深浅配色

- 浅色用 B1 原值：身体 `#013660`、丝 `#F29176`、眼/嘴 `#FF896D`。身体对 `--canvas #FAFAFA` 实测约 11.9:1，充裕。
- 深色必须提亮身体：`#1B5A9E` 对 `#101418` 只有 **2.64:1**，低于图形非文本 3:1 建议线。提案用 `#2166B0`，对 `#101418` 为 **3.16:1**（对生产暗色表面 `--surface #111111` 和 `--canvas #0A0A0A` 分别为 3.23:1、3.39:1）。这是**待定项**：3.16 刚过线、余量很薄，落地时按实际 `data-theme` 表面重测；不达标就继续提亮，不用描边或阴影「补」对比度。

### 出现时序与动效

- 空状态持续 **≥500ms** 仍未被选中，才启动动画；首屏不加动画负担。
- 动效沿用 B1 语言：钟摆 **±2°、周期 3s**，叠加呼吸与眨眼，合成 **9s 无缝循环**（3 个摆动周期、2 个呼吸周期、1 次眨眼）。
- 实现上所有 SMIL 动画用 `begin="indefinite"`，由 JS 在 500ms 计时器到期且状态仍为空时 `beginElement()` 启动；期间被选中就取消计时器、永不启动。SMIL 文档时间轴只给静止帧，正好充当兜底。
- `prefers-reduced-motion: reduce` 时只显示静态首帧：SMIL 不受 CSS 媒体查询约束，必须在 JS 里读 `matchMedia` 后不启动动画，仅靠 CSS 兜不住。
- 静态首帧必须是完整构图（蜘蛛吊在丝上、睁眼），不能是动画的中间空档态。

### 可访问性

插画是装饰，`aria-hidden="true"`，不进入可访问名；空状态里的说明文字仍是唯一的语义来源。SVG 内部不出现任何用户数据，全部是常量标记。

## 明确不做

以下每项都是**不做**，不是「后续可选」：

- **常驻 / 停留点**（右栏正文末尾滚到底、中栏末尾、顶栏、会话头、左栏末尾）：刚完成降噪重构，常驻插画会让界面持续变吵；且现有素材只有「吊丝 + 前肢上举」，没有丝上的落地坐姿，几何重绘会读成「举手抱空气」，要成立需要一张真正的坐姿重绘帧。用户已决定不做。
- **顶栏 logo / 应用图标（蜘蛛方案）**：放弃。等比缩到 24px 时眼睛直径只剩约 0.80px（原图眼径 60/1920，按 24px 计），实际一个像素都不剩；膝折一条腿只有 1–1.3px，不可读；剪影只剩「圆身体 + 八条短腿」，B1 的萌没有带过来，用户判定不好看。
- **Trace 行、角色 pill、会话行、失败态、`history-loader`、「正文未到」、顶栏存储降级 chip、会话头动作条**：都是承载状态语义的信息位，插画会与读数抢读，与降噪规则冲突；均已判否决。
- **左栏零会话**：理由见上表，保留现有 24px 空图标。

## Alternatives considered

**位图 / 透明 APNG / GIF。** 被否决不是美术问题，而是发布面问题：白名单只发文本，二进制没有服务路径，也不支持 Range；GIF 还会在深色底上留下抠底光晕。

**CSS keyframes 代替 SMIL。** 与 `prefers-reduced-motion` 的集成更直接，长期支持也更稳。本轮不用，是因为动画源按 SMIL 编写（矢量原型就是 SMIL 时间轴），改成 CSS 等于重写一遍关键帧，且失去「单个 SVG 文件可独立打开」的性质。若 Safari 风险兑现，CSS 版就是既定退路，而不是临时方案。

**外部 `.svg` 文件 + 白名单条目。** 需要扩 `STATIC_FILES`、加 MIME，并多发一次请求；内联只有一个文件、跟随 `data-theme` 变量，也没有缓存失效问题。否决。

**右栏 200 / 中栏 160 的交换。** 右栏 200 会压到说明文字并挤占读数区，中栏 160 在 544 宽里偏小、镇不住空白。否决。

**左栏也放 128px 插画。** 250px 栏内占比过半，标题、搜索框、列表三层的视觉层级全部塌掉。否决。

**把插画塞进顶栏 logo 或应用图标。** 24px 下眼睛与膝折不可读，只剩生物剪影，品牌辨识度归零。用户已判定不好看。否决。

## Acceptance criteria

- **尺寸**：右栏插画渲染盒 160×160 CSS px（±0.5），中栏 200×200（±0.5，1440 视口）；SVG `viewBox` 为方形，`width`/`height` 属性与 CSS 盒一致，无拉伸。
- **响应式**：容器内宽 ≤320px 时右栏降为 96×96；420px 时仍保持 160（实测两侧各余约 130px，不触发降级）。中栏容器 <360px 时降为 132×132。
- **对比度**：浅色身体 `#013660` 对 `--canvas` ≥3:1（实测约 11.9:1）；深色 `#2166B0` 对实际 `--surface`/`--canvas` ≥3:1（`#111111` 3.23:1、`#0A0A0A` 3.39:1）。用实际取色值记录，不写「看起来够」。
- **体积**：内联 SVG 片段 ≤4096 B（UTF-8，未压缩），且不含 `data:image` 位图；`STATIC_FILES` 条目不增加。
- **首屏不加载**：插画是内联常量，页面加载后 `performance.getEntriesByType('resource')` 不新增条目；首 500ms 内对同一位置两次截图（约 100ms 与 400ms）像素差为 0。
- **500ms 门控**：空状态出现后 <500ms 时根 SVG 带 `data-motion="idle"`，≥500ms 仍为空时变为 `data-motion="running"`；500ms 内发生选中则属性保持 `idle`，且之后不再启动。
- **reduced-motion**：模拟 `prefers-reduced-motion: reduce` 时 `data-motion="static"`，首帧完整可读；约 10s 内两次截图像素差为 0。
- **无缝循环**：9s 周期；`t=0` 与 `t=9s` 的截图像素差为 0（呼吸与眨眼都在周期内闭合）。
- **布局**：中栏空状态的水平中心与列表容器中心偏差 ≤2px；插画与说明文字的间距为 12–16px，文字不再从左上角起排。
- **无回归**：三段右栏空状态共用同一拼装函数；说明文字、`<b>` 语义与现有文案不变；`bun test`、`bun run typecheck` 通过，提交前 `verify:notes` 通过。现有测试没有视觉快照能力，尺寸、对比度、门控与 reduced-motion 用浏览器实测截图记录，不靠推断。

## Risks

- **SMIL 源仍需从 B1 重绘（最大风险）**：仓库内外都没有与 B1 完全等价的 SMIL 源，只能按 `spider.svg` 的几何与配色重绘到动效版。八条腿的膝折位置、眼距与嘴弧很容易在重绘时漂移，出现「看着像另一只蜘蛛」。验收要把重绘帧与 `B1-256.png` 并排比对轮廓与五官位置，偏差超过一像素量级就返工。
- **Safari 对 SMIL 的长期支持**：SMIL 在 Safari 仍可用，但多年被讨论过废弃；一旦被移除，动画整体失效。退路是静态首帧兜底（默认状态本来就是静止帧），必要时按 `Alternatives` 里的 CSS keyframes 版本重写，不改落点与尺寸。
- **深色对比余量薄**：`#2166B0` 对 `#101418` 只有 3.16:1，对 `#111111` 3.23:1，任何 token 微调都可能跌回 3:1 以下。上线前必须按最终 `--surface`/`--canvas` 重测；不达标就继续提亮，不靠阴影或描边冒充。
- **窄栏降级阈值**：右栏在 1100 视口附近内宽会掉到 420 左右；本提案判定 420 仍用 160、≤320 才降到 96。若真实测量在该窗口下说明文字被挤成三行以上，就提前到 360 触发降级。
- **持续循环等于持续动画**：空状态若长时间停留，9s 循环会一直播放。若被判定为噪音，降级路径是完整播完 3 个循环后停在首帧（同一素材，无需重绘），不改尺寸与落点。
- **中栏布局改动**：把空状态从左上角改为居中列会动到 `.sess-empty` 的外层结构，需确认不影响「读取中」「请求都没有可读正文」两种相邻空文案的排版。
