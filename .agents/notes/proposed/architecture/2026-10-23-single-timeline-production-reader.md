# Agent Note: 单一轨迹生产阅读

Status: proposed

## Problem

用户已通过原型确定紧凑单行轨迹和右栏上下文的阅读方式。生产页面仍提供对话与请求账本两个入口，首屏从最早请求开始，正文缓存把连续历史页与当前阅读位置绑定。直接复制原型会绕过生产派生状态投影，并把不同读取时点的增量、正文和工具结果拼在一起。

## Proposal

将原型确认的交互迁入生产页面，继续以请求作为身份和计量单位，由前端把可信新增输入与实际回复转换为阅读步骤。保留生产的输入解释、能力提取、状态说明、用量与路由展示；原型的静态数据、独立服务和上下文集合比较不进入生产。

读取层补充最近窗口、向前翻页、请求阅读版本校验及按调用位置读取结果。发布代存在时整套读取已发布结果，默认同步派生继续使用现行运行配置。实现范围、接口、缓存所有权和任务验收以[实施计划](../../../../docs/superpowers/plans/2026-10-23-single-timeline-production-reader.md)为准；落地时把接口与读取机制写入[架构设计](../../../../docs/architecture-design.md)，提案不作为已交付说明。

本提案补充[单一轨迹原型](../../implemented/feature/2026-10-23-single-timeline-prototype.md)、[本机读取原型](../../implemented/feature/2026-10-23-local-trace-prototype-reader.md)和[右栏原型](../../implemented/feature/2026-10-23-prototype-request-context-rail.md)，它们继续拥有原型范围及验证限制。生产实施后将部分取代[固定账本行](../../implemented/feature/2026-10-21-ledger-fixed-row-and-type-tags.md)和[读数裁剪修复](../../implemented/bug-fix/2026-10-21-ledger-readings-overflow.md)的布局选择；防止读数内部裁剪的验收仍有效。[服务端输入解释](../../implemented/feature/2026-10-22-server-side-input-interpretation.md)的语义与能力归属保持有效。活动树检索未发现另一篇覆盖生产单一轨迹、条件正文读取和最近窗口的提案；本轮只记录提案，旧 implemented 记录保持原状。

## Alternatives considered

**直接把原型 HTML 替换生产首页。** 原型具有合成对象、全局结果查找、演示路由和独立数据库窗口查询，缺少生产缓存失效与读取一致性保证。只迁移交互和可复用的纯渲染函数。

**新建步骤表或重做派生流水线。** 请求身份、可信增量、消息解释和工具结果路径已经存在。步骤属于阅读组织，不需要增加另一套长期数据或改变采集与容量策略。

**只改 CSS。** 列表只给请求级摘要，无法逐条呈现多个新增消息和多个工具调用；最近窗口与顶部向前加载也需要明确的查询支持。

**用一个全会话事务冻结所有历史。** 长会话会增加读取与正文保留成本；界面需要的是可重新读取的当前窗口。请求级条件读取可检测失效，不能承诺跨多个 GET 永久冻结整个会话。

**为本轮迁移启用切片派生。** 查询能正确读取发布代与生产启用切片是两个决定。现有容量结论继续生效，本轮不改变运行模式。

## Acceptance criteria

生产只保留步骤轨迹，用户消息、助手文本与工具调用各占紧凑一行，详情初始折叠。同请求的步骤共享当前载入请求的数字序号；中栏不常驻模型名和时刻，请求计时只出现一次。初始窗口覆盖常见桌面视口，顶部追加历史保持原有记录位置。

右栏按请求能力、请求结构、本次回复排列。能力清单与结构默认折叠，结构按需分页、消息全文可返回列表，完整回复可读。同请求重绘保留滚动与展开状态。侧栏折叠、Session ID 复制、详情栏拖动与键盘调宽均可操作。

合成回归证明历史不重复为新增、未知与保留状态不升级为确定关系、多个工具结果同消息时仍按精确路径读取、过期阅读版本被拒绝、迟到响应不覆盖新会话或新请求。列表、详情、会话标题与工具关联统一选择派生来源。测试和人工验收的实际结果分别记录，不以原型样本代替生产验收。

## Risks

首笔请求的可信增量可能包含大量历史，单次消息分页也不能限制单条消息或完整回复的字节量；实现必须逐片推进并显示未读范围。读取版本只能在后续读取或显式刷新时发现失效，不提供持续实时一致性的保证。

发布代查询接线涉及会话标题、列表和详情，必须以与同步旧值刻意不同的合成代际验证，避免只在两套值相同的样本上通过。多 choices 的 Chat 调用位置尚不适合用一个 ord 唯一表达；本轮只把单 choice 回复作为确定工具定位来源，多 choice 保留原始对象并明确限制。
