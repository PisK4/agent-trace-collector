# Agent Note: Plugin 准入边界与本地 Feature 包契约

Status: proposed

## Problem

[页面 Plugin 机制与首个 Todo 插件](2026-11-04-plugin-system-and-todo-feature.md)已交付登记层、第五页签与社区轨的本地 Parser 包。社区想加新想法时，今天只有一条窄路：给已登记的 Feature 写某家 Agent 的 Parser，而登记表里只有 Todo。本地包不能声明新页签、新读取契约或新视图，这与「社区开发者把新想法接进页面」的目标差一层。

同时缺一份可被 README 直接引用的作者契约。现有事实散在 `CONTRIBUTING.md`、`docs/operations.md`、两篇 implemented note 与代码类型里；开发者要拼起来才能知道什么能做、什么不能做、包长什么样、失败怎么表现。仓库也还没有成文的准入判据，容易把摄入、派生、证据身份这类核心能力误当成 Plugin 搬出去。

本轮把「哪些能力适合做成 Plugin」和「本地 Feature 包的完整形态」固定成一份指引，并给出分阶段实现顺序。指引是作者侧的唯一入口；为什么这样分层、否决了什么写在本文。

## Proposal

### 准入判据

七条全过才进 Plugin：只读；独立读取契约；独立槽位；可整体关闭；核心持有取数、转义、缓存与校验；不改证据身份、轮次结算、actor 归属、保留、鉴权与计费；可合成测试。需要写库、改 schema 或派生、在页面执行任意 JavaScript 或 HTML、访问数据库或网络、触发外部副作用的能力直接否决。

现有能力逐项结论写进[指引](../../../../docs/plugin-guide.md#23-现有能力逐项结论)：Todo 已落地；Web 搜索是下一个候选；Skill 与 Plan 暂不做；Subagent 是核心结构，不做社区 Parser；会话汇总组、工具配对页与后台作业没有独立槽位；四个核心页签与摄入、派生、鉴权、保留、计费永远不做 Plugin。结论是旧功能不搬，Plugin 只承载新增的独立阅读能力。

### 本地 Feature 包契约（v2）

目标形态写进[指引第 5 节](../../../../docs/plugin-guide.md#5-完整形态本地-feature-包规划中尚未实现)：

- 清单 `api: 2` 增加 `feature` 对象，声明 `id`、`label`、`scope`（`request` 或 `turn`）；页签 key 为 `plugin:<package>:<feature>`。清单次序即页签次序，元数据不执行包代码。
- 包导出 `feature`；每项只有 `id` 与 `read(input)`。`read` 每次拿到该作用域的全部事实，返回封闭视图模型或 `null`。
- 事实信封包含请求元数据与工具调用：`reqId`、`ord`、`agent`、`toolName`、`input`、有界且脱敏的 `resultText`。轮次作用域复用 `listTurns` 与 `mainActorOf`。
- 视图模型只支持 `list`、`tree`、`facts`、`empty` 四种；核心渲染、转义并执行上限校验，包不产出 HTML，也没有 URL 字段。
- Worker 继续单飞、1.5 秒超时、迟到回复丢弃、崩溃与超时 terminate 并记死当前包；其他包换新线程继续。
- 读取走新的具名操作 `pluginRead` 与按作用域分开的两条 HTTP 路由；并发、取消与缓存继续归 `read-scheduler.js` 与 `reader-store.js`，客户端新增 `web/plugin-tab.js` 渲染封闭视图。
- `PLUGIN_API = 2` 与 v1 Parser 包并存；破坏性变化升版本，不静默兼容。

### 阶段

本轮只交付文档与决策：`docs/plugin-guide.md` 成为作者契约；`README.md`、`README.zh-CN.md`、`docs/README.md` 与 `CONTRIBUTING.md` 指向它；`docs/operations.md` 的本地插件包一节补作者入口。v2 运行时不在本轮。

实现顺序：清单 v2 与 `/api/plugins`；`pluginRead`、事实收集与视图校验；客户端渲染与动态页签；Worker 协议泛化；合成测试与文档；用 Web 搜索做第一个内部 Feature，再开放本地 Feature 包。

## Alternatives considered

**允许包在页面执行渲染函数或返回 HTML。** 落选。页面一律转义正文与路由内容，插件直接插 HTML 会把 XSS 面从本机包扩大到每个页面；CSP 也没有 `frame-src`，没有现成沙箱可用。封闭视图模型让核心保留渲染权。

**用 iframe 沙箱跑社区页面。** 落选。要改 CSP、增加宿主与消息协议，首版只为只读列表引入一层跨文档通信不值得；崩溃与超时已经由 Worker 隔离，页面侧只需要数据。

**让包在服务端自己查库或注册 HTTP 路由。** 落选。外部代码会看见全库正文，绕过读取契约、脱敏、缓存与调度；插件只能拿到核心收集的有界事实。

**把现有页签逐个搬进 Plugin。** 落选。读数、正文、工具、路由是核心证据，关掉就让页面缺基础事实；汇总组、配对页与后台作业没有独立槽位，搬走只证明能搬。Plugin 要证明的是新增能力可注册、可关闭。

**社区只做 Parser，不开放新 Feature。** 落选。Parser 只能适配已有能力，社区的新想法没有入口；但直接开放又缺视图模型与客户端页签契约，所以分阶段：先把契约写死，再实现 v2。

**本轮直接实现 v2 再写文档。** 落选。动态页签会碰选择、URL、滚动与读取缓存，事实信封还要定结果摘录的边界；先写契约能避免实现时反复改字段，也能让提案评审有依据。实现作为下一批代码任务，带合成测试与真实流量验收。

**首版接远程市场、签名与自动更新。** 落选。Worker 与采集器同进程，外部代码拥有宿主权限；本地可信包加人工评审是当前信任边界的上限，远程分发留到有签名与隔离运行时之后。

## Acceptance criteria

- `docs/plugin-guide.md` 存在，包含准入判据、现有能力逐项结论、两条今天可用的贡献路径、v2 契约、提案模板、失败排查与参考链接。
- `README.md` 与 `README.zh-CN.md` 的 Plugin 段落和文档索引指向该指引；`docs/README.md` 收录；`CONTRIBUTING.md` 的插件章节不再复制会漂移的字段表，只保留提交入口与检查清单；`docs/operations.md` 的本地插件包链接到作者契约。
- 指引明确标出 v2 尚未实现；本轮不改运行时、不加表、不升 `PLUGIN_API`。
- 文档只用合成事实作例子；不写真实请求正文、账号、令牌或用户配置。
- `verify:notes` 通过；相关链接可解析。
- v2 实现时的验收条件：清单与视图校验、请求与轮次两条正常路径、空/回收/截断、四类视图与畸形视图、超时/抛错/迟到回复/线程崩溃、页签注册与 URL 往返、客户端不旁路 fetch、调度与缓存不旁路；合成与真实流量分开记录。

## Risks

Worker 与采集器同进程，Bun 的 Worker 隔离崩溃与超时，不隔离文件、网络或宿主权限。事实信封会把工具参数与结果摘录交给本地包，只装可信代码这条不能松。

动态页签会改客户端的选择模型：页签的 scope 决定它是否保留轮次态，URL 的 tab key 要能回退，滚动与焦点要保持。这是 v2 里最容易出回归的一块，需要行为测试而不是只测端点。

封闭视图模型刻意限窄。树图、表格、图表、任意布局都做不了；需要这些形态的能力要么先扩视图词汇，要么留在核心。扩词汇同样要升 `PLUGIN_API`。

事实信封里的 `resultText` 会暴露工具结果摘录。首版只给脱敏后的有界文本，正文回收后为 `null`；如果某个 Feature 需要更多正文，先评审这个 Feature 是否应该留在核心。

v2 落地前，社区只能提交 Parser 包；新 Feature 走提案与核心实现。指引把这条写清楚，避免 README 的引用被读成「今天就能装新页签」。
