# Agent Note: 中栏间距、历史提示与右栏读数修正

Status: proposed

## Problem

本提案只覆盖阅读界面的显示与入口，不修改采集、派生和存储。2026-10-24 评审已对照当前实现核查；下列尺寸来自提案原有的合成浏览器记录，本次评审未重新测量，不能当作修订方案的验收结果。[工具配对页](../../implemented/feature/2026-10-24-trace-pair-rail-page.md)已交付，实施以现有配对入口为基础，无需等待另一个未提交改动。

**中栏序号占了过宽的槽位。** [生产样式](../../../../web/index.html)的 `.compact-meta` 宽 86px，1300px 断点为 76px，620px 断点为 22px；[步骤渲染](../../../../web/trace-view.js)只放请求序号。原合成记录在 1507px 视口下测得中栏可用宽 611px，标签起点 x=374、预览起点 x=445。收窄槽位能把空间让给内容，但序号位数不能按首次加载上限推断：[窗口存储](../../../../web/reader-store.js)的 `loadEarlier` 会累计追加历史，`windowLimit()` 的 100 只限制初始加载，`ordinalOf()` 按当前全部已载入请求编号。

**历史区常驻的起点提示可以删减。** [界面装配](../../../../web/app.js)的 `traceHtml()` 在 `olderCursor === null` 且存在请求时显示已到会话起点。它表达的是历史是否读尽，分隔线本身不能替代这个事实；删除它是降低常驻信息量的取舍。历史区已有顺序说明，可以保留加载入口与进行态，省去读尽后的文字。

**用量排版和计时标签难以对照。** `ledgerParts()` 用 `·` 将计时与用量各排成一行。原合成记录在 640px 右栏中测得两行各高 20px，构成图例六类共高 113px，整个折叠区高 284px；计时样本为 `首字 0.42s · 总 2.10s · 71 tok/s · 首个文本 0.48s`，用量样本为 `入 9,000 · 出 120 · 缓读 10,000 · 缓写 700 · 命中 51%`。窄栏折行后标签与数字不易对照，图例又列出了四个零值类别。

现有 `.chain-row` 提供标签列与值列，但 `dd` 没有 `text-align:right`，不能直接得到数字右对齐。逐项改成一行还会把两行读数展开成多行，图例省下的空间未必抵得过新增高度。排版目标是读清标签和值，不能先承诺整个折叠区变矮。

**显式 URL 页签被会话选择覆盖。** 初始化和 `popstate` 都解析 `tab`，随后 `selectSession()` 无条件重置为 `facts`；`updateURL()` 又按重置后的状态写回地址，丢掉显式声明。首次无声明进入读数页是现有默认，不属于这个缺陷。

路由页还有读取前提：`railBody()` 只取 `routes` 缓存，`loadWindowReads()` 不加载路由；现有 `ensureRoute()` 由页签点击或路由折叠事件触发。直接保留 `railTab` 无法让 URL 直达、切会话后的路由内容自动就绪。

## Proposal

### 一、缩窄序号槽，保留多位数空间

以 28px 作为短序号的基准宽度，统一三个断点的序号宽度规则。整个当前窗口共用一个宽度，按最大序号的位数为长序号扩展；宽度规则取 `max(28px, 位数 × 1ch + 8px)`，位数由步骤列表按当前 `rows.length` 写进 `--ord-digits`，`1ch` 在序号槽自己的等宽字号上取值，断点字号变化随计算生效；不按每行的数字单独撑宽，避免标签起点参差。加载历史后重算共享宽度，不截断序号，也不限制历史加载数量。

保留 `title` 中的请求序号语义与现有步骤按钮。按 86px 缩到 28px 算，同一布局下标签和预览应前移约 58px；原标签 x=374 的对应预测是 x=316，具体位置仍以浏览器测量为准。620px 的旧值为 22px，只能说明原样式更窄，不能证明增加到 28px 后没有溢出。

本项部分调整[中栏只呈现内容](../../implemented/simplification/2026-10-24-trace-content-only-and-wide-rail.md)的布局；36px 行高与不显示附加计量的决定继续保留。

### 二、删除读尽历史后的常驻文字

删除 `traceHtml()` 中已到会话起点的分支，保留正在读取更早记录的反馈和加载更早记录按钮。保留 `.history-loader` 的分隔线、内距与顺序说明，不新增另一个读尽标记。

这项只删终态文字，不改游标或错误处理。验收分别覆盖存在历史、读取中、读尽和空会话，不能用 `olderCursor === null` 单独证明会话加载成功。

### 三、读数按标签和值对齐，保留计时口径

计时与用量各用一个 `<dl class="chain">`，内部复用 `.chain-row` 的标签和值结构；新增局部的读数样式范围，为数值列设置右对齐、等宽数字与适当行距，不修改全局 `.chain-row dd`，以免改变路由等文字详情的排版。移除这两组读数中的 `·` 分隔符；旧 `.strip-row` 样式只在确认没有其他使用者后删除。

`ttft_ms` 和 `first_text_ms` 分别保留，标签使用首 token 与首个文本，说明中明确首 token 指第一个内容，可能是文本、推理或工具调用。上游 magpie 检出 `2374ffe1` 的 [usage.Record 定义](../../../../../../repos-external/magpie/internal/usage/usage.go)分别定义这两个结束事件，[上报校验](../../../../../../repos-external/magpie/internal/gateway/usage_ingest.go)也禁止首个文本早于首个内容。它们共享请求起点，但测量事件不同；数值相近或相等都不能作为合并依据。现有前端用 `toFixed(2)` 显示秒，精度为 0.01s，样本的 60ms 差异已经可见。删除 100ms 阈值与把另一个数藏进 `title` 的方案，也不把 `first_text_ms` 替作缺失的 `ttft_ms`。源码证据锚定上述检出，不代表已核对本机运行二进制版本或真实数据分布。

计时保持有值才展示，合法的 0 不按缺失处理；用量任一基础字段有值时保留各槽，缺值显示 `—`，全缺时不渲染该组。速度分母继续沿用现有 `总 − ttft_ms` 及其 `flow_ms` 回退规则，不随标签调整更换算法；`fold-count` 的总 / 出 / 命中摘要不变。

构成条与图例共用 `tokens > 0` 的可见类别，图例按 token 数降序。没有正值类别时不留下空的条和图例容器，仍保留可用总量、窗口、占用与原有缺失或估计说明。上游同一检出的 [Prompt.calibrate](../../../../../../repos-external/magpie/internal/gateway/prompt.go)会按总量缩放各类并舍入，因此已估计的正值类别也可能得到 0；零值不能解释为没有该类内容。零值与缺失类别在图例中均不可见，这个信息取舍需要明说；总量只能保留总数，不能证明每个未展示类别都已被估计覆盖。

`ledgerRowsHtml()` 和 `usageFoldHtml()` 共用 `ledgerParts()`，两条路径同时验收。窗口外请求已有详情对象，要显式传入 `ledgerRowsHtml(read.detail, read.detail)`，避免仍走默认 `detail = null` 而漏掉详情中的 `first_text_ms`。用量折叠键继续使用 `prompt:<req>`，本项不增加折叠键。

两列结构优先解决可读性，展开高度可能增加；需要比较 280px、640px 右栏下的总高度、换行与数字完整性。保留默认展开的现有行为，不能把折叠区位于末尾当作永远不占首屏的保证。

### 四、恢复页签声明，并补齐路由读取

初始化与浏览器历史恢复按 URL 解析合法页签，无有效声明时继续使用 `facts`；`selectSession()` 不再覆盖已经确定的页签。手动切会话保留当前顶层页签，但仍清除请求内的步骤与工具选择。这只保留页签偏好，不承诺保留跨请求的正文定位、工具四页或滚动位置。

当请求选择确定且当前页签为 `route` 时，显式调用现有 `ensureRoute(reqId)`。覆盖首次 URL 进入、`popstate`、手动切会话，以及保留路由页的刷新和请求定位路径。调用放在导航完成处，不在渲染函数内发起；沿用存储层的合并读取与失效规则，不重复建立缓存。无当前请求、窗口外或不存在的 trace 保持现有说明，不为它们预取路由。

步骤点击继续按 `resolveSelectedSource()` 分流：调用及已配对结果进入工具配对页，request/reply 来源进入正文；无来源的记录和辅助请求暂时保留进入读数页。未知回复块虽标为 `record`，但有 reply 来源，现有实现已经进入正文，不能把所有 `record` 统一归入保留页签分支。[现有来源解析回归](../../../../tests/trace-view.test.ts)覆盖了这种未知块；本次评审运行选中来源解析的 3 例测试通过，这不代表新提案已实现。增量事件行仍是进入读数并续读的动作入口。

### 仍需产品判断的范围

本提案建议维持无声明时的读数默认：其中本次回复默认展开，已有正文入口。若决定默认正文，需要同步初始化、`popstate` 缺省解析和 `updateURL()` 的缺省序列化约定，并验证旧链接；只改 `state.railTab` 初值不完整。

无来源 Event/Aux 是否保留当前页签，应独立于 URL 缺陷决定。在正文页点这种记录会更换请求并回退整份回复；在工具页会清掉 `toolOwner/toolOrd` 并退回调用列表。保持页签名称不能保证选中记录有对应内容，也不能保持原阅读位置。当前建议保留读数入口；若改成跟随页签，需要先明确无来源事件在每个页签中的展示目标。

## Alternatives considered

**按 100ms 合并首 token 与首个文本。** 时间接近不能证明事件相同，现有两位小数秒也能显示 60ms 差异。分别命名并保留有值字段更直接，没有阈值分支和悬停才能读到的指标。

**固定 28px，并假定最多 100 笔。** 初始加载上限不约束累计历史。统一最小宽度加窗口级位数扩展，既缩短常见序号槽，也保留长会话完整编号。

**只复用 `.chain-row`，不加局部样式。** 现有值列左对齐并允许任意位置折行，达不到数字右对齐要求。全局修改又会影响路由等文字详情，因此仅在读数范围设置样式。

**继续用平铺数字或改成 pill 加弹层。** 平铺在窄栏会散开，弹层则增加读取操作。本轮先用可直接读取的标签和值排版，并如实验收它增加的高度。

**删除 `selectSession()` 的赋值就完成 URL 修复。** 它能保住页签名，却不能触发路由读取。导航需要同时确定显示目标和取得该目标的数据，不能靠再点一次页签补齐。

**所有 `record` 保留当前页签或都进入正文。** `record` 包含有协议来源的未知回复块，也包含无来源状态记录；类型标签不足以决定阅读目标。沿用来源解析，暂不反转无来源记录进入读数的行为。

**保留起点文案和全部零值图例。** 信息更完整，但持续占用空间。本轮接受不常驻显示历史读尽状态与零值类别，加载反馈、数据总量及异常说明继续保留。

## Acceptance criteria

- 合成场景在 1507px 视口下，短序号槽宽 28px、行高 36px；相同布局下标签与预览前移约 58px。验证 1、99、100、999、1000 和更长序号，连续加载历史后同一窗口的标签起点一致且序号不被裁剪。覆盖 1300px、620px、400px 视口与桌面最窄中栏；同时检查元素边界和页面横向溢出。
- 历史读尽时只留下顺序说明；有更早记录时保留按钮，读取中保留反馈，空会话不出现起点声明。删除终态文字不改变加载游标与错误处理。
- 计时与用量的标签和值对齐，数值右边缘一致；覆盖两项计时相等、相差 60ms、明显不同、仅一项有值、0 与全部缺失，两项有值时始终分别展示。用量缺值仍为 `—`，费用及速度计算口径不变。
- 构成图例只显示正值类别；覆盖部分为零、全部为零、空类别和缺失总量。全零或空类别不留下空图表，已有总量与状态说明仍可见，不把未知总量变成 0。
- 在 280px、640px 右栏记录读数区和整个用量折叠区的实际高度；长数字完整，标签和值对应，窄栏不拆散数值。窗口外请求复用相同排版并保留已返回的首个文本值；其他 `.chain-row` 的文字详情样式不变。
- `?tab=body`、`?tab=tools`、`?tab=route` 在自动选择首会话和带 session/trace 的入口都保留声明，URL 写回后刷新仍一致；无效 tab 与无声明入口继续回退读数。覆盖 `popstate`、手动切会话、窗口内与窗口外 trace。
- 路由页首次进入、切会话及保留路由页的刷新或定位都自动读取当前请求的路由，不要求再次点击页签；验证内容所属请求、空路由、读取失败后可重试和已有缓存不重复读取。
- 调用和已配对结果仍进入配对页；未配对结果、System、输入、回复文本及有来源的未知块仍定位正文；无来源记录和 Aux 仍进入读数，增量事件仍续读。切会话不残留旧工具 owner。
- 实施时为计时缺值、URL 状态恢复和路由请求触发补最窄行为回归；布局用合成浏览器测量，不用源码字符串匹配冒充排版验证。运行受影响的前端测试、`bun run typecheck`、`bun run verify:notes` 与 `git diff --check`；全量 `bun test` 留给显式全量验收。

## Risks

- **缩窄槽位不等于任意窗口都安全。** 边栏开合、断点、字体与序号位数都会影响可用宽度。验收要覆盖长序号与元素裁剪，不能只检查页面是否出现横向滚动。
- **两列读数可能增高。** 图例删除零值不保证抵消逐项排版增加的高度。若完整读数样本过长，应在局部布局中调整密度，不通过隐藏计时字段弥补。
- **隐藏零值类别会丢失类别级状态。** 读者无法从图例区分零值与未覆盖类别；总量和估计说明不能恢复这层信息。本轮接受该展示取舍，不改变后端数据。
- **页签保留带来跨会话空态。** 没有工具或路由的请求仍应给出对应空态，不自动跳回读数。路由加载必须跟随实际选中请求，失败不能伪装成无路由。
- **部分取代已有决策。** 本项涉及[用量折叠](../../implemented/simplification/2026-10-24-usage-ledger-fold.md)的读数排版，以及[中栏只呈现内容](../../implemented/simplification/2026-10-24-trace-content-only-and-wide-rail.md)的槽位宽度；两篇仍有有效决定，不归档。实施时同步事实与交叉链接，并更新[架构中的轨迹阅读布局](../../../../docs/architecture-design.md#轨迹阅读布局)。[角色与选择一致性](../../implemented/bug-fix/2026-10-24-reader-role-and-selection-consistency.md)和[配对页](../../implemented/feature/2026-10-24-trace-pair-rail-page.md)的来源导航规则继续有效。
