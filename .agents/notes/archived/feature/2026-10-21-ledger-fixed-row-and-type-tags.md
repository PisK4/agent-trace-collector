# Agent Note: 账本折叠行固定高度与类型标签列

Status: implemented
Archived: 2026-10-24

## Problem

账本折叠行的高度取决于有没有回复文本，读数列宽度随内容变化，每类消息只有一个灰色描边标签。滚动长轨迹时每行的主文本起点不同，标签没有颜色，扫读必须先逐条读文字。参考版式把消息类别放在行首，而当时的实现是时间在前、标签在内容格内，读起来是「时间 → 标签 → 文本」。

## Decision

折叠行固定 56px，两行各 18px；第二行没有回复也保留空槽，所有行的主文本起点一致。行首依次是状态点、类型标签列、时间、内容、读数列、展开标记；类型标签固定 56×18，主行与回复行各一个槽位，颜色沿用现有 `--k-*` token。标题生成请求用紫色「标题」标签，分支标记、异常标志与 HTTP 状态收进右对齐的读数列。失败行在读数列之外再加 2px 红色内嵌条。

版式、各断点尺寸与合成库验收记录见 [README 的中栏版式一节](../../../../README.md#中栏版式)，实现见 [web/app.js](../../../../web/app.js) 与 [web/index.html](../../../../web/index.html)。

## Alternatives considered

**保留自适应行高。** 有回复的行更高，主文本的 y 坐标逐行不同，长轨迹无法纵向扫读。

**标签留在内容格内。** 第一版这样实现，读序是「时间 → 标签 → 文本」；参考版式要求标签在行首，标签因此独立成列，两行共用同一列的两个槽位。

**只在窄屏隐藏可选读数，不隐藏整列。** 620px 以下保留读数列会挤压内容或产生横向滚动；最终选择整列隐藏，代价是分支标记与 HTTP 状态在窄屏不可见，状态点仍表达成功/失败。

**给标签只用文字、不加颜色。** 颜色承担类别区分，文字标签承担可读性；只留文字会让扫读重新依赖逐字阅读。

## Consequences

- 每行等高、标签与文本起点固定，滚动时不再左右跳。
- 固定列宽在 1240px 以下压缩读数列、620px 以下隐藏整列；分支标记在窄屏不可见是已知取舍。
- 两行标签槽位即使没有回复也保留 18px，换来全表对齐。
- 版式没有自动化几何测试；验证使用元素几何与计算样式，本机 CDP 截图超时。
