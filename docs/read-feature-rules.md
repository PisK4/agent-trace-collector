# 读取功能接入规则

本文是[读取架构提案](../.agents/notes/proposed/architecture/2026-11-02-read-architecture-and-client-seams.md)配套的评审草案，尚未作为现行实现生效。批准并落地后，入口只保留一条指向本文的规则；行为与类型归代码及[架构设计](architecture-design.md)，不在各 feature 再抄一份。

## 先确定读取用途

新增页面功能前，先找拥有相同事实的 module。已有详情、正文区间、工具结果、路由、轮次、会话汇总或条目目录能满足时，复用原 Interface。只有输入、返回事实或一致性要求不同才新增具名操作。新增 UI 不自动意味着新增 HTTP 路由。

一个操作必须回答以下问题，答案写在其类型和函数契约旁，评审时按下表验证。默认值与上限以契约代码为唯一事实源，规则不手抄数字。

| 要求 | 查证方法 |
| --- | --- |
| 结果是谁的、何时失效 | 检查 canonical 身份、reading token、输入修订与回收状态；构造同 id 换版和迟到响应 |
| 谁持有缓存、何时释放 | 检查 page/session/request/dialog owner、退出函数和 timer；通过关闭、切会话与 dispose 验证 |
| 读取何时发生 | 区分首屏、显式交互、范围准备和后台补齐；记录操作序列，确认未触发的详情没有预取 |
| 同一请求怎样共享 | 检查去重键是否含完整输入与版本；取消一个消费者不能误伤其他 owner |
| 工作怎样结束 | 检查游标、条数、字节、同步耗时和单项超大；确认每次截断都推进且缺口如实可见 |
| 失败怎样呈现和恢复 | 分别验证非法输入、404、409、取消、鉴权、服务不可用、响应畸形；不把失败写为空成功 |
| 怎样更新界面 | 标明影响的请求、前驱/调用方依赖和会话头；确认只更新变化组，焦点和锚点保持 |
| 怎样定位性能成本 | 固定操作名计时，分别记录排队、执行、字节、解析和投影；不记录正文、token 与真实路径 |

## 代码职责

只有 HTTP adapter 拼路径、调用 Fetch、解析 Response 和映射 HTTP status。feature 通过 reader-store 或弹窗使用的读取 facade 发出具名读取；不直接调用 adapter，不另建队列。HTTP adapter 的运行时校验至少覆盖身份、版本和数据完整对应，TypeScript 类型不能替代外部输入校验。

调度 module 管执行、容量、公平性和取消，不解释业务状态。reader-store 管证据缓存、同记录去重、两套游标与自动恢复。弹窗只持有自身的交互状态和有限结果；关闭即取消其 scope，不给全局正文缓存直接赋值。

准备 module 决定目标优先、依赖和读取预算。投影 module 无网络、无 DOM，不更改选择；读取完成后只更新受影响模型。DOM module 管转义、稳定键、焦点、选择及视口。新增 feature 不通过渲染函数偷偷取数，不以对所有行增加 revision 代替依赖分析。

## 批量与调度

优先以用户阅读用例组成批次，禁止通用任意 URL 列表或 SQL 执行入口。批内每项都有稳定 index、身份、结果和错误；客户端先检查整批完整对应，再接纳单项。不把一个 409 扩大成整批作废，不把跨批独立快照描述为整场冻结。

所有读取都进入同一调度 module，包括 stats 和上下文明细。后台准备只排有限批次，队列满时等待生产者下一轮或返回明确 queue_full，不无限登记 Promise。读取任务直到正文消费和解析结束才释放活动槽。

取消移除待发任务并通知在途任务，缓存回写仍检查 epoch、记录归属、修订和 token。HTTP 取消不保证终止服务端同步工作。普通网络错误、鉴权失败与 503 不展开成单项风暴；版本冲突沿用原有恢复政策。

自动重试、自动补齐范围、正文淘汰和轮次导航都是可观察行为。变更这些政策必须说明受影响场景与反例，不能以性能重构名义静默修改。

## 新 feature 的最小交付

1. 在读取契约添加具名输入/输出，或说明复用哪个操作；类型只含可序列化事实。
2. 更新后端持有事实的查询和 HTTP adapter；复用别名、token、投影和协议解释规则。
3. 明确 owner、priority、取消时机和缓存键；复用统一调度，不在 feature 内设并发常量。
4. 让 store 或准备流程产出带身份的变化；投影登记依赖，DOM 保留选择与锚点。
5. 添加能观察错误结果的行为测试、取消/迟到反例及必要的性能工作量断言。
6. 更新所属 Agent Note 与现行事实文档，运行受影响的最窄测试、typecheck 与 notes 门禁。

这些步骤包含 feature 的完成条件，不能只交付一个端点就宣称界面接入完整。HTTP adapter 编码测试与真实查询契约测试各承担不同职责；避免为同一行为叠加大量只验证转发的测试。

## 桌面客户端约束

桌面读取遵守相同事实、错误和预算。WebView 可复用 JS module；Swift 等原生 UI 复用契约与后端规则，需要自身 adapter 和协调实现。当前不为尚未选择的 IPC 或框架写空壳。

UI 不直接写生产 SQLite，不持有数据库 schema 和派生重算流程。窗口退出只释放窗口 owner，不隐式停止 launchd 采集。宿主连接、凭证和深链解析在装配处注入，证据 module 不读取 localStorage、宿主全局变量或任意环境变量。

新宿主必须明确身份来源、origin、读权限与导航范围。不能为连接方便扩大监听地址、开放跨域或把原始文件系统访问暴露成通用 bridge。应用协议版本与 reading token 分别管理；独立发布客户端出现时，再交付版本协商和兼容测试。

## 评审否决条件

出现直接 Fetch 旁路、第二份可写证据缓存、无界任务/响应、未校验迟到回写、以空数组掩盖失败、投影触发网络，或为未来平台引入未使用 adapter 时，不进入合并。单次同步工作超过响应预算而没有观测和后续处理路径，也不能仅以请求数下降关闭性能问题。

这份规则不替代数据库事务与采集约束。写事务不得 await；单 writer、正文回收、派生版本升级和切片冻结继续遵守项目入口与架构文档。
