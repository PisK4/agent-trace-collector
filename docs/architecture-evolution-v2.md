# ATC 架构演进方案 v2

本文是这一轮架构改造的目标约束与阶段划分，组织字段保真、证据重建、Agent 语义与机器流量容量之间的依赖。交付记录与验收见[架构演进实施入口](superpowers/plans/2026-10-22-atc-evolution-implementation.md)；现行设计见[收敛型技术架构设计](architecture-design.md)，运行操作见[运维手册](operations.md)。

结构升级采用破坏式替换：旧库拒绝打开后由运维删除重建，不提供跨结构迁移。下文涉及迁移阶段的部分仅保留为提案背景，现行规则见[旧库删除重建](../.agents/notes/implemented/architecture/2026-10-23-destructive-schema-replacement.md)。

## 目标与完成条件

ATC 要持续记录机器调用，并让读者区分请求事实、上游报告、ATC 解释与尚缺证据。兼容新的 Agent 时，专有规则应集中在少量位置；请求增长时，采集、后台派生和阅读应有明确的工作量限制。

下一版同时追求三项结果：字段与多次尝试的解释正确；新增已知 Agent 语义不再要求前后端分别识别；混合负载下的采集与查询能够满足明确的延迟预算。三项分别验收。新增一个注册表不能证明容量改善，字段数量增加也不能证明事实更准确。

技术约束沿用现有设计：单进程 TypeScript + Bun、SQLite WAL 与单 writer、独立只读连接、原生 JavaScript 页面、不增加第三方运行依赖。ATC 继续作为 magpie 的旁路记录器，保留请求为主实体、会话为派生阅读视图的定位。采集范围受上游可观察面限制，不承诺覆盖每一笔内部辅助调用。hook 保存的是客户端交给网关的脱敏协议对象，后续仍可能发生转换和逐 provider 改写；不能标成每个实际模型收到的逐字节输入，依据见[现有接入约定](magpie-mechanisms-research.md#开始实现前要落实的输入约定)。

## 为什么需要统筹重构

现有两份提案分别指出来源读错与用途解释缺位，共同依赖重建、版本、隐私和调度。当前机制的源码核对、反例及验证范围集中在[联合评审](agent-request-kind-review.md#与字段保真方案的联合评估)及[执行与恢复补充评审](agent-request-kind-review.md#执行与恢复补充评审)，本文维护目标职责与验收。

| 当前改动路径 | 目标改动路径 | 评审依据 |
| --- | --- | --- |
| 来源 mapper、多处请求写入与离线回填 | 来源 Adapter 统一解释；投影统一收集 owner 证据、判断完整性并选择事实 | [字段与回填](agent-request-kind-review.md#字段修复必须同时覆盖收敛与历史回填)、[完整性](agent-request-kind-review.md#来源完整性与隐私一致性) |
| 脱敏 payload、结构化列与长期摘要分别形成 | 同一隐私对象派生所有可保存内容，历史隐私修复显式执行 | [隐私路径](agent-request-kind-review.md#脱敏要覆盖结构化列与摘要) |
| 整组派生、页面用途与包装解释 | 请求用途独立触发，多个消费者共用语义规则 | [迁移范围](agent-request-kind-review.md#现有-feature-的完整迁移评估)、[触发](agent-request-kind-review.md#请求触发与完成恢复) |
| 来源映射版本、保留列及维护报告 | 迁移前核对写入者与消费者，避免把协议解析版本、重算次数或默认值当作来源映射能力 | [版本与旧测试](agent-request-kind-review.md#版本消费者与旧测试契约) |
| 链、主链、工具和摘要分段执行 | 一个执行入口统一排序、依赖、完成确认与恢复，再按测量切片 | [派生正确性](agent-request-kind-review.md#派生排序与摘要依赖)、[版本与旧测试](agent-request-kind-review.md#版本消费者与旧测试契约) |

推荐优先加深三个 Module：来源解释与请求投影、请求语义解释、派生执行。它们分别集中上游字段知识、客户端语义知识和重算成本。新增文件必须承载这些知识的实际迁移；只增加转发层不提高 Depth。

删除检验采用一条可直接检查的规则：删掉某个 Module 后，原本集中的复杂度是否回到多个调用者。来源投影应集中 owner 证据收集、完整性判断、模型与尝试选择；请求语义集中 title、包装与技能规则；派生执行集中实时 tick 与维护命令共用的排序、阶段依赖和完成协议。只包装 Store、为每个 Agent 建空壳或为每个字段建专用 Module，没有同样的收益。

| 候选 | 当前改动路径 → 目标改动路径 | 推荐程度与先后 |
| --- | --- | --- |
| 来源解释与请求投影 | mapper + 多个请求写入点 + 回填各自解释 → Module 按 owner 收集证据、判断完整性并集中选择；来源 Adapter 解释字段，在线与离线共用 | 强：先解决会持续写错的数据，作为语义与阅读的前提 |
| 请求语义解释 | derive 与 web 各自猜用途、清洗、解析 → 三个独立语义操作，派生和正文阅读消费同一规则 | 强：已有重复及不同真实形状，迁移能直接删除分散规则 |
| 派生执行 | tick 调全组 derive，再自行工具配对 → 一个执行入口管理受影响范围、预算、提交与恢复 | 值得推进：先测量并集中现有调用，再按瓶颈增加切片或增量 |


## 目标组织与职责

下面是数据经过各 Module 的逻辑顺序，不要求每行新建目录、进程或独立表。

```text
账本 / 路由 / hook
        ↓
来源读取 + 来源 Adapter + 统一隐私处理
        ↓
证据身份与 owner 关联 → 请求事实投影 + 长期路由摘要
        ↓                         ↓
请求语义解释                  独立只读查询
        ↓                         ↑
会话前驱 / 链角色 / 工具关联 ──────┘
                                  ↓
                      正文分页解释与阅读页面
```

协议 Adapter 为请求语义和通用派生提供消息、文本、工具定义、调用与结果的协议解释。正文读取与解压仍属于调用上下文；Agent 规则不取得数据库、网络或写库能力。后台调度限制上述任务的单批工作量，容量准入继续由统一磁盘策略控制。

| Module | 调用者应知道的 Interface | 内部集中承担的 Implementation | 预期收益 |
| --- | --- | --- | --- |
| 来源解释与请求投影 | 已关联的请求身份、当前事务上下文及目标映射版本；输出确定更新、完整性与未决原因 | 按 owner 收集证据引用、可用来源和长期事实；判断完整性，集中键名、类型、缺失、优先级及尝试选择 | 在线和回填穿过同一 Seam，收集与选择从全部调用者消失，改善 Locality |
| 请求语义解释 | 已知 Agent 标签、协议视图与证据状态；输出用途、链参与策略、输入解释或技能声明 | 固定规则顺序、命中依据、规则版本、缺证据处理；三个操作各自独立 | 删除页面的重复识别；相同规则服务派生和正文阅读，形成 Leverage |
| 派生执行 | 受影响范围、目标算法、单批预算；返回进度和未完成工作 | 合并触发、统一逻辑顺序与阶段依赖、数据复用、分批计算、过期防护及恢复 | 调用者不再自行组织扫描、配对和摘要阶段，成本与正确性从同一 Seam 验收 |
| 读模型与正文阅读 | 稳定 ID、keyset 游标、正文区间、明确状态 | 摘要读取、消息级解释、能力覆盖状态、路由结构的安全投影 | 列表不解压正文，页面只组织阅读与交互 |

这是职责提案，函数名和 TypeScript 类型在对应阶段结合调用者确定。保留现有 Store 事务方式，不引入通用 Repository、可插拔数据库或全局事件总线。协议已有 anthropic/chat 两个真实 Adapter；Agent 专有规则也已有不同解析形状，因此这些 Seam 有实际变化依据。其它位置没有第二种实际变化时，先用具体函数。

### 来源解释与请求投影

来源 Adapter 读取上游真实结构，保存未知字段，报告可选字段缺失与非法类型。稳定的物理证据身份仍按现有机制生成，不由 Profile 或显示文本生成。请求投影负责从属于同一请求的证据集选择事实，不能让每个写入点各自补默认值。

版本在区间内不能证明字段解释正确。`src/sources/magpie.ts:286` 的现有 probeMagpie 检查版本与可达性；[现行设计](architecture-design.md#版本与形状漂移)还要求持续检查来源形状。下一版将必要键、合法省略、非法类型和未知键的检查放进来源解释路径，按来源记录不含正文的计数与短原因，不为一次可选缺失降级整批。先覆盖本轮读错的键与类型，不另建通用 schema 框架。

隐私处理先于内容落盘与摘要提取。关联需要的 route_id、物理偏移与响应 ID 应在专用提取路径保持其既有语义，合成测试确认没有被泛化脱敏误伤；account、错误文本、候选、尝试数组和 prompt parts 从统一处理后的对象形成列与摘要。来源键 account 与 providerAccount 的别名归一放在来源 Adapter，两种入口使用相同的稳定占位符，不能只处理 providerAccount。未知原始字段也只保留脱敏后的版本。默认查询响应继续遵守[既有账号与 host 披露限制](architecture-design.md#安全边界)。

在线入口从处理后的同一对象形成结构化列、payload 和长期摘要，所有来源入口调用相同规则；改变证据到达顺序不能改变最终隐私形态。当前路径差异与反例见[来源完整性与隐私一致性](agent-request-kind-review.md#来源完整性与隐私一致性)。

历史字段重映射默认只读已保存 payload，不对整份对象重复运行脱敏器。修复旧 account 明文属于显式隐私变换：保留已有占位符，只处理仍需修复的路径，记录变换版本与可恢复范围；不能以不重脱敏为由继续传播旧明文，也不能靠换盐把所有值重新散列。占位符幂等缺口的核对见[同一评审](agent-request-kind-review.md#来源完整性与隐私一致性)。缺少原盐或旧规则身份时先报告限制，恢复所需凭据不写入方案或 fixture。

稳定占位符依赖原 redaction.salt。首次空库可生成盐；已有数据目录缺盐、恢复后盐不匹配或无法证明绑定时，应停止新摄入并报告恢复限制，不静默生成新盐后继续宣称可跨记录比较。阶段 2 定义库与盐的绑定标识及旧库显式确认路径，绑定标识不包含盐明文，也不能替旧库证明原盐身份。可恢复采集的备份须包含数据库、匹配的盐及绑定信息，使用现有受限权限；仅数据库的快照可用于受限读取，不能据此恢复占位符连续性。认证 token 属另一项恢复身份，可恢复或显式重配；恢复盐不等于恢复认证。缺失或损坏路径用合成盐验收，现有备份范围依据见[盐与备份边界](agent-request-kind-review.md#盐与备份边界)。

投影需要集中回答以下问题，不把答案留给页面或 Feature：

| 事实族 | 下一版处理原则 |
| --- | --- |
| 请求模型、provider 模型、回复声明模型 | req、model、served 分别保留含义；req 缺失保持未知。显示层需要备用值时说明其来源 |
| hook 模型暂存 | hook 报告模型与 success 独立长期保存到存活 owner，直接命中和合并走同一投影规则；ledger.req 缺失不删除 hook 报告，hook 值不写成 ledger.req 或 vendor served。界面可显示带 hook 来源的备用值，不能冒充请求值已获账本确认；两源不一致时并存并显示来源，不能按到达顺序覆盖。HTTP status 仅保存实得状态，不由 success 合成 |
| 最终尝试与其它尝试 | provider、host、account、effort、tier_sent、tier_served、err 跟随同一选定尝试；无最终证据时保留 pending_final 或失败状态，不跨尝试拼接非空字段 |
| 请求层身份与声明 | session、native_session、Agent 标签及原始 kind 保留来源；native_session 不替换请求唯一身份或现有 conv_key/actor |
| 上游 kind | ledger 与 route 各自保留非空报告值及可用状态；单一值可用，一致则合并来源，多值冲突不选边，具体建议见下节。来源归并只提供信号，不能直接决定退出主链 |
| Prompt 计数 | 合法、受支持 Prompt 中 true 表示已校准，false/合法省略表示未校准；Prompt 缺失或非法保持未知。总量校准不证明各 part 精确；held 表示上游持有历史，不得把当前 body 当完整会话 |
| 费用 | 账本 cost 是客户端自报 OwnCost，API cost/priced 是定价观测；两者不能互相覆盖或混合汇总 |

这些规则不要求所有字段进入 request。长期存储按消费者和恢复需求选择：来源 kind、语义判定依据与版本为本轮共同必需；effort、tier 和错误摘要按详情消费确定；account、host 的上浮与公开需要另行说明用途；没有长期消费者的字段继续留在短期脱敏证据中。索引仅随查询需要增加。

路由尝试已经有 order/tries 可读，不先建立新的 attempt 专表。先验证长期摘要是否足以保留实际需要的尝试事实；如证实账本尝试无法用现有结构表达，再在该阶段选择存储形状。`开源源码@magpie-2374ffe` 中 routeUsage 可包含 Deferred 计费条目，用量条目与尝试并非严格一一对应，不能按数组位置强行配对，依据见[已有机制研究](magpie-mechanisms-research.md#估计值与报告值)。route_summary.z 不是完整 raw_route，不能将其视为恢复任意字段的来源，也不新增第三份重复摘要。

### 投影输入完整性与来源冲突

建议将来源投影做成一个同步操作：调用方先按现有机制关联证据 owner，再把稳定请求身份、当前事务上下文与目标映射版本交给 Module。Module 内按 request_evidence 收集全部归属引用、可重读来源和长期保留事实，判断完整性，再选择字段并返回请求更新与不能复核的原因，由当前事务写入。在线 ledger、route、hook 与离线重建共用这一流程，调用方不各自维护查询集合或完整性判断。身份分配、证据幂等、alias 与正文迁移、费用观测、文件游标保持原职责；来源投影不变成通用 Store 包装。

证据过期只说明输入不能重读，不能证明字段为空或尝试减少。投影须区分完整可重算、部分可复核与不可复核；最终事实族和尝试合计分别判断。完整证据允许修正旧错误值；证据不完整时保留已有最终尝试、起始时间和合计，并标其旧映射版本及限制。不得将 request 旧值作为新规则已确认的输入，也不能简单取 MAX 保住合计来掩盖重复计费。新的物理行是否是历史重复与是否有完整聚合输入是两项检查，缺乏稳定尝试身份时保持待核对。

完整性判断须读取 owner 的全部证据引用及 present/expired 等状态，不能只查询存活 raw。对证据不完整的事实族，不从部分 raw 宣布完成重建；具体反例见[来源完整性与隐私一致性](agent-request-kind-review.md#来源完整性与隐私一致性)。

上游 kind 采用以下保守归并作为本轮推荐，属于 `推断`，尚未交付。对同一 owner 分别收集 ledger、route 的非空报告集合；空串、未报告、非法类型各自记录状态，不把它们当成撤销。每个来源只有一个已知值且另一来源未知时采用该值并说明单源；两源一致时合并来源；任一来源多值或两源不同则保留冲突，归并值未知。未知 kind 字符串仍保留原值，不因未登记就判为非法。用途分类可在适用 Agent 的强请求指纹上独立成立，但不能把来源冲突隐藏为已确认的上游报告。

route 缺少可信快照修订号，`src/reconcile.ts:499` 的 upsert 不能证明后到版本更新。为满足重复读取与到达顺序无关，长期仅保留已观察到的非空 kind 集合及冲突状态；有实证的撤销或更正规则出现前，不按到达顺序清除冲突，也不保存整份快照历史。单源集合超过来源尺寸或元数据预算时保留冲突与溢出状态；短样本按稳定字节序截取，不能保留最先到的若干值而让排列改变报告。溢出不再返回可用的单一归并值，不保存无限快照。相同证据集合的排列、重复、缺键快照和 raw 过期均应得到相同报告；标量列或短 JSON 的具体形状在 schema 阶段按读取成本确定。

### 请求语义独立于会话归属

请求用途、输入解释和技能声明都描述当前请求，不必等待 actor 确认。现有 derive_queue 按 conv_key/actor 工作，不能直接成为这些结果唯一的触发路径。下一版要在请求证据变化后安排请求级解释，actor 未定时保留归属未定状态；只把前驱、链角色和跨请求工具关系留到归属确认后计算。

推荐在请求行保存用途判定的待处理状态，复用既有 writer 与后台 tick；derive_queue 继续表示 conv_key/actor 分组，不塞入 actor 哨兵，也不增加通用任务框架。当前队列主键不能表达 actor 未定的单笔请求；`src/hook.ts:214` 的直接命中路径与 `src/reconcile.ts:314` 的 route 应用又没有完整覆盖触发。持久化状态比只在写入完成后调用内存回调更容易恢复。

待处理状态描述是否需要工作，判定状态描述结果依据，两者分开。请求行保存单调输入修订及结果所消费的修订；这与 derive_queue 的组级输入修订分别存在，具体存储与迁移见 [C 详细计划](superpowers/plans/2026-10-22-atc-durable-rebuild.md)。新请求、正文/回复补齐、适用 Agent 或来源 kind 变化、owner 合并都在原写事务内增加请求修订并标记待处理；正文回收也使旧任务失效，仅费用或诊断计数变化不触发用途重判。合并后的修订不能复用任一旧任务仍可命中的身份。同步阶段在完整入口的同一 writer 事务内读取、解释并按请求身份、输入修订与规则目标保存终态；切片阶段有界读取后在事务外解释，短同步事务复核相同依赖，跨 yield 必须校验。这里复用单进程任务，不引入 worker 线程。updated_at 不作修订号，它也受其它变化影响，且毫秒值可能重复。

| 触发或状态 | 请求级处理 | 分组处理 |
| --- | --- | --- |
| hook-only、actor 未定 | 正常判用途；缺回复/未知 Agent 保存相应结果，暂不等待会话 | 保持归属未知，不建共享哨兵组 |
| hook 直接并入已有请求、正文或标签后到 | 同事务标记；重复同一 hook_id 无新增工作 | 已知组立即标记失效，语义结果变化后再合并触发 |
| owner 合并、conv/actor 改变 | 存活请求重新判定，不能直接复制任一待删行的 clean 状态 | 修改前旧组、修改后新组同时失效；空旧组也须处理完成 |
| 正文回收 | 保留旧判定和旧版本，标为无法复核；未判过则为缺证据；可用的来源信号仍可独立解释 | 使进行中的旧计算失效，按当前可读性重建；不能用进程内旧正文绕过回收 |
| 规则升级 | 显式迁移按范围标记待处理；有正文重判，无正文保留旧版本并给出终态原因 | 依赖的用途政策改变时标记对应组，不能只比较执行次数 |

解释完成、因缺证据无法继续和输入不受支持都能清除本次待处理标记，后续输入变化再触发；解析错误保留短原因及有界重试，不能让一条坏记录占住所有任务。保存旧结论时不得把规则版本改成新版本。输入解释和技能提取按正文读取执行，复用同一规则包；本轮只持久化用途及通用派生确实消费的短结果，不为按需能力阅读建立逐请求常驻任务。

Agent 语义保持三个独立操作：用途分类、输入解释、技能提取。同一 chat 请求可以同时有 harness 包装与技能声明。Profile 只选择确有依据的规则，不建立全能 Feature Interface，也不为仅使用通用规则的标签建空 Profile。工具定义归协议 Adapter，用户首句备用标题及会话最终标题选择归通用派生与读模型。

用途分类保存 ATC 稳定类别，同时保留上游报告。固定优先级先处理适用 Agent 下的强请求指纹，再用共享启发式；title 保持现有识别兼容及其误判边界。classifier 的保守门槛与反例见[分类器门槛评审](agent-request-kind-review.md#分类器门槛会把普通请求移出主链)。无匹配表示尚未识别特殊用途，不能同时宣称证据已确认属于 chat。存储可以保留兼容的 chat 值，但必须能从判定状态区分默认值、已识别类别和无法复核的旧结论。

链参与策略与最终 chain_role 独立。已确认 title/classifier 退出祖先与工具配对候选；未知类别不自动成为 aux。正文不可比时沿用中性处理，不能改成 branch。普通未知用途默认沿用既有 chat 链参与政策并标未识别，该兼容建议需显式用例固定，避免以类别命名推导策略。会话标题候选、列表轮次与工具配对都需消费同一参与政策；`src/queries.ts:102` 的标题 SQL 也属于贯通范围，不能只替换 derive 中的判断。

规则 ID、规则版本、短信号代码、判定状态就地保存到请求，不复制 system 或 transcript 全文，不建立独立证据台账。正文存在时允许新规则重新判断；正文已回收时保留旧结论与旧版本，并标无法复核。算法升级不能把保留旧结果写成新规则已确认。

### 派生执行与调度

先区分请求事实、请求语义、会话派生的依赖变化，再讨论增量。schema 版本表达结构；来源映射版本表达字段解释；语义规则版本表达用途或包装解释；会话算法版本表达前驱、角色和工具关联。adapter_version 保持现有协议解析语义，redact_version 保持正文脱敏语义，不将它们重解释为来源映射版本。来源映射与显式历史隐私变换另行记录版本及作用范围，阶段 2 落 schema 前确定存放位置；未接入写入路径的 match_version、attempt_derive_version 与默认 instance_key 不能充当已实现能力，每项在迁移中明确接入、保留或移除，不因列已存在就复用。

derive_version 不再用累加次数比较算法新旧；历史值必须标为旧口径，执行次数如有诊断需求另记。维护 rebuild 报告同步区分目标算法、实际产出算法、未完成数量与保留旧版本结果数量，混合版本不能用 MAX 概括成整组完成。实施同时修改维护输出、对应断言及运维字段说明，消费者依据见[版本与旧测试契约](agent-request-kind-review.md#版本消费者与旧测试契约)。

先修正完整组重建的排序与阶段依赖，再将其作为正确性基准。派生执行 Module 定义一个确定的逻辑顺序，前驱候选遍历、主链根选择和工具先后判断共同使用；规定来源混合、缺键及相同键时的比较与兜底。存在稳定证据身份时，不以摄入分配的 req_id 改变语义关系；只有兜底顺序的场景不得冒充已证明因果先后。来源后补使排序依据变化时使整组失效。页面可保留时间加 req_id 的 keyset 分页，页面相邻不作为前驱或工具配对依据，排序变动与派生发布后按代际刷新关系。

在修正后的完整基准上，逐步合并同组触发、复用已读取的指纹与解码对象、避免不变数据重复写入，再按请求数、候选比较或实际耗时切片。仅在两个组之间 yield 不能限制超长组；耗时预算不能中断一次同步解压，需要保留既有单对象尺寸限制。

派生执行采用同一个入口驱动请求判定与分组阶段，实时 tick、维护命令和回填不再自行拼接 drainDerive 与 pairToolCalls。执行依赖为请求用途与参与策略、链及确定增量、角色与工具关联、依赖工具的摘要、完成确认；不依赖工具的格式化可提前，但摘要不得隐式读取上一轮工具表。工具名沿本次确定的调用关系读取，限定当前 conv/actor、调用请求和调用位置；切片时再限定计算代际。call_id 只作匹配信号，歧义或未知关联使用内容兜底及状态，不能全表取一个名称。完成确认晚于所有阶段，进度与整组完成分别报告，[已核对的恢复与依赖问题](agent-request-kind-review.md#执行与恢复补充评审)不靠合并调用名称解决。

建议分两步加深执行 Module。先修正排序与摘要依赖，在不切片时将链、角色、工具配对、摘要和完成确认归入同一同步任务事务；这一步不宣称限制长组占用。进入跨事务切片时，仅为派生结果引入计算代际：保留上一份已发布结果，将本次链、标题/摘要和工具关系写到未发布代际，完成后用短事务切换发布指针。请求事实、正文和来源证据不复制。

代际结果必须能独立于 request 事实维护，推荐按请求与代际使用独立派生结果表，并为工具关系保存对应代际；分组发布指针选择可读结果。req_kind、model_title 等请求级解释依旧由请求语义持有，组计算记录所消费的请求修订，不重复拥有其权威值。同步执行阶段可继续使用现有列；若阶段 2 一并引入代际结构，则在该阶段迁移前冻结字段归属、表键、保留元信息与查询索引；若切片独立交付，则在切片的 schema 迁移前完成同样检查。任何切片实现都不得先落计算再补存储设计，具体索引和批量数值以合成查询测量确定。

只在查询侧屏蔽、同时原地覆写旧派生值的备选不足以保住历史：本次已覆盖旧摘要而尚未完成时若正文回收，旧结果已丢，本次结果又不能确认。为避免这个状态，计算代际必须与已发布代际分开，保留正文回收前最后一次完整产物；回收使本次计算失效并放弃其临时结果。读取旧产物时附旧算法及过期/无法复核状态，不能冒充当前输入已确认。

分组进度复用扩展后的 derive_queue，记录组输入修订与目标算法；引入切片时再记录已发布修订、计算代际和发布指针。任务标识不能在删行重建后复用；可以保留组记录，空组最终清理时需让存活任务失效。请求待解释状态只负责请求用途。持久化祖先数组、解码缓存和任意步骤检查点仍不属于第一轮要求，切片重启可丢弃未发布代际并从头重建。

下表描述跨事务切片的提交要求；初期同步入口保留相同依赖顺序，在一次任务事务中完成，不提前要求代际表。

| 执行阶段 | 有界工作与提交要求 | 查询可依赖的结果 |
| --- | --- | --- |
| 输入变化 | 原写事务增加受影响组的输入修订并标记待重建；来源归属迁移覆盖两组 | 请求事实和可读正文继续可查；依赖组的结果标记过期 |
| 请求用途 | 先排空当前组所需的请求判定，或等待其得到缺证据终态；变化合并到组修订 | 独立展示请求用途及依据；不能同时把旧链角色标为当前解释 |
| 链与确定增量 | 按统一逻辑顺序计算；按请求、引用、候选比较和写入行数分批，只写计算代际，每次提交校验输入修订与算法目标 | 未发布代际不可见；旧结果仅作带状态的历史结果 |
| 角色与工具 | 按读取、候选和写入预算切片，消费本代际链结果及统一顺序；配对结果显式供后续摘要消费 | 新关系尚未发布，不能被旧代际摘要隐式读取 |
| 标题与摘要 | 消费本次链、参与策略和确定工具关联；承接的历史摘要/工具关系逐行携带原算法、原输入依据和保留原因，不能只引用即将清理的旧代际 | 正文已回收的旧结果仅作历史保留，不作为新算法复核 |
| 完成确认 | 短事务核对输入修订未变、组内无待解释依赖、全部阶段完成，再切换发布指针 | 同一响应读取该组同一完整代际；旧代际随后按批清理 |

查询通过同一个只读快照读取分组状态、发布指针与结果，返回派生状态。dirty/running 时默认对话不使用旧前驱、增量 ord、链角色、工具配对及依赖它们的用户增量标题/摘要；历史详情可读取上一份产物并明确其状态，页面仍可读取请求事实与完整脱敏正文。会话标题 SQL 过滤失效链候选；独立已确认的 model_title 可作为候选，并附判定状态。分页每次响应说明派生代际，页面遇代际变化时刷新缓存的关系；无需把多次分页绑定成长时间 SQLite 读事务。

计算期间收到新证据、归属合并、规则改变或正文回收时，写事务使相关请求/组依赖失效。计算提交采用修订相等检查；失败就放弃未发布代际，保留新工作，不能清除后来产生的触发。新输入的任务在前一未发布代际清理或复用其空间后才开始，单组最多一份已发布和一份计算结果；全局同时只推进有预算的一组，查询不依赖其进程内缓存。临时结果、旧代际、清理产生的 WAL 均计入总磁盘，空间不足时暂停派生并保留可恢复状态，不能挤占采集准入或正文预算。

`src/store.ts:92` 的 writer 只允许同步事务，yield 必须在事务外。不能跨 yield 保持写事务，也不保持覆盖整组计算的 WAL 读快照；每次有界读取后校验依赖，已回收正文在完成确认前必须使旧任务失效。读取整组到内存、一次处理全部祖先、最终一次写全部角色或全部工具关系，都仍会留下无界阶段；需要逐项计数，单次解压受既有单对象尺寸限制，解码缓存另设字节预算。

切片改善最长占用，不改变任意祖先算法的总复杂度，也不保证持续变化的热组立即 clean。不同组轮转，失效重试有界，记录重建次数、最老待处理年龄与停止输入后的排空；若持续负载下长期只能显示待重建，容量验收判失败，后续再评估缩小受影响范围或稳定前缀复用，不能用完成标记掩盖饥饿。上述选择是待实施的 `推断`，没有据此宣称吞吐提升。

from_sort 只用于识别受影响起点，不能据此删除更早祖先候选。迟到请求、旧请求用途变化或归属变化可能改变后继和主链选择；优化必须保留[任意祖先前驱规则](../.agents/notes/implemented/architecture/2026-10-20-semantic-fingerprint-and-ancestor-predecessor.md)。

### 正文与阅读

服务端用同一语义 Module 解释列表摘要与正文分页消息，按 ord 返回显示解释及状态，原始脱敏消息保持可读。输入解释不修改内容哈希或共享 block.fingerprint，不把显示清洗当成内容等价。已有指纹设计与实现的差距留在[联合评审](agent-request-kind-review.md#包装迁移不能同时改写指纹)，Agent 专有指纹另案处理。

能力视图区分协议工具定义与 Agent 技能声明，区分为空、未识别、缺失和分页覆盖不完整。首片没有读到某段 system 文本不能解释成零技能。按需解释不默认长期复制技能描述或工具 schema；以后如需正文回收后继续阅读能力，需要纳入正文预算与保留政策。

页面先完成会误导读者的纠错：未知 req_kind/chain_role 原样保留、中性显示；part 采用 magpie 已知类别并给未知值有效颜色；分页文案与实际方向一致；flags 从确定状态聚合。随后再做尝试链结构化阅读、上下文占用提示、滚动保持和复制。未知 fail 保留原值，无时间证据时不补造重试间隔；75%/90% 仅作阅读提示。

## 历史修复与迁移

历史修复要穿过与在线路径相同的字段规则，按三步执行：必要时先完成显式隐私修复，再重映射可用的已保存来源；按现有证据 owner 与输入完整性重建请求事实和长期路由摘要；最后重建请求语义、会话关系及工具配对。不能只改 mapper 或只跑 derive，不能删除 request_evidence 绕过幂等保护。

结构版本与迁移完成状态分开。沿用[启动拒绝自动升级、显式脚本保住正文](../.agents/notes/archived/architecture/2026-10-20-schema-v3-rejects-in-place-upgrade.md)的策略，在 collector_state 保存目标版本、阶段、范围和完成状态。初始化与待迁移标记同事务；每批数据及检查点同事务；最终守恒和不可恢复报告完成后才记迁移完成。openStore 同时检查结构与该标记，结构已新但迁移未完时拒绝普通采集启动，仅显式迁移入口允许续跑。迁移脚本遇未知来源结构或损坏输入报告后停止该范围，不以提高 user_version 跳过。离线入口配合维护锁、范围预览和分阶段恢复报告；第一轮只在合成库验证，真实库操作另行授权。

迁移按可恢复性报告：有脱敏 raw 的可重映射；raw 过期但长期摘要足够的仅恢复对应字段；两者都没有的保持未知；历史错误备用值不继续作为可信请求模型。保留 req_id、alias、证据 owner、正文引用、cost_observation、游标与主动淘汰墓碑。重复运行结果收敛，中断后续跑不增加请求或费用。

同一批必要字段可以共用一次 schema 升版，但不能借此塞入所有候选字段。每次迁移前冻结其消费者、增长预算、缺失语义和存储契约；表结构与脚本一起交付，本文不提前写出 v5 全部列定义。阶段 2 必须落实请求修订、目标/实际版本及历史保留状态；切片暂缓时，代际表随独立迁移交付，不能因期望一次升版就阻塞当前正确性修复。

| 必需长期信息 | 实际消费者与保存限制 |
| --- | --- |
| 来源 kind 报告及冲突 | 用途解释、详情来源说明、raw 过期后恢复；保存有界短值与状态，不复制来源全文 |
| 模型来源和选定尝试 | 三模型阅读、独立 hook 报告、最终字段族一致性、缺 raw 时禁止重新选择；保存足以复核选择的身份或明确不可复核，不能用显示备用值代替 |
| 用途结果、短依据、结果版本、请求输入/消费修订及待处理状态 | 链政策、标题、用途展示和重启恢复；请求修订独立于组修订，阶段 2 落 schema 前确定；结果版本说明实际产出 |
| 分组输入/发布修订、算法目标和阶段 | 过期检查、发布选择、维护排空；复用 derive_queue 管理组进度，不另建通用任务表 |
| 派生结果代际及发布指针 | 切片时隔离未发布结果与最后完整产物；与请求事实分离，存储与读取契约在引入切片的 schema 迁移前冻结，全部暂存计入预算 |
| 工具关系和摘要的原算法、原输入依据及保留状态 | 区分本次重算、缺正文保留、歧义与无法复核；关系业务状态和保留状态分开，不能用 tool_call.derive_version 累加值替代 |
| 来源映射/隐私变换版本及恢复状态 | 历史字段修复与迁移报告；独立于协议 adapter_version 和正文 redact_version，按来源或批次保存即可 |
| 数据库与隐私盐的绑定 | 恢复后新摄入继续使用同一占位符身份；阶段 2 明确绑定、旧库确认与缺盐拒绝，不保存盐明文到数据库或文档 |

技能描述、工具 schema、account/host 展示、逐尝试专表不属于这份最小集合。待处理扫描和组状态读取的新增索引纳入每请求及每组空间测量；存储打包方式由合成查询成本决定。

## 容量目标与验证方法

容量工作从第一阶段采集基线，贯穿每个改动。已有存储回放数字不能代替常驻进程的混合负载；本轮没有性能测量，以下负载是 `推断` 的合成验收起点，阈值是拟议门槛。

| 合成场景 | 初始负载 | 需要观察的结果 |
| --- | --- | --- |
| 连续采集与阅读 | 1 请求/秒持续 10 分钟；另跑 5 请求/秒持续 10 分钟；请求正文以 0.35 MiB 与 2 MiB 混合 | hook 延迟、接受/拒绝、队列年龄与追平时间；同时翻页与读正文 |
| 突发 | 10 个并发 hook，包含 4 MiB 请求及不同回复大小；重复发送同一 hook_id | 有界内存、明确背压、重试后不重计；不以返回 200 代表正文一定存在 |
| 长会话 | 2,000 笔；再用 10,000 笔检验增长；共享历史与独有正文分别构造 | 候选比较次数、解码次数、单批最长占用、完整与增量结果一致 |
| 历史目录 | 同一批不变路由文件重复轮询，再追加、替换 gzip、跨午夜 | 不变文件的解压次数下降；替换仍可检出，证据集合不漏不重 |
| 混合维护 | 采集和查询期间触发正文回收、raw 清理、费用同步 | 写事务时长、事件循环延迟、库/WAL/临时文件总量、准入状态与查询延迟 |

先沿用现有会话列表 100 ms 的验收目标；hook 200 响应以数据库提交为前提，拟以 2 秒预算检验重试在内的端到端行为，具体应与实施时插件超时配置一致。合成测试目标为接受率和重试结果可核对，正常持续负载不出现 503；429、507 各有明确原因与统计，接受响应不能掩盖未持久化的工作。正文尺寸超限或磁盘降级单列，不混入正常接收率。

拒绝观测采用有界的固定原因计数，不要求每次拒绝先写库。保留现有准入限制，在拒绝分支增加进程级计数，经本地认证的统计入口读取；响应携带原因，负载端同时记录每次尝试、最终接受、重试和放弃。统计注明启动时间与重启归零边界，不保存被拒正文或任意来源字符串，不增加 envelope 排队或并发放行。需要跨重启累计时再单独确定有界汇总与崩溃丢失语义；当前 ingest_issue 不能冒充全部 HTTP 拒绝统计，依据见[拒绝观测边界](agent-request-kind-review.md#拒绝观测边界)。

固定机器环境、Bun 版本、数据种子和配置后记录 p50/p95/p99、最大事务时长、事件循环延迟、峰值 RSS、派生积压最老年龄与停止输入后的排空时间。先记录基线，再为派生积压和排空设可复现阈值；没有这些阈值与前后对照，不宣布容量目标完成。10,000 笔是扩大规模的压力点，不是默认支持上限或已验证能力。

吞吐之外还要验算长期元数据。按合成库实测的每请求新增字节、路由/尝试数量和索引成本，计算日请求量下的年增长与到达磁盘门槛的时间；持续秒级吞吐不能直接等同于全年平均流量。正文回收不会缩减长期请求元数据，[现有容量门槛](../.agents/notes/implemented/architecture/2026-10-20-retention-three-gates.md)也不保证无限期保存。若目标日量与保留年限超出上限，需要单独提出元数据保留或扩容决策，不能通过暗中清理请求满足验收。

优先尝试的优化是路由文件变化确认后再解压、同组派生触发合并、单次任务内解码复用与后台切片。费用重扫和预算 SUM 若在基线中占用显著，再采用有失效规则的缓存或增量计数。worker、spool、更换数据库和多进程要有上述测量证明，才进入下一次方案决策。

## magpie 的补充调研

继续调研有价值，但范围应由本轮未决问题限制。既有研究已覆盖配置适配、用途归并、prompt 分解、路由与 direct，不能重新列一轮 Feature 清单作为架构依据。对标的对象是解决问题的机制及其适用条件。

现有可吸纳项包括原始 kind 与归并结果分开、按实际能力和形状门控、Prompt 总量校准与分项估计分开、尝试失败码保留未知。读取缓存的失效机制需要结合具体路径复核，不能笼统当作现成解法。源码不能证明本机安装版已经启用相同路径；对 ATC 的采用判断属于 `推断`。

补充研究随各阶段进行：来源阶段核对字段省略/类型/漂移；投影阶段核对 attempt 与最终行的关系；阅读阶段核对 fail 与 prompt 的真实语义；容量阶段研究缓存的失效条件。每项必须给出固定源码、ATC 对应切口、采用代价和可失败的合成用例。不能以 magpie 有该能力作为采用理由，也不把其网关控制策略搬入 ATC。

| --- | --- |
| 来源升级后，如何区分合法省略与解析失败 | 完成本轮字段的固定源码形状、合成正反例与降级理由即可；不枚举全量 Agent 配置 |
| 多次尝试、计费用量与最终状态如何对应 | 找到明确生产者与消费逻辑，保留不能一一配对的情况；不从展示顺序发明关联 |
| 读取缓存何时失效，旧快照如何停止发布 | 说明来源代际、内容变化、配置变化或过期的触发；ATC 仅采用与自身数据身份一致的部分 |
| 尝试链与上下文有哪些误读风险 | 固定失败码、未知兜底、计数和窗口的来源；读者所需信息足够后停止，不移植整套界面 |

## 分阶段推进

| 阶段 | 具体产出 | 本阶段完成条件与依赖 |
| --- | --- | --- |
| 0a：正确性基线 | 固定代码与文档基准；将已复现缺陷落成回归，明确旧测试的真实契约 | 每项修复前有可稳定失败的对应断言；不依赖负载入口，也不要求所有反例同时修复 |
| 0b：容量基线 | 独立合成负载入口、拒绝观测与固定环境 | 性能基线可重复，作为容量优化的前置；与 1—4 并行 |
| 1：来源与在线投影 | 修真实键名/类型及全部模型写入路径；统一结构化字段脱敏；part/分页等独立纠错 | 依赖对应 0a 回归；新证据值、来源和隐私正确，多尝试不拼接，已有身份与费用不回归；需要新增长期信息的部分转阶段 2 |
| 2：长期事实与重建 | 冻结本次 schema 的版本归属、来源元信息、请求修订/待处理与工具保留状态；显式迁移和恢复；完成正确的同步派生入口 | 合成旧库、raw 过期、中断续跑与守恒通过；迁移未完成时启动行为明确；报告/测试消费者同步。若同时交付切片，先冻结代际存储与查询契约 |
| 3：用途语义 | 迁 title、增加 classifier、保存依据，贯通链参与、工具配对和读模型；覆盖 actor 未知 | 依赖阶段 2 的请求状态；缺回复、乱序、未知类别、规则冲突与正文回收结果明确；页面删除重复用途判断 |
| 4：输入与能力阅读 | 统一包装解释、消息级结果；技能解析与协议工具组合；结构化尝试链 | 依赖实际消费的前序信息；多条增量用户消息不丢、原文可查、解析覆盖可见，页面不再维护另一套同义规则 |
| 5：容量收敛 | 按 0b 基线优化路由读取与派生工作量；按测量决定是否切片 | 先通过修正后的完整重建基准；切片另有冻结存储契约与显式迁移，混合负载达到门槛，资源上限与积压恢复有结果 |

阶段 5 的测量与低风险优化可与 1—4 并行，不等功能迁完才关注容量。无需新列的同步派生正确性修复也可在对应 0a 回归建立后独立交付；持久修订和保留状态随阶段 2 迁移，切片不成为前提。阶段 1 的新摄入正确与阶段 2 的历史修复分别交付；classifier 不等待账号展示、搜索或 direct。每阶段按可回退的行为范围交付，拆清纯迁移、识别规则改变和性能优化，避免一次大替换让差异无法定位。

### 阶段 0 的最小交付

0a 在现有测试入口补能稳定失败的合成反例：字段形状、脱敏到达顺序、部分 raw 重放、hook 直接命中漏触发、链与配对之间的退出、同毫秒请求换 ID、重复重建摘要与跨组 call_id。测试保留在实际共享 Interface，不为临时架构模型另建生产框架。旧测试的处理见[版本与旧测试契约](agent-request-kind-review.md#版本消费者与旧测试契约)：保留完整组重算的有效断言并正确命名，删除或重写空壳；切片预算使用显式契约，不能默默把旧 limit 从组数改成请求数。真正的切片恢复测试须处理一部分后关闭、重开、继续，再比较完整语义产物。

0b 单独建立可运行的合成负载入口，使用仓库外全新临时目录、合成盐和独立端口，不读默认 magpie 路径、不写真实配置。固定种子生成普通/辅助请求、多尝试、父子 actor、迟到正文、共享与独有块，按[容量场景](#容量目标与验证方法)驱动现有采集和查询路径。现有程序若不能注入合成路径，应先做最小运行配置适配；不以重写派生算法换取基线。输出环境、种子、接收/拒绝、延迟分位、队列年龄、排空、事务和内存统计，明确缺少的观测，测量入口与语义改造分开交付。

[已有核对](agent-request-kind-review.md#补充验证范围)只包含临时合成反例，未建立持久回归或混合负载入口。来源和同步执行修复按各自 0a 回归推进，0b 并行建立，容量优化在有基线后开始；长期信息与迁移先定消费者和失效语义，再落实存储。文档审阅和既有单次存储数字不能替代阶段验收。

## 验收与回退

字段和重建检查使用合成数据，覆盖三模型各异、req 缺失、cost 为零、err 与 err_type 不同、Prompt true/false/省略/非法、最终尝试缺失及全部失败。hook-only、直接命中、owner 合并和两源交换顺序须保留独立 hook 模型，ledger.req 缺失不抹掉该报告，success 不生成 HTTP 状态。备份恢复分别覆盖原盐、缺盐与错盐，不能静默换盐继续摄入。相同证据集以不同顺序到达，最终语义投影一致；接收时间、执行次数等运行元信息不参与断言。请求数量、证据唯一 owner、正文引用和费用观测守恒。复用现有 [magpie 测试](../tests/magpie.test.ts)、[收敛测试](../tests/reconcile.test.ts)、[派生测试](../tests/derive.test.ts)等入口补回归，新增测试以实际共享 Interface 为表面，不为转发层复制测试。

语义检查穿过实际解释与派生 Interface，覆盖普通 `<block>no` 反例、Agent 不符、缺回复、迟到 Agent、hook-only、规则优先级、保留旧判定与新规则复核的区别。输入解释测试覆盖合法相似标签、包装里真实文本、插话、畸形和分页；HTML 转义断言继续留在页面测试。

完整重建先通过顺序与重复执行检查：同毫秒、逆序到达、来源后补后，相同最终证据得到相同关系；正文可读时相同输入重复重建与清空可重算派生后重建得到相同摘要和工具关联。覆盖跨组相同 call_id、同组多候选及未知关联，执行计数不参与语义比较；缺正文时另验历史保留，不清空不可重算结果来制造对照。

性能优化用同一合成数据分别运行修正后的完整重建与优化路径，比对类别、前驱、增量 ord、链角色、标题、摘要和工具关联，穿插迟到、合并、回收与重启。每个阶段后注入退出，验证请求待处理和组状态仍可恢复；在组 A 计算中加入新证据、迁移至组 B 或回收正文，旧任务必须提交失败且不能清掉新工作。逐批查询 dirty 组，断言不会返回部分已确认链；工具或摘要阶段中断时不能报告 clean。保留完整算法作为恢复工具，直至优化路径的等价性有足够覆盖。

上线选择以来源事实修正、历史重建、用途迁移、输入/能力解释和容量优化为独立改动单元。title 迁移先按原有合成结果保持行为；classifier、Agent 门控收紧和包装规则调整分别说明新增行为。每次只保留实际需要的恢复方式，不为这一轮先建永久双管线。

回退围绕代码版本与迁移前备份进行。schema 升级后不能假定旧程序可打开；新增语义也不能通过清空证据或删正文回退。具体命令随实施更新运维文档。本轮不执行真实库回填、服务切换或外部发布。
